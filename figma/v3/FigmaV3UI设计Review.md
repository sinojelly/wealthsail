# WealthSail v3 UI 设计评审

总体判断：v3 的产品方向是正确的，比原来的基金筛选页面有明显进步。我建议保留整体设计思路，但在正式开发前做一次 UI/UX 优化。

我检查了以下文件：

- `figma/v3/src/pages/Opportunities.tsx`（941 行）
- `figma/v3/src/App.tsx`（199 行）
- `figma/v3/images/` 下的三张截图文件

其中，截图接口只能返回文件信息，未能提供图像像素，因此下面的界面评审基于 React 代码定义的实际布局与交互，暂不包含逐像素的截图视觉核查。

## 一、v3 最值得保留的设计

1\. 从基金筛选升级为投资机会中心

把宏观经济、投资方向、指数比较、基金选择、决策诊断串在同一页面，符合我们之前确定的产品目标。

2\. 投资方向与指数、基金已经实现基础交互联动

`chooseDirection()` 和 `chooseIndex()` 能切换下游的候选指数与基金。这是 v3 最有价值的部分。

3\. 基金详情区分三个不同的问题

长期配置价值、近期技术状态、当前组合可承担的风险被独立展示，没有简单地使用一个综合评分决定所有问题。

4\. 同指数基金比较的思路正确

费用、跟踪误差、规模、流动性、折溢价，比单纯比较两只 ETF 的 MACD 更有意义。

这些基础都应该保留。

## 二、我认为最需要改进的 10 个地方

| 优先级 | 问题                       | 改进建议             |
| --- | ------------------------ | ---------------- |
| P0  | 展示数据是硬编码的，但看起来像真实市场数据    | 原型与正式数据必须明显区分    |
| P0  | 宏观信息和投资方向之间缺少可验证的关联      | 加入方向驱动因素、证据与反方情景 |
| P0  | 方向分、指数分、基金质量分缺少明确含义      | 三类评分独立定义并支持查看依据  |
| P0  | 搜索仅覆盖当前指数基金              | 增加全局搜索与当前指数内搜索   |
| P0  | 切换指数时图表使用相同的 `trendData` | 图表必须绑定选中的指数或基金   |
| P1  | 页面过长，完成一次分析需要反复向下滚动      | 桌面端增加常驻的筛选/诊断区域  |
| P1  | 不同类别基金放在相同的比较列里          | ETF 和场外基金使用适配字段  |
| P1  | 多个按钮没有操作效果               | 明确交互行为或移除假按钮     |
| P1  | 部分字体过小，手机端表格较宽           | 改善字号、响应式布局与键盘操作  |
| P1  | 缺少数据异常、空值、更新失败状态         | 为关键区域设计完整的数据状态   |

### 1. 最重要：宏观与方向不能只是上下排列

当前页面有四张宏观卡片和四张投资方向卡片，但两者之间的逻辑关联比较弱。

例如，中国宽基卡片写了“增长边际改善、流动性相对宽松”，但这些文字目前是预先写死的，没有建立从实际宏观数据到方向研究判断的计算和证据关系。

我建议用户选中一个投资方向时，系统能自动展开：

中国宽基 — 研究依据示例

有利因素

经济增长边际改善、流动性环境可能有利于权益资产估值

不利因素

企业盈利不及预期、估值偏高或外部流动性收紧

数据与可信度

显示实际数据发布日期、覆盖程度、计算模型及缺失项

以上为设计内容示例，并非当前市场研究结论。

这样才真正实现了“宏观经济 → 投资方向”的有机结合。

### 2. 评分系统需要大幅完善

目前有三个分数来源：

- 投资方向 `score`
- 相关指数 `score`
- 基金 `quality`

例如 `ScoreRing` 显示 76 或 81，但是用户并不知道这些分数如何计算，也不知道它们能不能直接比较。

建议分别定义：

| 评分       | 实际含义                  |
| -------- | --------------------- |
| 方向研究评分   | 宏观、基本面、估值、风险环境的综合研究状态 |
| 指数技术评分   | 均线、动量、MACD、KDJ 等技术状态  |
| 基金产品质量评分 | 跟踪效果、费用、规模、流动性和运营质量   |

不能简单地把方向分 76 与基金质量分 92 相比较。

而且，应该能点击分数查看构成、计算参数、数据截止时间和不确定性。

### 3. 页面布局应该减少滚动

v3 的 `Opportunities.tsx` 是从上到下排列的长页面：

宏观卡片 → 宏观解释 → 方向卡片 → 方向摘要 → 指数比较 → 基金列表 → 基金诊断。

逻辑正确，但真实使用时，用户选了一只基金后要滚动到很下面查看诊断，再想换一个指数又要滚回上面。

建议把正式桌面版改成以下结构：

投资机会中心

顶部：搜索任意基金 · 数据更新时间 · 数据质量

宏观环境摘要

增长 · 通胀 · 流动性 · 风险　（点击展开完整分析）

投资方向导航

中国宽基 / 红利 / 成长 / 港股 / 美国权益 / 债券 / 黄金

左侧：指数与基金

指数比较、基金搜索、同指数比较、排序、筛选

选择某个指数或基金

右侧：常驻诊断

长期价值、趋势、风险、走势图、评分依据

自动跟随左侧选择变化

示意图：窄屏时改为纵向布局，基金诊断通过独立详情页或全屏面板呈现。

我认为这种布局更适合每天反复研究多个指数或基金。

### 4. 数据更新状态必须更准确

当前顶部写着：

“研究数据已更新 · 2026-08-23 07:45 CST · 覆盖率 92%”。

但当前是 2026 年 10 月，这只是演示数据。正式版必须依据实际数据质量来显示“已更新”“部分过期”“更新失败”。

另外，宏观指标、ETF 行情、指数估值和基金净值的更新时间可能不同。

建议分别管理数据截止时间，并在关键位置显示，而不是用顶部一个时间代表所有数据。

“覆盖率 92%”也需要明确分母：究竟是研究候选覆盖率、行情覆盖率，还是具备完整评分的数据比例。

### 5. 全局搜索需要独立

代码中：

```
const filteredFunds = useMemo(() => {
  // 仅从当前 selectedIndex 对应的 funds 中搜索
}, [funds, query]);
```

这意味着用户输入一个不属于当前指数的基金代码，就会得到空结果。

建议顶部设置全局搜索，覆盖已有基金主数据；指数内部再保留局部搜索或筛选。

同时，切换投资方向不应该无条件清空用户的全部查询状态。应明确区分全局搜索和当前研究路径的局部条件。

### 6. ETF 和场外基金不应混用质量指标

目前表格同时比较“日均成交金额”和“T+1 确认”，但这两个概念并不是同一种流动性指标。

另外，“综合费率”必须明确包含哪些成本：管理费、托管费、销售服务费、申购赎回费，还是 ETF 交易佣金和价差。

建议同一指数下保留两种产品入口：场内 ETF 和场外指数基金。允许一起浏览，但比较字段要根据交易形态变化。

### 7. 技术走势图存在真实交互问题

目前指数右侧深色图表与下方基金诊断的趋势图，都使用同一个 `trendData`。

切换沪深300、中证500或黄金时，图表的数据并不会真正改变。

这是原型可以接受、正式产品必须解决的问题。

另外，ETF 价格、指数点位与场外基金净值需要分别标注口径，不能统一称为“复权价格”。

### 8. 部分按钮还只是视觉元素

我在代码中发现：

| UI 控件      | 当前情况     | 建议                |
| ---------- | -------- | ----------------- |
| 五步研究导航     | 静态高亮最后一步 | 做成页面锚点导航或去掉步骤编号   |
| 查看数据方法     | 没有实际行为   | 打开来源与计算方法说明       |
| 加入研究清单     | 没有操作行为   | 接入现有 `/watchlist` |
| 查看计划中的验证口径 | 没有操作行为   | 展示说明，或改为普通文字      |
| 表格行选择      | 鼠标点击     | 支持键盘选择和可访问的控件语义   |

这些并不是算法问题，但会直接影响用户对系统的信任。

### 9. 视觉层级和字号需要调整

从样式代码看，很多数据、表头及注释使用 `text-[10px]`、`text-[11px]`、`text-xs`。金融信息通常密度高，如果大量使用 10—12px，阅读负担会明显增加。

我的建议是：关键数值与判断保持足够醒目，普通表格正文尽量使用 13—14px 左右，辅助说明也不要过小。

同时，颜色应重点表达状态，而不是让大量绿色、橙色、青色同时竞争注意力。

目前投资方向卡、指数比较与诊断区都比较强调视觉层级，后续更应突出真正影响决策的信息，而不是强调所有评分。

### 10. v3 代码还不能直接替换主项目

`figma/v3/src` 目前只有两个 TSX 文件，没有看到完整的样式、依赖、构建配置和其他页面实现。

`App.tsx` 还引用了 Dashboard、Reports 等页面，因此它更像是设计原型的一部分，而不是独立可运行的完整 WealthSail 前端。

正式集成时建议：

保留当前 `frontend` 的 React Router、AppShell、认证、权限和已有 API，迁移 `Opportunities` 页面设计，而不是直接用 v3 的 `App.tsx` 替换主应用。

此外，941 行的 `Opportunities.tsx` 应拆成宏观、方向、指数、基金、诊断等独立组件，避免未来维护困难。

## 三、与第 18 号实施计划还要同步哪些变化？

我建议把本次 v3 评审纳入原实施计划，在正式编码前补充一轮 UI 验收要求。

| 调整项       | 对应实施内容                        |
| --------- | ----------------------------- |
| UI 信息架构冻结 | 明确全局搜索、宏观摘要、方向导航、指数比较、基金诊断的关系 |
| 宏观联动契约    | 方向研究依据、数据来源、发布时间、计算版本、质量状态    |
| 评分规则      | 区分方向研究分、指数技术分、基金质量分           |
| 查询与状态管理   | 全局搜索、指数内筛选、URL 状态、分页、选中项持久化   |
| 图表数据绑定    | 每个指数和基金独立加载真实时序数据             |
| 产品质量比较    | 按基金交易形态显示适当的费用和流动性字段          |
| 交互验收      | 按钮行为、键盘访问、手机适配、加载与异常状态        |
| 真实数据治理    | 严禁演示值进入正式环境的投资评分或建议           |

尤其需要优先确定宏观、方向、指数和基金分析 API 返回的字段及关联关系，否则前端很容易再次依赖硬编码的演示对象。

## 四、建议的修改顺序

我认为先改 UI/UX，再接入真实数据更合理，但不需要现在就把全部宏观、估值、策略算法开发完。

第一步：v3.1 UI 优化

布局压缩、全局搜索、方向联动、常驻诊断、手机端适配、无效按钮处理。

第二步：建立前后端数据契约

定义宏观、方向、指数、基金四层数据接口，以及时间、来源和缺失状态。

第三步：接入真实数据与分析引擎

逐步实现宏观观察、历史行情、技术指标、基金质量和可解释排名。

第四步：完整场景验收

从选择方向到比较指数、找到基金、查看诊断，再到加入自选和后续自动提醒。

## 最终结论

v3 值得保留，它已经具备我们设想的投资研究工作台雏形。

我不会建议重画一套完全不同的界面，真正需要做的是让它从“看起来像一个专业投研系统”转变成“用户能够快速找到值得研究的投资方向，并正确理解风险和买卖信号”的工具。

我尤其建议优先完成三件事：

第一，宏观数据与投资方向建立真正的证据关系，而不是只在页面上相邻展示。

第二，将“选投资方向、选指数、选基金”和“判断买卖时机”区分清楚，避免综合评分混淆。

第三，优化长页面的导航和局部联动，让用户不必频繁上下滚动，就能比较多只指数及基金。

当前 v3 是一个有价值的交互原型，但要达到你提出的“高度自动化、直观方便、辅助投资决策”的目标，还需要上述产品与数据方面的完善。

如果把 `投资机会.png`、`投资机会2.png` 和 `投资机会3.png` 三张截图直接上传到对话中，我还能进一步逐张核查实际视觉效果，包括颜色、间距、字体、信息密度和不同区域的布局，并指出具体应该修改的位置。

# 补充三张截图后的评审

现在看到三张实际截图后，可以更准确地评价 v3 的 UI 了。

我的结论：视觉设计整体不错，已经有专业金融投研软件的感觉，不需要推翻重做。但页面目前更适合“阅读研究报告”，还没有充分优化“快速发现机会、比较基金、判断买卖时机”的操作效率。

我建议保留现在的深蓝侧边栏、青绿色主题、卡片布局和指数对比方式，重点改进信息组织、页面长度、数据联动和决策信息。

## 一、逐张截图评价

### 截图一：宏观经济 + 投资方向

这一部分的视觉设计基本合理，页面整洁、信息分组清晰，宏观数据和方向卡片也容易理解。

但有三个明显问题。

问题一：首屏空间使用不够高效。

当前在一个接近 1000px 高度的屏幕上，主要只能看到宏观数据和投资方向。真正最有用的“指数比较”和“基金选择”都在下面。

建议压缩顶部的标题、五步导航、宏观卡片和投资方向区域。

特别是五步导航，现在第五步“决策诊断”固定高亮，但用户其实还没有走到第五步，容易让人误认为它是一个流程进度条。

可以改成可点击的导航锚点：

`市场环境 | 投资方向 | 指数比较 | 基金选择 | 决策诊断`

或者直接删除导航条，让页面标题与选择路径承担导航作用。

问题二：投资方向的分类层级不统一。

现在四张卡片是：

中国宽基、红利策略、科技成长、黄金资产。

前三者主要是股票风格或投资策略，黄金却是另一个资产类别。未来再加入美股、港股、债券、行业主题，就会越来越混乱。

建议调整为两级选择：

第一级：资产类别与市场

A股

港股

美股

债券

黄金

其他

第二级：投资风格和方向

宽基

红利

成长

价值

科技

消费

周期

低波

示例：选择“A股 + 红利”，下方自动筛选相关指数和基金。

问题三：宏观卡片和方向卡片还缺少实际因果解释。

比如，宏观显示“流动性相对宽松”，下方中国宽基显示“积极观察”，用户自然会问：

为什么？这个结论主要来自增长、估值还是流动性？还有哪些负面因素？它和其他方向相比有什么优势？

建议点击方向时，在研究概要中明确显示“支持因素 / 反方因素 / 数据可靠度”，并能追溯到顶部对应宏观指标。

### 截图二：指数比较 + 基金候选

我认为这一张的布局是 v3 中最值得保留的部分。

左侧指数比较、右侧走势图，下面是跟踪所选指数的基金列表。逻辑上非常合理。

不过建议做以下调整：

| 现有设计               | 建议改进                    |
| ------------------ | ----------------------- |
| 指数分数 81、78、70      | 标注分数代表技术趋势、估值还是综合评价     |
| 历史位置“近10年38%”      | 明确是 PE 分位、PB 分位还是价格区间位置 |
| 右侧深色走势图            | 添加曲线图例、数据口径和可切换的时间区间    |
| 基金列表默认按预设顺序        | 支持费用、跟踪误差、规模、流动性排序      |
| 场内 ETF 与场外基金放在同一张表 | 使用差异化的交易成本及流动性字段        |
| 搜索仅当前指数的基金         | 增加独立的全局基金搜索             |

另外，不建议让每个指数都拥有一个含义模糊的综合评分。

例如沪深300的 81 分，最好明确显示“技术趋势 81”，估值吸引力和长期投资价值单独分析。

同一指数下的基金质量分，也需要明示其计算方法和样本范围。

右侧深色图表很好看，但现在只是两条没有清晰图例的线，用户不容易判断哪条是价格、哪条是均线。建议增加 `价格 / MA20 / MA60 / MA200` 开关以及 `3个月 / 1年 / 3年 / 5年` 时间区间。没有有效历史数据时，对应区间应禁用或说明缺失。

### 截图三：基金综合判断

三个并列卡片的设计非常好：

长期价值

值得投吗？

技术趋势

何时关注？

组合风险

适合我吗？

这是一个适合长期保留的决策框架。

但这里还有一个比较重要的投资逻辑问题。

现在“长期配置价值：值得研究”的理由主要是基金跟踪宽基指数、费率较低、跟踪质量好。

这些理由可以说明它是一个较好的投资工具，却不能单独证明它所跟踪的指数现在值得长期投资。

我建议在“长期配置价值”下面区分：

- 标的价值：指数或资产的基本面、估值、收益风险前景。
- 产品质量：这只基金是否适合用来获得该指数敞口。

另一个值得改善的点是“当前组合可承担风险”显示“需连接持仓”。WealthSail 已经有资产看板和持仓管理，因此正式版更应该直接读取当前用户有权限访问的账户持仓。没有数据时显示“未发现有效持仓快照”或“请选择账户”，而不是引导用户重新连接一套持仓。

此外，这张图的卡片下方有比较多的空白，建议把有效的决策因素也放进卡片，例如关键支持条件、风险触发条件、最近一次信号变化，而不只是放一段总结文字。

## 二、推荐的 v3.1 页面布局

我建议保留现有页面整体风格，但桌面端改成上方概览、左侧选择、右侧诊断的结构。

这里最关键的改变，是不把基金综合诊断固定放在页面最下方。

这样，用户在比较沪深300、中证A500或不同 ETF 时，左侧点一下，右侧就能快速更新对应分析结果。

## 三、关于“买卖时机”，建议再增加一个信息区

目前技术状态主要显示“震荡偏强”“MACD金叉”等。

这些有用，但还不足以直接辅助买卖决策。

我建议增加一张更实用的“策略信号”卡片，明确区分市场事实和策略判断。

策略条件与信号变化

示意，非实时信号

| 长期趋势 | 价格与 MA200 关系     |
| ---- | ---------------- |
| 中期趋势 | MA20 / MA60 与动量  |
| 短期状态 | MACD / KDJ / RSI |
| 估值检查 | 是否已有可靠的估值指标      |
| 风险检查 | 仓位、波动、集中度        |

下一步观察什么？

例如：如果趋势条件满足，但短线动量过热，继续观察回踩均线后的表现；相关规则需先经过历史验证。

未来不仅要显示现在是什么状态，还要显示相较上一交易日发生了什么变化。

例如“近期技术评分由 58 升至 76”“长期趋势由弱转强”“波动风险明显上升”。

这种变化信息比每天显示一个静态评分更有决策价值，也更适合做企业微信自动提醒。
