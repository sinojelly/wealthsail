为了满足“既有定时推送，又能随时问答，还能管理持仓”的需求，并且考虑到未来要无缝扩展到微信或飞书，MVP 的 UI/UX 设计核心理念应该是：**ChatOps（对话即操作） + 结构化卡片（Rich Cards）**。

这种设计将 Agent 视作你的“数字投顾同事”，界面的主体是一个聊天窗口，所有的操作和报告都以对话或交互卡片的形式展开。

以下是针对这个 Web 交互界面的极简且高效的设计方案：

### 一、 整体页面布局设计 (Web 端)

建议采用类似 ChatGPT 或主流协作软件（如飞书）的“左中右”三栏布局（或者移动端自适应为单栏 + 抽屉），保持极简：

* **左侧导航条 (Sidebar)**：
* **Agent 频道**：主聊天区（如“盘前推演”、“个股诊断”）。
* **功能入口**：持仓看板 (Portfolio)、自选池 (Watchlist)、系统设置。


* **中部主交互区 (Chat/Workspace)**：
* **核心流**：对话流（Timeline）。所有的定时盘前报告、问答结果都在这里以时间轴呈现。
* **输入框**：支持自然语言输入，并支持 `/` 快捷指令（Slash Commands）。


* **右侧情报面板 (Context Panel - 可折叠)**：
* 展示当前正在聊天的股票的实时 K 线缩略图、盘口数据或你的持仓成本，省去在不同页面跳来跳去。

### 二、 核心交互场景与 UI 呈现

#### 1. 场景一：早晨 8:30 的“盘前推演”推送

不需要用户点击，系统定时向对话框推送一张“结构化 Markdown 卡片”。
为了便于快速扫视，UI 上可以用颜色（红/绿）区分多空情绪。

> 🤖 **AlphaGhost (Agent)** [08:30 AM]
> 📊 **今日盘前推演：2026-08-20**
> | 标的 | 当前状态 | 支撑位 | 压力位 | 情绪 |
> | --- | --- | --- | --- | --- |
> | **腾讯控股** | ¥ 375.0 | ¥ 368.0 | ¥ 385.0 | 🟢 偏暖 |
> | **贵州茅台** | ¥ 1420.0 | ¥ 1400.0 | ¥ 1450.0 | 🔴 防御 |
> 
> 
> 📝 **核心剧本与操作预案 (If-Then)**：
> * **腾讯**：昨夜中概股大涨，今日大概率高开。**预案**：若高开突破 385，持仓不动；若跌破 368 支撑，建议减仓 1/3。
> * **茅台**：白酒板块资金流出明显。**预案**：无明确利好，暂不加仓，触及 1400 触发止损。
> 
> 
> ⚡ [一键更新持仓] | 🔍 [深度分析腾讯] *(卡片底部附带快捷操作按钮)*

#### 2. 场景二：盘中随时问答 (Ad-hoc Query)

用户在输入框随时提问，支持模糊查询。

* **用户**：`帮我看看宁德时代今天怎么跌了？还能拿吗？`
* **交互设计**：Agent 接收后，先回复 `“⏳ 正在检索 [宁德时代] 实时新闻与技术面...”`（提供加载反馈），几秒后输出结构化回答。回答中应重点包含**当前价与用户持仓成本的对比**。

#### 3. 场景三：配置关注股票与记录持仓 (Portfolio 配置)

为了兼顾效率和直观，提供两种配置交互方式：

* **方式 A：GUI 可视化表格 (适合批量初始化)**
点击左侧的“持仓看板”，主界面切换为数据表格。你可以像用 Excel 一样直接增删改：
* 字段包含：代码、名称、持仓股数、**买入均价**、当前价、浮动盈亏（根据接口自动计算）。


* **方式 B：自然语言/指令录入 (适合盘中随手记)**
在聊天框直接输入：
* *自然语言*：`“我刚以 380 元的价格买入了 500 股腾讯。”` -> Agent 自动解析并更新数据库，回复 `“✅ 已记录：腾讯控股，买入 500股，成本 ¥380。”`
* *快捷指令*：键入 `/buy 00700 380 500`。这种指令模式未来平移到飞书/微信极度丝滑。

### 三、 为什么这样设计便于扩展到微信/飞书？

这套基于 **“对话流 (Chat) + 卡片 (Card) + 指令 (Command)”** 的 UI 架构，其底层数据完全解耦。

1. **飞书/钉钉扩展**：飞书的机器人 API 原生支持“消息卡片 (Message Cards)”。你在 Web 端设计的 Markdown 表格和交互按钮，可以通过飞书的 Card Builder 直接映射。每天 8:30，后台脚本直接调用 Webhook，将盘前卡片推送到你的个人飞书里。
2. **微信扩展**：利用“企业微信”的机器人应用（或者 Server酱、PushPlus），可以将纯文本的 Markdown 简报推送到微信聊天框。盘中你也可以在企业微信里给 Agent 发消息 `“/分析 贵州茅台”`，后台接收解析后再推回来。

### 四、 快速实现该界面的技术推荐

既然您熟悉前端和系统架构，对于这个 MVP，建议采用以下极速开发方案：

* **极速 Web UI (Python 方案)**：直接使用 **Streamlit** 或 **Gradio**。
* Streamlit 原生支持 `st.chat_message`（构建聊天流）、`st.sidebar`（侧边栏配置）和 `st.dataframe`（持仓管理表格）。用几十行 Python 代码就能写出一个非常 Geek 且美观的 AI 对话界面。


* **现代 Web UI (React/Next.js 方案)**：
* 如果您想发挥 React Native 的经验，可以使用类似于 **ChatUI** (Ant Design 体系) 或 **Vercel AI SDK** 提供的现成对话组件，配合 Tailwind CSS，界面会非常现代化，且极易通过 PWA 技术变成手机上的独立 App 体验。
