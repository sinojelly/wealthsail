要快速跑通一个最小可行性产品（MVP），核心原则是**“做减法”**：砍掉复杂的微服务通讯、多 Agent 辩论和底层数据库运维，把精力全部集中在**“验证大模型的分析判断能力”**上。

为了让初学者（或想快速验证逻辑的开发者）最容易上手，同时满足**多端/跨设备实时同步与持久化**的需求，建议 MVP 阶段**采用 Python 后端 + Supabase 云端存储**架构。以下是精简且易于扩展的 MVP 方案：

---

### 一、 MVP 阶段保留的核心功能 (做减法)

MVP 只需要解决一个核心痛点：**每天收盘/盘前，自动帮我把持仓和关注股票的异动、新闻和技术面总结成人话，并给出跨设备可查看的操作预案。**

1. **跨设备持仓与自选股管理**：记录股票/基金代码、成本价、持仓股数以及关注的自选股（支持移动端/Web端多端同步）。
2. **一键 AI 诊股（单体 Agent）**：输入代码，系统自动抓取近 20 天 K 线数据 + 最新 5 条新闻，喂给大模型，输出“看多/看空/观望”及核心逻辑。
3. **盘前定时简报与预案持久化**：每天早上 8:30 - 9:00（A股/港股开盘前）触发任务，生成操盘建议与 If-Then 应对预案，自动持久化至云端并推送至指定渠道。

---

### 二、 盘前需要抓取的数据源（AkShare 都能搞定）

在早上 8:30，虽然今天还没开盘，但经过一个晚上，市场已经积累了大量决定今天开盘走向的信息：

1. **昨夜外盘传导**：美股大盘走势、纳斯达克中国金龙指数（中概股直接影响港股/A股开盘）、富时 A50 期指夜盘表现。
2. **隔夜公告与新闻**：昨晚上市公司发布的最新公告（如业绩预增、减持、并购），以及隔夜发生的宏观大事。
3. **昨日技术面惯性**：昨天收盘时的支撑位、压力位、以及量价关系。

---

### 三、 盘中如何配合？（进阶小思路）

由于盘前已经让大模型生成了具体的“支撑位”、“压力位”和“条件单”，你在实盘操作时就会非常从容：

- **极简做法（人工执行）**：早上 9:00 看一眼手机上 Agent 推送或云端同步的《今日剧本与点位》，9:15 在券商 APP 里提前挂好条件单（到达指定价格自动买卖），然后就可以安心去工作了。
- **后续自动化升级（系统执行）**：未来系统升级后，可以在盘中（如 10:30、14:00）让 Python 脚本轮询当前实时价格。如果发现当前价格**触及了盘前 AI 设定的条件点位**，立刻给你的手机发一条紧急推送：“⚠️ 触发盘前预案：【腾讯控股】已跌破 380 元支撑位，请执行减仓操作！”

---

### 四、 极简技术栈推荐 (支持跨设备多端)

抛弃复杂的微服务与本地运维数据库，先用一套极简工具链把逻辑跑通并保证数据云端同步：

* **后端与逻辑层：Python (FastAPI)**
  * **原因**：Python 拥有最完善的 AI 库和金融数据抓取库。使用 FastAPI 可以用极少的代码起一个高性能接口，完全能 Cover 前期的轻量级调用。

* **数据存储与用户鉴权：Supabase (Cloud PostgreSQL + Auth + Realtime)**
  * **原因**：零运维成本，自带开箱即用的 Auth 用户鉴权、行级安全策略 (RLS) 以及 RESTful/Python SDK 接口。数据天然存在云端，原生支持 Web 端、移动端 (React Native/Flutter) 跨设备同步。

https://supabase.com/dashboard/org/iekhjwzqjjnnanwcbwuj

* **数据源：AkShare (开源 Python 库)**
  * **原因**：完全免费且对国内开发者友好，两行代码就能获取 A 股/美股的 K 线数据、龙虎榜和财经新闻，不需要折腾复杂的 API 密钥。

* **前端展示：Streamlit / React Native / Telegram Bot**
  * **原因**：快速验证阶段可用 Streamlit 或微信/Telegram 机器人接收推送；后期开发 App/小程序时，直接通过 Supabase SDK 连接同一个云端数据库即可，无需改动后端架构。

* **AI 调用：直接请求 LLM API (如 OpenAI 或 DeepSeek)**
  * **原因**：MVP 阶段不需要上 LangChain 或复杂的 Agent 框架。把获取到的数据拼接成结构化的 Prompt，直接调用大模型 API 即可。

### 五、 MVP 数据持久化设计 (Supabase 数据库设计)

为了实现跨设备使用与历史复盘，除了**用户账户数据**、**关注股票**和**持仓股票**外，MVP 还需要持久化**AI简报与诊股历史**以及**用户推送配置**。

#### 1. 用户账户与拓展表 (`profiles`)
* 使用 Supabase 内置 `auth.users` 存储登录凭证，拓展表存储用户偏好。
* **主要字段**：`id` (关联 auth.users), `nickname`, `avatar_url`, `created_at`

#### 2. 持仓股票表 (`user_positions`)
* 记录用户的实际持仓及成本，用于计算收益与盘前 AI 诊股。
* **主要字段**：`id`, `user_id`, `stock_code`, `stock_name`, `market` (A/HK/US), `cost_price`, `quantity`, `updated_at`

#### 3. 关注/自选股票表 (`user_watchlists`)
* 记录用户关注但尚未买入的股票。
* **主要字段**：`id`, `user_id`, `stock_code`, `stock_name`, `market`, `notes` (关注原因), `created_at`

#### 4. AI 诊股与盘前简报历史表 (`ai_reports`)
* **持久化必要性**：AI 生成的盘前 If-Then 预案与诊股报告必须留存，用户才能在移动端/Web端随时查看历史判断、进行履约复盘与胜率统计。
* **主要字段**：`id`, `user_id`, `stock_code` (可为空，空代表多股综合简报), `report_type` (`daily_briefing` / `diagnosis`), `report_date`, `summary_json` (结构化保存开盘预期、Support/Resistance 点位、If-Then 预案), `sentiment` (`bullish` / `bearish` / `neutral`), `created_at`

#### 5. 用户推送与通知配置表 (`user_push_configs`)
* **持久化必要性**：跨设备管理用户的推送渠道（如 Telegram Chat ID, Server酱 SendKey, 企业微信 Webhook 等）与定时提醒开关（默认 08:30）。
* **主要字段**：`id`, `user_id`, `channel` (`telegram` / `serverchan` / `wechat_work` / `push_token`), `config_json`, `is_enabled`, `notify_time`

### 六、 MVP 系统的核心代码流转思路

你可以用一个简单的 Python 脚本（配合定时任务）串起整个流程：

1. **读取持仓与自选 (Supabase SDK)**：从 Supabase 数据库按 `user_id` 查询出该用户持仓和关注的股票列表及成本价。
2. **拉取行情与新闻 (AkShare)**：
   * 调用获取 K 线接口，拿到近 10 天的开盘价、收盘价、涨跌幅。
   * 调用新闻接口，拿到该股票最近 24 小时的关键资讯。
3. **组装 Prompt 并调用 AI**：
   * 将行情与新闻拼接成结构化 Prompt，请求 DeepSeek / OpenAI 生成带点位和 If-Then 预案的分析报告。
4. **保存报告至 Supabase (`ai_reports`)**：将大模型生成的预案解析并存入 Supabase，以便移动端/Web端跨设备拉取回看。
5. **多渠道推送**：从 Supabase 读取用户的 `user_push_configs`，将盘前简报推送到用户的手机（Telegram/微信/App）。

### 七、 后续演进路线

当这个基于 Supabase + Python 的 MVP 跑通后，演进路径将非常清晰：

1. **跨设备前端拓展**：用 React Native 或 Flutter 编写移动端 App / 微信小程序，使用 `@supabase/supabase-js` 直接连 Supabase 实时显示持仓、自选股和历史 AI 预案。
2. **性能与自动化升级**：引入 Go 语言重写后台定时任务引擎与高频行情抓取服务，Supabase 保持作为统一的数据与 Auth 中枢，利用 Realtime 订阅实现盘中触点即时推送。
