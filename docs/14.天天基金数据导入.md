# 天天基金数据采集与导入操作指南

> 导入批次的重复 ZIP 判断、草稿恢复、取消/重新解析、`NEEDS_REVIEW` 语义和完整状态转换，参见 [17.WealthSail 导入批次状态、幂等与草稿治理设计](./17.WealthSail导入批次状态幂等与草稿治理设计.md)。
>
> 用户确认导入后由系统自动完成净值回填、持有日期处理、指标计算与自动重试的最终交互和状态设计，参见 [19.WealthSail 天天基金导入用户操作与后台处理状态设计](./19.WealthSail天天基金导入用户操作与后台处理状态设计.md)。

## 1. 为什么需要重新采集旧导出数据

现有旧导出目录使用 `wealthsail-tiantian-import/v1` 格式，只有历史交易数据，缺少当前持仓权威快照 `current-positions.json`，也没有 WealthSail Web 接受的 ZIP 导入包。

当前后端只接受 `wealthsail-tiantian-import/v2`。不建议手工转换旧数据，因为无法仅靠历史交易可靠还原当前份额、成本和市值。重新采集更安全，现有工具已经支持自动分页、跨年度查询、当前持仓明细采集和活期宝业务排除。

## 2. 确认服务器具备导入条件

如果数据库只升级到 020，需要依次执行全部缺失迁移直到最新的 031：

- 021：天天基金导入和持有区间指标的核心表结构；
- 022～025：相关数据完整性与权限加固；
- 026～027：当前应用版本需要的回调防重放和市场热点读模型；
- 028：补齐确认事务锁定 DRAFT 持仓明细所需的最小 UPDATE RLS 策略；
- 029：保存持有起点的推导方式、可信度和原因，并把可信度带入持仓区间指标。
- 030：允许 API 在当前租户内读取批次关联的数据任务状态；仅开放关联查询所需列。
- 031：保存草稿取消原因和重新解析替代链，保证旧草稿取消与新草稿创建处于同一事务。

不要只单独执行 021。具体命令参见 [11.数据库升级方法.md](11.数据库升级方法.md)。

API 和 Worker 环境需要设置：

```dotenv
TIANTIAN_IMPORT_ENABLED=true
```

必须运行 Worker，否则当前持仓虽然可以导入，但历史净值、持有期最高值和最低值等指标会一直停留在 `PENDING`。

修改环境变量后重启并检查服务：

```bash
sudo systemctl restart wealthsail
sudo systemctl restart wealthsail-worker

sudo systemctl status wealthsail --no-pager -l
sudo systemctl status wealthsail-worker --no-pager -l
```

如果服务器没有 `wealthsail-worker.service`，需要先部署 Worker，再开启导入功能。

## 3. 在 Windows 电脑采集数据

进入采集工具目录并安装依赖：

```powershell
cd D:\develop\gitee\WealthSail\tools\tiantian-fund-importer
pnpm install
```

指定需要覆盖的最早交易日期：

```powershell
pnpm capture -- --from 2020-01-01
```

如果天天基金开户时间早于 2020 年，应将日期提前，例如：

```powershell
pnpm capture -- --from 2015-01-01
```

采集过程如下：

1. 工具打开独立 Edge 浏览器窗口；
2. 在该窗口登录天天基金，推荐使用天天基金 App 扫码；
3. 确认已经进入“交易查询”页面，回到 PowerShell 按 `Enter`；
4. 工具访问持仓子系统。如果终端提示需要单独登录，在同一浏览器中再次扫码；
5. 看到基金持仓列表后，回到 PowerShell 按 `Enter`；
6. 保持浏览器打开，等待终端显示“采集完成”。

工具会自动：

- 从主持仓接口获取基金、汇总市值、持仓收益和净值；
- 逐只打开持仓明细，汇总多张银行卡下的精确份额；
- 使用同时点市值和持仓收益推导成本，不使用四位小数净值反推份额；
- 按年度拆分历史查询并自动获取全部分页；
- 排除充值、快速取现、每日收益等活期宝记录；
- 保留使用活期宝付款或回款的真实基金买卖；
- 对特殊调整生成待复核项，并保留组合买入、组合卖出和调仓作为持有日期辅助证据；
- 生成 `wealthsail-tiantian-import/v2` ZIP。

输出目录格式如下：

```text
tools\tiantian-fund-importer\private-data\exports\run-时间戳\
```

Web 中应选择 `wealthsail-tiantian-YYYYMMDD.zip`，不要解压 ZIP，也不要选择旧的 `fund-transactions.csv`。完整工具说明参见 [天天基金采集工具 README](../tools/tiantian-fund-importer/README.md)。

`private-data` 包含真实持仓和交易数据，已经由 Git 忽略。不要将该目录中的文件手工提交到仓库或发送给无关人员。

## 4. 在 WealthSail Web 中导入

使用 `OWNER`、`ADMIN` 或 `EDITOR` 账号登录，然后：

1. 进入首页或持仓页面；
2. 点击“导入 / 更新持仓”；
3. 找到“导入或更新天天基金持仓”；
4. 首次导入时创建一个“天天基金”专用投资账户；
5. 选择刚生成的 `wealthsail-tiantian-YYYYMMDD.zip`；
6. 等待解析和预览；
7. 核对新增、变更、不变、关闭和冲突五类结果；
8. 检查历史覆盖时间、活期宝排除数量和待复核记录；
9. 检查系统已经自动填入的持有起始日期、推导方式和可信度；日期不合理时直接修改；
10. 勾选“已核对全部预览”并确认导入。

### 4.1 不上传 ZIP 时怎样处理已有草稿

“持仓导入与更新”页面会先显示“待处理草稿”，再显示 ZIP 上传区。草稿是已经成功解析并完整保存的
预览，不是正式持仓，也不代表导入失败。每张卡片会显示目标账户、快照日期、更新时间、五类差异
数量、校验结论、新鲜度和可执行操作。用户不选择文件也可以：

- 点击“继续核对”查看已保存的完整预览；
- 对 `FRESH + VALID` 草稿直接确认，正式写入持仓基线；
- 点击“取消草稿”明确放弃本次预览；取消保留审计记录，不会写入正式持仓；
- 对 `STALE` 或 `INVALID` 草稿查看原因，并进入“重新解析”流程。

服务端不会长期保存包含真实投资数据的原始 ZIP。因此“继续核对”和“取消”不需要文件，
“重新解析”必须由用户重新选择原 ZIP。页面切换到重解析模式时只保留目标草稿和账户，不会在浏览器
或服务端偷偷缓存文件。

### 4.2 再次上传相同 ZIP 会发生什么

相同 ZIP 以原始文件内容哈希、租户和来源账户范围共同判断，不是只比较文件名。默认 `AUTO` 策略
按确定性规则处理：

| 已有状态 | 条件 | 页面和服务端行为 |
|---|---|---|
| 无相同活跃批次 | — | 创建新草稿，显示“已生成新预览” |
| `DRAFT` | `FRESH + VALID` | 恢复已有草稿，不重复保存或重复入账 |
| `DRAFT` | `STALE`，且新预览有效 | 在同一数据库事务中取消旧草稿并创建新草稿 |
| `DRAFT` | `INVALID` 或来源绑定不可用 | 保留旧草稿，要求用户选择继续核对或明确重新解析 |
| `CONFIRMED` | 相同 ZIP 已正式导入 | 返回原结果并提示“该 ZIP 已导入”，绝不重复写入 |
| `CANCELLED` | — | 允许以当前规则创建全新的草稿 |

页面会区分 `CREATED`、`RESTORED_DRAFT`、`ALREADY_CONFIRMED`、`REPARSED` 和
`USER_DECISION_REQUIRED`，避免把恢复、重解析或已导入误报为普通成功。重新解析不是原地覆盖：旧批次
会以 `SUPERSEDED_BY_REPARSE` 原因终止，新批次获得新的 batch id 并指向旧批次。新预览保存失败时，
整个事务回滚，旧草稿保持原状。

预览时，服务端会使用基金代码从权威基金名录核验标准名称，并幂等补全缺失的
`OFF_EXCHANGE_FUND / FUND_CN` 标的主数据。ZIP 中的基金名称只作为来源名称保留，不能直接成为
标准名称。服务器需要能够访问 AkShare 使用的东方财富基金名录；如果权威源暂时不可用，持仓仍会
逐条显示，但标记为“基金代码未通过权威主数据核验”，并禁止确认，避免用未经核验的名称污染主数据。

待复核历史记录不会伪造成买卖或资金流水，因此作为明确警告保留，不影响已经核验的当前持仓快照。
用户仍应在“历史流水”和“问题与提示”中检查其数量，并通过“已核对全部预览”表达人工确认。

持有起始日期按证据强弱自动选择并预填。逐基金份额流水能够调和当前持仓时为高可信；逐基金历史
不完整但仍能得到候选日期时继续优先使用该基金自己的证据；完全无法从逐基金流水得到日期时，才
回退到同一脱敏银行卡尾号下的组合买入或调仓活动。组合买入为中可信，存在调仓或只有调仓证据时
为低可信，因为组合记录没有逐基金成分明细。用户不修改日期时，系统直接采用候选日期；用户修改后
保存为 `USER_CONFIRMED / HIGH`。组合活动始终只作为日期证据，绝不拆分为虚构的基金成交。

确认后，系统先写入当前持仓和交易事实，再由 Worker 异步下载官方历史净值，计算：

- 持有天数；
- 持有期最高和最低净值；
- 当前净值距离持有期最高值和最低值的百分比。

指标状态会从 `PENDING` 变为 `READY`、`PARTIAL` 或 `CONFLICT`。其中 `PARTIAL` 表示历史净值覆盖不完整，`CONFLICT` 表示交易历史与当前持仓快照存在需要人工处理的冲突。

## 5. 常见问题

### 5.1 `excluded-summary.json` 与 Manifest 记录数不一致

`excluded-summary.json` 是一条 JSON 汇总对象，而不是由多个字段分别组成的多条记录。服务端必须使用包含该兼容修复的版本。更新代码并重启 API 后，可以重新上传原 ZIP，不需要重新采集。

### 5.2 采集工具提示未捕获到结构化持仓数据

交易查询和持仓属于不同子系统，可能分别要求登录。根据终端提示在同一浏览器内完成持仓登录，确认能看到基金持仓列表后再继续。

### 5.3 持有期指标长期处于 `PENDING`

依次检查：

1. `TIANTIAN_IMPORT_ENABLED` 是否为 `true`；
2. `wealthsail-worker` 是否处于运行状态；
3. Worker 日志是否存在净值下载失败、限流或基金代码无法识别等错误。

### 5.4 顶部显示持仓数量，但当前持仓列表为空

这是旧版预览在本地基金主数据为空时的缺陷：未解析基金被记录为错误后直接从预览项中跳过，导致
“持仓总数”与五类差异数量不自洽。更新到包含基金主数据自动核验和未知基金可见冲突行的版本后，
取消旧草稿并重新上传原 ZIP；不需要重新采集。如果权威源正常，可核验基金会自动进入新增或变化
分类；如果权威源异常，页面会列出具体基金及中文阻断原因，而不是显示空白列表。

### 5.5 持仓列表正常，但确认提示“导入持仓项目为空或未通过校验”

如果页面能看到持仓，且汇总显示全部为新增/变化/不变而冲突为 0，应先检查数据库是否已经应用
`028_portfolio_import_item_update_policy.sql`。确认事务会使用 `SELECT ... FOR UPDATE` 锁定草稿持仓；
PostgreSQL 除了 SELECT 策略，还会检查 UPDATE RLS。缺少 028 时，普通预览可以读到持仓，但确认事务
会被 RLS 过滤为 0 行。

按 [数据库升级方法](./11.数据库升级方法.md) 使用正式 runner 迁移到当前目标 031，并确认自动 readback 成功。
028 只增加最小权限策略，不修改持仓、交易或批次数据；对于已经显示正常、数据库明细均为 VALID 的
现有 DRAFT，不需要重新采集 ZIP，也不需要取消或重新解析，迁移完成后可直接再次确认。如果列表本身
为空，则属于 5.4 的旧草稿问题，应取消旧草稿并重新上传原 ZIP。

### 5.6 批次详情返回 500，日志提示无权读取 `workflow.job_runs`

批次详情会显示确认后的净值回填和区间指标任务状态。数据库未应用
`030_tiantian_job_status_read_policy.sql` 时，API 能读取导入批次本身，但在关联最新数据任务时会被
PostgreSQL 拒绝。迁移到 030 后，API 只获得 `id/tenant_id/status/job_type/payload/available_at`
六列的 SELECT 权限，并由 RLS 限制为当前租户；Worker 的租约、重试和错误信息仍不会暴露。

该详情端点只接受 `TIANTIAN_FUND_ZIP` 批次。把手工持仓批次 ID 传给它会返回 404，而不是尝试组装
不匹配的响应或访问任务表。

### 5.7 组合或调仓基金仍然没有自动日期

先查看 ZIP 的 `manifest.json` 中 `collectorVersion`。0.3.0 之前的采集器可能已把缺少成功状态文案的
组合一键买入放进 `non-posting`，服务端无法从已经丢失的记录中恢复日期。请更新代码后重新运行采集，
并上传新生成的 ZIP。新版会把组合活动保留为 `review-required` 日期证据。

若新版仍无日期，通常是组合活动与当前持仓的脱敏账户尾号不同、记录晚于快照、或记录里没有可用
发生时间。系统不会跨银行卡尾号猜测。只有调仓而没有组合买入时，页面会采用最早调仓日作为低可信
候选，并提示“无法证明最初买入日期”；用户可以按实际情况修改。

### 5.7 草稿提示过期，为什么不能直接确认

`STALE` 不表示 ZIP 格式错误，而表示草稿生成后比较上下文已经明确变化，例如目标账户持仓事实发生
变化、预览引擎升级，或已有更新的天天基金快照被确认。继续使用旧差异可能覆盖新事实，所以确认接口
会在数据库锁内再次检查新鲜度并返回冲突。请点击“重新解析”，重新选择原 ZIP；无需重新登录天天基金
或重新采集，除非希望导入一个更新快照。
