\## 一、脚本会自动完成什么？



1\. 检查生产环境



&#x20;  核对 `nas-compose`、固定项目名、Docker 网络、持久化卷和 `091\_ai\_usage.sql`。

2\. 编译新镜像



&#x20;  调用已有 `build\_docker\_wealthsail.sh --build-only`，此时网站继续运行。

3\. 预览数据库迁移



&#x20;  调用 `scripts/migrate.py --dry-run`，显示 `PLAN` 和 `SKIP`，不执行待迁移 SQL。

4\. 确认维护操作并暂停 Worker/API



&#x20;  只停止这两个服务，不停止共享 PostgreSQL。

5\. 备份并验证 PostgreSQL



&#x20;  使用 `pg\_dump -Fc` 生成一致性数据库备份，再用 `pg\_restore --list` 检查备份格式。

6\. 执行增量迁移



&#x20;  使用 `db-init` 的管理员网络环境，但覆盖入口，只运行 `scripts/migrate.py`。必须通过 `READBACK OK`。

7\. 部署并验收



&#x20;  调用现有 `build\_docker\_wealthsail.sh --deploy-only`，检查服务和 Codex 登录状态。



这里我对原操作顺序做了一点优化：先构建、预览迁移，待 API/Worker 停止写入后再备份。这样得到的是更准确的迁移前数据库快照，而且构建失败不会影响现有网站。

\## 三、怎么运行？



先进行只读检查：



```

bash upgrade\_docker\_wealthsail\_db.sh --check

```



检查成功后，在 NAS 的交互式 SSH 终端执行：



```

sudo bash upgrade\_docker\_wealthsail\_db.sh --apply

```



执行过程中需要输入一次 PostgreSQL 管理员密码，不会在终端回显，也不会写入脚本、环境文件或 Docker 命令参数。



看到迁移预览后，需要输入：



```

APPLY wealthsail

```



才会真正停止 API/Worker 并开始迁移。

\## 四、如果中途失败怎么办？



脚本采用保守的故障处理方式：



| 失败阶段            | 处理方式                |

| --------------- | ------------------- |

| 环境检查失败          | 不构建，不停止服务           |

| 镜像构建失败          | 旧网站继续运行             |

| 迁移预览失败          | 不停止服务               |

| PostgreSQL 备份失败 | 停止迁移，保留服务停机状态       |

| SQL 执行失败        | 停止后续部署，保留备份，等待人工核查  |

| 新版本部署失败         | 保留迁移后的数据库，不自动回滚 SQL |



特别是 SQL 执行失败时，不会自动恢复旧版 API/Worker，因为数据库可能已经部分迁移，旧代码未必与新结构兼容。



它也不会执行 `initialize\_postgres.py`、`down -v` 或 Docker 数据清理。

# 支持读取数据库配置信息

建议使用 独立的数据库迁移管理员配置文件，专门供 NAS 运维脚本读取。

不要放在 `deployment/env/api.env`、`worker.env` 或 `codex.env` 中。因为这些文件会注入常驻容器，而数据库管理员拥有 DDL 等高权限，不应该让 Web、Worker 或 Codex Runner 获得。

## 一、推荐的配置位置

```
/data_n002/data/udata/real/15221151691/docker/
├── wealth-sail/
│   ├── private/
│   │   └── migration-admin.env       ← 新增，仅 root 可读
│   ├── avatars/
│   └── backups/
│       └── postgres/
├── codex/
└── cloudflared/
    └── tools/
```

它位于源码仓库外，也不属于现有容器的挂载目录。

配置内容建议非常简单：

```
PG_ADMIN_USER=admin
PG_ADMIN_PASSWORD=这里填写真实的PostgreSQL管理员密码
```

密码按原样填写，不用额外加引号。即使包含 `$`、`#`、`&`、`=`，新版脚本也会按纯文本读取，不会将 `.env` 当作 Shell 脚本执行。

### 在 NAS 上创建文件

```
PRIVATE_DIR="/data_n002/data/udata/real/15221151691/docker/wealth-sail/private"

sudo install -d -o root -g root -m 0700 "$PRIVATE_DIR"

sudo touch "$PRIVATE_DIR/migration-admin.env"
sudo chown root:root "$PRIVATE_DIR/migration-admin.env"
sudo chmod 0600 "$PRIVATE_DIR/migration-admin.env"

sudo nano "$PRIVATE_DIR/migration-admin.env"
```

保存后核对权限，不显示密码：

```
sudo stat -c '%a %U:%G %n' \
  "$PRIVATE_DIR" \
  "$PRIVATE_DIR/migration-admin.env"
```

预期目录是 `700 root:root`，配置文件是 `600 root:root`。

注意：这是持久保存的明文凭据。 文件权限能防止普通 NAS 用户读取，但不能抵御 root 权限失陷或包含该路径的不安全备份。不要把它放进同步盘、Git、公开下载目录，也不要发送文件内容或截图。
