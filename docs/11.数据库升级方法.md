## 本轮升级：095→096 日报失败诊断

更新到本轮代码前，先备份并确认目标数据库，再使用已有的 `scripts.migrate` 执行迁移。
`MIGRATION_DATABASE_URL` 继续通过受控环境注入；不要把真实连接串、密码或令牌写入命令示例、
日志或 Git。以下 `<host:port/database>` 必须替换为已确认的目标标识，不包含用户名和密码：

```bash
python -m scripts.migrate --environment production --confirm-target '<host:port/database>' --dry-run
python -m scripts.migrate --environment production --confirm-target '<host:port/database>'
```

预期 dry-run 包含 `096_daily_research_failure_diagnostics.sql`；执行后迁移台账应记录版本 096，
并保留 runner 的 `READBACK OK` 结果。096 的事务由 runner 管理，不要添加 `BEGIN/COMMIT`、
修改旧 migration、重写 checksum 或绕过迁移台账直接粘贴 SQL。

096 只给 `research.daily_research_results` 增加可空的 `failure_stage`、
`failure_reason_code`、`failure_rule_id`、`failure_item_index`。旧结果保留 NULL；新失败结果
在原终态 INSERT 中一次保存受白名单限制的代码和索引，不保存异常原文、来源引句或提示词。
READY 结果的四列必须全为 NULL。已有角色、RLS、每日唯一名额和追加式写入权限均不变；
不能通过 UPDATE 给历史失败补诊断或重试已消费的名额。

迁移后可用受控只读连接核验列、约束和历史兼容性：

```sql
SELECT column_name, is_nullable
FROM information_schema.columns
WHERE table_schema='research' AND table_name='daily_research_results'
  AND column_name IN ('failure_stage','failure_reason_code','failure_rule_id','failure_item_index');

SELECT count(*) AS invalid_ready_results
FROM research.daily_research_results
WHERE status='READY' AND (failure_stage IS NOT NULL OR failure_reason_code IS NOT NULL
  OR failure_rule_id IS NOT NULL OR failure_item_index IS NOT NULL);
```

应返回四个可空列，且 `invalid_ready_results=0`。API 仍只读、Worker 仍只 INSERT；
诊断只属于当前展示的 runId，保留旧成功日报时不能把它的身份与另一次失败或 pipeline 的诊断混用。
应用回滚时保留新增列和 096 台账；后续修复继续新增前向迁移。

更新代码后、重启新版本服务之前，必须先手动执行数据库迁移。`systemctl restart` 只加载代码，
不会执行 SQL。当前 API 鉴权会读取 025 增加的 `identity.profiles.auth_version`，成交确认依赖 025
的同租户确认人外键和 event 唯一索引，企业微信 POST 回调依赖 026 的持久防重 claim，市场热点
API 依赖 027 的 Worker-owned 快照表，天天基金确认依赖 028 的 DRAFT 导入项 UPDATE RLS，持有日期
推导与指标接口依赖 029 的方法、可信度和原因字段，天天基金批次详情依赖 030 的租户隔离任务状态
只读策略和列级权限，导入草稿恢复、取消原因和原子重解析依赖 031；如果先启应用，回调、读取或
导入确认链路会缺少必要对象。032 进一步增加平台角色、默认租户、账户归属和个人租户邀请；
033 让新个人租户原子初始化四时段报告计划；034 增加 OWNER 重命名活动租户所需的 UPDATE RLS
与列级最小权限；035 撤销 migration 009 遗留的 API 直接创建 `workflow.jobs` 能力，使四时段计划只能
由受保护的邀请函数原子创建；036 统一天天基金与基金估值器的数据源类型为 `FUND_NAV`，并保留
`PUBLIC_API` 作为许可模式；037 增加确认导入后的追加式持有起点决策，只允许当前租户的 API 追加
决定，不改写已确认导入、持仓账本或历史决策。038 进一步区分“接受原估算日期”和“修改日期”：
前者只保存审计决定且不重算，后者只为被修改基金创建净值回填任务；同时补齐 Worker 在重算结束后
刷新持仓与账户估值投影所需的最小列权限。039 增加账户级、不可变且版本化的累计收益跟踪基线：
既有完整 NAV 自动建立零历史收益基线，未来首个完整 NAV 也由触发器自动初始化；API 只允许账户
受益所有者追加用户确认版本，不允许修改或删除历史版本。040 拒绝已有重复时段并增加
`workflow.jobs(tenant_id, report_session)` 唯一约束，防止重复报告和重复推送；041 增加无持仓用户共享市场简报缓存，
042 以最小权限开放盘前所需参考数据只读访问，043 在用户偏好中增加四时段研报推送开关并默认开启。新版登录、资产作用域、Jelly 独立租户迁移、报告调度和租户治理均
依赖这些对象，不能先启应用再补 SQL。057 后的公司行动自动同步依赖 058 的受控写入函数与双来源
审计字段，以及 059 授予 Worker 的最小持仓/主数据读取权限；060 还增加盘前个性化报告的
标的趋势缓存。缺少任一迁移都会使对应的自动功能无法安全运行。

061 为场外基金申购/赎回状态增加天天基金来源、来源元数据与受控写入函数。Worker 只能执行
`reference.upsert_fund_profile_status`，不得直接写 `reference.fund_profiles`；当来源不可用或字段
无法识别时，系统宁可不写入、不把状态推断为“开放”。

062 将天天基金公开基金分红表纳入既有公司行动事实链路。Worker 仅按当前场外基金持仓筛选并通过
既有受控函数写入；每条事实保留权益登记日、除息日和红利发放日。来源故障或缺少除息日时不写入，
报告不会把“无数据”伪造成“无分红”。

从本版代码起，Worker 会在每个 A 股交易日 `22:00` 扫描全部租户的当前场外基金持仓，按参考基金
去重后同步官方历史单位净值。首次同步读取最近 60 个交易日，后续只重读最近 7 个自然日以接收
数据源的迟到更正；事实仍只写入既有 `market.market_observations` 的 `NAV` 链路，不创建
`workflow.jobs`、不重算租户账本、不需要新的数据库 migration。趋势计算会接受官方历史 NAV 的
`STALE` 状态（它仅表示披露日早于当前日），但股票/场内基金仍只接受 `FRESH` 收盘价。

### C. dry-run：只看计划，不执行 SQL

迁移必须使用管理员/迁移专用 DSN，不能使用 API 或 Worker 运行时 DSN。把示例目标替换为命令

### F.1 062 基金分红公司行动验证

062 复用交易日 `06:00` 的 `CORPORATE_ACTIONS_REFRESH`，不新增 `workflow.jobs`。迁移完成并重启
Worker 后，下一交易日的同步会先读取当前持仓的 A 股、场内基金和场外基金；基金分红源只接收场外
基金代码，按公开年度表筛选后才进入数据库受控写入函数。

发布人可使用管理员只读连接核查来源注册和未来四天的基金分红事实：

```sql
SELECT name, source_type, license_model, allowed_usage, status
FROM reference.data_sources
WHERE name = 'AKSHARE_FUND_DIVIDEND_ACTIONS';

SELECT alias.alias_value AS symbol,
       instrument.canonical_name,
       action.action_date AS ex_date,
       action.record_date,
       action.pay_date,
       action.params,
       action.quality_status,
       action.source_ref
FROM market.corporate_actions action
JOIN reference.instruments instrument ON instrument.id = action.instrument_id
JOIN LATERAL (
    SELECT alias_value
    FROM reference.instrument_aliases
    WHERE instrument_id = action.instrument_id
      AND alias_type = 'TICKER'
    ORDER BY effective_from DESC
    LIMIT 1
) alias ON TRUE
WHERE action.action_type = 'FUND_DIVIDEND'
  AND action.action_date BETWEEN CURRENT_DATE AND CURRENT_DATE + 3
ORDER BY action.action_date, alias.alias_value;
```

有事实时，盘前个性化报告的“今日操作提醒”会显示“基金分红除息”，并明确净值可能技术性调整、
应关注红利到账；没有结果只表示来源当前没有可确认的持仓基金除息日，不能据此断言基金不存在分红。
可用同一 OWNER/ADMIN 调试入口 `POST /api/v1/debug/reports/trigger/PRE_MARKET?phase=PERSONALIZED`
核对报告审计与企微投递正文。

后 URL 使用 `#reset-token=` 且页面读取后立即清理；重置前的 access/refresh token 都变为 401；
SELL 超卖、BUY 缺现金或出局条件均被拒且无部分账本写入；合法成交确认后持仓/NAV 当次可见；
同一已认证企业微信回调重复提交只进入领域一次；Worker 至少生成一条 market-hot 快照，已登录 API

### J. 失败处理

- 025 预检发现历史脏数据：保持旧应用运行，导出冲突行，人工确认真实经济事实，使用单独编号的
  受审计 forward-fix SQL 修正，再重跑 runner；
- migration 已提交但 readback 失败：不要删除 ledger 行；修复权限/策略/对象后新增 migration；
- 034 显示 `APPLIED` 后只报 `personal tenant report schedule initialization is missing or unsafe`：
  034 已提交，无需也不得重跑其 SQL；更新到含 035 的代码后重新执行 runner，预期 034 显示 `SKIP`、
  035 显示 `APPLIED`，随后自动 readback 成功；
- 新应用启动失败但 031 已成功：可临时恢复兼容 031 的上一版应用代码，数据库保持 031；不要尝试
  删除 `auth_version`、完整性约束、回调 claim 或 market-hot 表；不兼容旧版本必须走 forward-fix；
- 026～031 已提交但 readback 失败：停止应用发布，保存回读结果，新增 migration 修复函数/权限；
  不得 DROP 后伪造 ledger，也不得把市场热点 API 临时改回请求内 Provider fan-out；
- SMTP 不可用：修复邮件配置。密码重置公开响应保持一致，旧的未消费链接不会因一次投递失败被
  立即作废。

## 历史基线：migration 021 改了什么

`021_tiantian_fund_import_and_position_metrics.sql` 是向前兼容的增量迁移，主要包括：

1. `ledger.portfolio_source_bindings`：把匿名化天天基金来源账号绑定到一个专用投资账户；
2. 扩展 `portfolio_import_batches/items`：支持 v2 ZIP、DRAFT 预览、逐项差异、终态幂等和
   当前快照的 `POSITION_SNAPSHOT`；
3. `portfolio_import_source_records` 与 `portfolio_source_transactions`：保存可审计的第三方
   来源事实，历史流水不伪造为 WealthSail 成交/现金流；
4. `position_period_metrics`：物化持有起始日、官方单位净值最高/最低和区间位置；
5. 扩展 `workflow.job_runs`：支持可租约、可重试、进程重启后可恢复的
   `FUND_NAV_BACKFILL` / `POSITION_PERIOD_METRICS_REBUILD`；
6. 增加复合外键、唯一索引、不可变触发器、RLS、API/Worker 最小授权和浏览器直写防线。

迁移脚本正式提交 SQL 后，会自动执行 migration readback。**readback 不是另一条命令**：若表、
列、约束、触发器、RLS 或角色权限不符合契约，`scripts/migrate.py` 会以非零状态退出，上线必须
停止。数据库事务已经提交时应采用 forward-fix 修复读回问题，不能假装 migration 未执行。

### 3. 021 历史版本故障与回滚策略（仅供追溯）

- **dry-run 失败**：数据库尚未改变；修复目标、凭据、代码版本或 checksum 问题后重试。
- **SQL migration 失败**：单个 migration 在事务中执行，正常会回滚该版本；保留完整错误并检查
  ledger，修复后重跑。不要手工插入版本号。
- **021 已提交但 readback 失败**：停止部署新应用，保留数据库快照，以 forward-fix 修复权限或
  契约；不要 DROP 新表或删除 migration ledger。
- **应用启动失败**：设置 `TIANTIAN_IMPORT_ENABLED=false`，恢复上一版应用代码；021 是增量 Schema，
  可以保留，不需要向下迁移。修复后重新部署。
- **已发生确认导入后发现业务缺陷**：立即关闭功能开关阻止新写入，保留 Worker/数据库和审计证据；
  已确认账本只能通过业务 REVERSAL/新快照更正，禁止删表、删批次或回滚 migration。
- **只想暂停净值 Provider**：不要重放或删除已确认批次；可以停止 Worker 进行排障，但这会同时
  影响四时段报告和 Outbox，应安排维护窗口。任务会保留在数据库，恢复 Worker 后继续认领。

功能开关关闭只阻止新预览、确认、取消和手工重试；已有持仓、导入历史和指标仍应可读，便于
排障和向用户说明。完整数据库恢复只能使用升级前备份，并且仅适用于尚未产生新业务事实的情况。

### 公司行动自动同步来源

交易日 06:00 的 Worker 仅扫描当前持仓，并且只会写入执行当天至未来 3 个自然日的行动：

- A 股：AkShare `stock_fhps_detail_em`，保存已实施方案的除权除息日、股权登记日、现金分红比例/描述、送股及转增比例；同时以 Baostock 交叉校验现金分红。
- 场内 ETF 与场外基金：AkShare `fund_fh_em`，按基金代码过滤，保存权益登记日、除息日、分红发放日及每份分红。`fund_etf_fund_info_em` 仅用于净值与申赎状态，不作为分红来源。

近期没有除权除息或基金分红的标的不会产生记录。历史行动不被删除，以保留审计事实；盘前报告查询仍限定在当天至未来 3 天。

少量数据也可以由 owner 连接执行 SQL。以下示例不会建立缺失主数据，找不到唯一代码时插入 0 行：

```sql
WITH target AS (
    SELECT instrument.id
    FROM reference.instrument_aliases alias
    JOIN reference.instruments instrument ON instrument.id = alias.instrument_id
    WHERE alias.alias_type = 'TICKER'
      AND alias.alias_value = '600036'
      AND alias.market = 'SSE'
      AND alias.effective_from <= DATE '2026-09-08'
      AND (alias.effective_to IS NULL OR alias.effective_to >= DATE '2026-09-08')
), source AS (
    SELECT id FROM reference.data_sources WHERE name = 'MANUAL_CORPORATE_ACTIONS'
)
INSERT INTO market.corporate_actions (
    instrument_id, action_type, action_date, ex_date, params, source_id,
    summary, source_event_id, revision, source_ref
)
SELECT target.id, 'EX_RIGHTS', DATE '2026-09-08', DATE '2026-09-08',
       '{}'::jsonb, source.id, '今日除权除息',
       'manual-sql:600036:2026-09-08:ex-rights', 1, NULL
FROM target CROSS JOIN source
ON CONFLICT (source_event_id, revision) DO NOTHING;
```
