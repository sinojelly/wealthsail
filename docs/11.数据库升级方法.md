# WealthSail 数据库升级方法（当前目标：021）

> 适用目录：`/opt/wealthsail`；适用分支：`master`
>
> 本文第一部分是当前版本从已部署状态升级到 migration 021 的完整操作。后面的附录 A 保留
> migration 020 当时的详细说明，供排障和审计使用，不应再把“只执行到 020”当作当前上线步骤。

更新代码后、重启新版本服务之前，必须先手动执行数据库迁移。`systemctl restart` 只加载代码，
不会执行 SQL。新 API 会读写 021 增加的列和表，新 Worker 会认领 021 增加的任务类型；如果先
启应用，轻则导入接口报 500，重则形成“账本已确认但异步指标无法落库”的不完整部署。

## 1. 本次 migration 021 改了什么

`021_tiantian_fund_import_and_position_metrics.sql` 是向前兼容的增量迁移，主要包括：

1. `ledger.portfolio_source_bindings`：把匿名化天天基金来源账号绑定到一个专用投资账户；
2. 扩展 `portfolio_import_batches/items`：支持 v2 ZIP、DRAFT 预览、逐项差异、终态幂等和
   当前快照的 `POSITION_SNAPSHOT`；
3. `portfolio_import_source_records` 与 `portfolio_source_transactions`：保存可审计的第三方
   来源事实，历史流水不伪造为 WealthSail 成交/现金流；
4. `position_period_metrics`：物化持有起始日、官方单位净值最高/最低和区间位置；
5. 扩展 `workflow.job_runs`：支持可租约、可重试、进程重启后可恢复的
   `FUND_NAV_BACKFILL` / `POSITION_PERIOD_METRICS_REBUILD`；
6. 增加复合外键、唯一索引、不可变触发器、RLS、API/Worker 最小授权和浏览器直写防线。

迁移脚本正式提交 SQL 后，会自动执行 migration readback。**readback 不是另一条命令**：若表、
列、约束、触发器、RLS 或角色权限不符合契约，`scripts/migrate.py` 会以非零状态退出，上线必须
停止。数据库事务已经提交时应采用 forward-fix 修复读回问题，不能假装 migration 未执行。

## 2. 当前版本完整升级步骤

### 2.1 备份、更新代码并确认文件

先在数据库平台创建可恢复备份/快照并记录时间点，然后在服务器执行：

```bash
cd /opt/wealthsail

git pull origin master
git rev-parse --short HEAD

test -f migrations/021_tiantian_fund_import_and_position_metrics.sql \
  && echo "OK: migration 021 exists" \
  || { echo "ERROR: migration 021 missing"; exit 1; }

test -x .venv/bin/python \
  && .venv/bin/python --version \
  || { echo "ERROR: .venv/bin/python missing"; exit 1; }
```

不要把文档中的旧 commit 哈希作为固定预期；以本次发布通知给出的 commit 和服务器
`git rev-parse --short HEAD` 为准，并确认工作树没有混入未部署文件：

```bash
git status --short
```

### 2.2 安全注入迁移管理员 DSN 并确认目标

迁移需要数据库 owner 或专用 migration 管理员。不要使用权限受限的
`wealthsail_api_login` / `wealthsail_worker_login`，推荐直连 5432 而不是 transaction pooler
6543。为避免密码进入 shell history：

```bash
read -rsp "请输入 MIGRATION_DATABASE_URL: " MIGRATION_DATABASE_URL
echo
export MIGRATION_DATABASE_URL

MIGRATION_TARGET="$(
  .venv/bin/python -c \
  'import os; from scripts.migrate import safe_target_name; print(safe_target_name(os.environ["MIGRATION_DATABASE_URL"]))'
)"

printf '准备迁移数据库：%s\n' "$MIGRATION_TARGET"
```

示例 DSN 为
`postgresql://postgres:URL编码后的密码@数据库地址:5432/postgres?sslmode=require`。输出只会显示
主机、端口和库名；如果不是目标生产库，立即停止。密码包含 `@ # : / ?` 等字符时必须 URL 编码。

### 2.3 先 dry-run，确认只计划缺失版本

```bash
.venv/bin/python scripts/migrate.py \
  --environment production \
  --confirm-target "$MIGRATION_TARGET" \
  --dry-run
```

如果生产库已经到 020，关键输出应类似：

```text
SKIP 001_initial_schemas.sql (already applied)
...
SKIP 020_channel_binding_uniqueness_hardening.sql (already applied)
PLAN 021_tiantian_fund_import_and_position_metrics.sql sha256=...
```

如果数据库还没有 020，dry-run 计划 `020` 后紧接 `021` 是正常的；但任何更早版本缺失都要先
核对数据库来源和发布记录。看到 `checksum drift`、`duplicate migration version`、目标确认不符、
无法备份或计划包含未知 SQL 时，不得正式执行，也不得手改 migration ledger 绕过检查。

### 2.4 正式迁移；自动 readback 必须成功

```bash
.venv/bin/python scripts/migrate.py \
  --environment production \
  --confirm-target "$MIGRATION_TARGET"
```

关键成功输出应包含：

```text
APPLIED 021_tiantian_fund_import_and_position_metrics.sql
READBACK OK: roles, browser grants and demo-user guard
```

若 021 已由前一次命令成功提交，重跑会显示 `SKIP 021 ... (already applied)` 并再次执行 readback，
不会重复建表。readback 除既有角色、Seed 和投影检查外，还会验证：

- 四张天天基金新表的关键列、`ENABLE/FORCE RLS`；
- `TIANTIAN_FUND_ZIP`、`POSITION_SNAPSHOT` 和两种数据任务的数据库 CHECK 约束；
- 来源绑定/记录/交易/批次不可变触发器；
- API 写预览/确认来源事实和只读指标、Worker 读来源并写指标所需的最小权限；
- `authenticated` 浏览器角色不能直接写上述账本表。

### 2.5 手工回读 migration、结构与任务约束

安装了 `psql` 时执行以下只读检查：

```bash
psql "$MIGRATION_DATABASE_URL" -X -v ON_ERROR_STOP=1 -c "
SELECT version, filename, applied_at
FROM public.wealthsail_schema_migrations
WHERE version IN (20, 21)
ORDER BY version;
"
```

最终至少必须返回版本 21：

```text
21 | 021_tiantian_fund_import_and_position_metrics.sql | ...
```

确认表、RLS 和关键索引：

```bash
psql "$MIGRATION_DATABASE_URL" -X -v ON_ERROR_STOP=1 -c "
SELECT n.nspname AS schema_name,
       c.relname AS table_name,
       c.relrowsecurity AS rls_enabled,
       c.relforcerowsecurity AS rls_forced
FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'ledger'
  AND c.relname IN (
    'portfolio_source_bindings',
    'portfolio_import_source_records',
    'portfolio_source_transactions',
    'position_period_metrics'
  )
ORDER BY c.relname;

SELECT schemaname, indexname
FROM pg_indexes
WHERE indexname IN (
  'uq_source_bindings_active_account_provider',
  'uq_import_batches_tiantian_package',
  'uq_import_batches_terminal_idempotency',
  'uq_import_items_external_snapshot_record',
  'idx_position_period_metrics_latest',
  'idx_job_runs_import_claimable'
)
ORDER BY indexname;
"
```

四张表都应为 `rls_enabled=t`、`rls_forced=t`，六个索引都应存在。确认持久任务约束包含两种类型：

```bash
psql "$MIGRATION_DATABASE_URL" -X -v ON_ERROR_STOP=1 -c "
SELECT pg_get_constraintdef(oid)
FROM pg_constraint
WHERE conname = 'job_runs_job_type_check';
"
```

输出必须同时包含 `FUND_NAV_BACKFILL` 和 `POSITION_PERIOD_METRICS_REBUILD`。

### 2.6 配置灰度开关和 Worker，再重启

先确认 systemd 单元及其真实 `EnvironmentFile`，不要猜配置文件路径：

```bash
systemctl list-unit-files --type=service | grep -E '^wealthsail'
sudo systemctl cat wealthsail
sudo systemctl cat wealthsail-worker 2>/dev/null || true
```

在 API 使用的环境文件加入：

```ini
TIANTIAN_IMPORT_ENABLED=true
TIANTIAN_IMPORT_MAX_UPLOAD_BYTES=20971520
TIANTIAN_IMPORT_MAX_EXPANDED_BYTES=104857600
```

在独立 Worker 环境文件加入或确认：

```ini
DATA_TASK_POLL_INTERVAL_SECONDS=5
DATA_TASK_CONCURRENCY=2
DATA_TASK_LEASE_SECONDS=300
DATA_TASK_MAX_ATTEMPTS=5
DATA_TASK_BASE_BACKOFF_SECONDS=10
FUND_NAV_HISTORY_PAGE_SIZE=100
FUND_NAV_HISTORY_MAX_PAGES=50
```

如果没有独立 Worker 服务，先不要打开 `TIANTIAN_IMPORT_ENABLED`；否则用户确认后没有进程回填
净值。配置完成后：

```bash
sudo systemctl daemon-reload
sudo systemctl restart wealthsail
sudo systemctl restart wealthsail-worker

sudo systemctl status wealthsail --no-pager -l
sudo systemctl status wealthsail-worker --no-pager -l
```

如果当前确实只有一个同时承载 API 与 Worker 的 `wealthsail.service`，只重启实际存在的服务，
但要从日志确认数据任务循环已经启动；不要执行一个不存在的单元后忽略错误。

### 2.7 启动日志、健康检查与业务冒烟

```bash
sudo journalctl -u wealthsail --since "10 minutes ago" --no-pager -o cat
sudo journalctl -u wealthsail-worker --since "10 minutes ago" --no-pager -o cat

curl -fsS http://127.0.0.1:8000/healthz
echo
```

日志中不应出现 `checksum drift`、`permission denied`、`runtime role boundary`、
`Tiantian import schema`、`Traceback` 或数据任务持续租约失败。健康接口成功后，用一个非生产资金
测试账号在 Web 执行：上传 v2 ZIP → 选择专用账户 → 预览 → 取消草稿；再用一份可控小包执行
确认，验证账本成功、指标先 `PENDING` 后 `READY/PARTIAL`、重复确认不增加账本事件。最后用
VIEWER 验证页面只读、API 写操作返回 403。不得用生产主账户做首次破坏性冒烟。

### 2.8 清除迁移管理员凭据

```bash
unset MIGRATION_DATABASE_URL
unset MIGRATION_TARGET

test -z "${MIGRATION_DATABASE_URL:-}" \
  && echo "OK: migration credential cleared" \
  || echo "WARNING: credential still exists"
```

## 3. 故障与回滚策略

- **dry-run 失败**：数据库尚未改变；修复目标、凭据、代码版本或 checksum 问题后重试。
- **SQL migration 失败**：单个 migration 在事务中执行，正常会回滚该版本；保留完整错误并检查
  ledger，修复后重跑。不要手工插入版本号。
- **021 已提交但 readback 失败**：停止部署新应用，保留数据库快照，以 forward-fix 修复权限或
  契约；不要 DROP 新表或删除 migration ledger。
- **应用启动失败**：设置 `TIANTIAN_IMPORT_ENABLED=false`，恢复上一版应用代码；021 是增量 Schema，
  可以保留，不需要向下迁移。修复后重新部署。
- **已发生确认导入后发现业务缺陷**：立即关闭功能开关阻止新写入，保留 Worker/数据库和审计证据；
  已确认账本只能通过业务 REVERSAL/新快照更正，禁止删表、删批次或回滚 migration。
- **只想暂停净值 Provider**：不要重放或删除已确认批次；可以停止 Worker 进行排障，但这会同时
  影响四时段报告和 Outbox，应安排维护窗口。任务会保留在数据库，恢复 Worker 后继续认领。

功能开关关闭只阻止新预览、确认、取消和手工重试；已有持仓、导入历史和指标仍应可读，便于
排障和向用户说明。完整数据库恢复只能使用升级前备份，并且仅适用于尚未产生新业务事实的情况。

```bash
curl -fsS http://127.0.0.1:8000/healthz
echo
```

预期类似：

```json
{
  "status": "ok",
  "db": "up"
}
```

如果服务通过 Nginx 暴露，则使用实际域名：

```bash
curl -fsS https://你的域名/healthz
echo
```

## 最简可复制版本

确认已准备好管理员 DSN后，可以按下面这一组执行：

```bash
cd /opt/wealthsail

git pull origin master
git rev-parse --short HEAD

read -rsp "请输入 MIGRATION_DATABASE_URL: " MIGRATION_DATABASE_URL
echo
export MIGRATION_DATABASE_URL

MIGRATION_TARGET="$(
  .venv/bin/python -c \
  'import os; from scripts.migrate import safe_target_name; print(safe_target_name(os.environ["MIGRATION_DATABASE_URL"]))'
)"

printf '迁移目标：%s\n' "$MIGRATION_TARGET"

.venv/bin/python scripts/migrate.py \
  --environment production \
  --confirm-target "$MIGRATION_TARGET" \
  --dry-run

.venv/bin/python scripts/migrate.py \
  --environment production \
  --confirm-target "$MIGRATION_TARGET"

unset MIGRATION_DATABASE_URL
unset MIGRATION_TARGET

sudo systemctl restart wealthsail
sudo systemctl status wealthsail --no-pager -l

sudo journalctl -u wealthsail \
  --since "5 minutes ago" \
  --no-pager \
  -o cat

curl -fsS http://127.0.0.1:8000/healthz
echo
```

正式执行前，dry-run 的关键判断是：旧版本全部 `SKIP`，并且只出现一个 `PLAN 020_channel_binding_uniqueness_hardening.sql`。
