更新代码后、重启新版本服务之前，必须先手动执行数据库迁移。`systemctl restart` 只加载代码，
不会执行 SQL。当前 API 鉴权会读取 025 增加的 `identity.profiles.auth_version`，成交确认依赖 025
的同租户确认人外键和 event 唯一索引，企业微信 POST 回调依赖 026 的持久防重 claim，市场热点
API 依赖 027 的 Worker-owned 快照表，天天基金确认依赖 028 的 DRAFT 导入项 UPDATE RLS，持有日期
推导与指标接口依赖 029 的方法、可信度和原因字段，天天基金批次详情依赖 030 的租户隔离任务状态
只读策略和列级权限，导入草稿恢复、取消原因和原子重解析依赖 031；如果先启应用，回调、读取或
导入确认链路会缺少必要对象。032 进一步增加平台角色、默认租户、账户归属和个人租户邀请；
033 让新个人租户原子初始化四时段报告计划；034 增加 OWNER 重命名活动租户所需的 UPDATE RLS
与列级最小权限；035 撤销 migration 009 遗留的 API 直接创建 `workflow.jobs` 能力，使四时段计划只能
由受保护的邀请函数原子创建。新版登录、资产作用域、Jelly 独立租户迁移、报告调度和租户治理均
依赖这些对象，不能先启应用再补 SQL。

## 当前升级：从 021（或 022–034 中间状态）到 035

### A. 迁移内容与为什么不能跳过

| Migration | 作用 | 当前版本处理 |
|---|---|---|
| `022_self_registration.sql` | 曾增加匿名“用户 + tenant + OWNER”注册 RPC | 保留历史 checksum；025 撤销并删除该 RPC，恢复 L1 邀请制 |
| `023_trade_fill_decision_api.sql` | 增加成交确认人、成交/决策 API 所需权限与不可变触发器 | 025 将确认人改为 tenant 复合外键，并限制只能写 `auth.uid()` |
| `024_password_reset_and_tenant_creation.sql` | 增加密码重置 token/RPC，也曾增加登录用户自建 tenant RPC | 保留密码重置；025 删除自建 tenant RPC，并加入 access 会话版本轮换 |
| `025_identity_session_and_trade_integrity_hardening.sql` | forward-fix 身份会话和成交完整性问题 | 保留历史 checksum；当前应用仍依赖其 auth_version、复合外键和 event 唯一关联 |
| `026_wecom_callback_replay_guard.sql` | 增加短期、不透明回调指纹表与原子 SECURITY DEFINER claim | 当前企微 POST 回调持久防重所必需；表不向浏览器/API/Worker直接开放 |
| `027_market_hot_read_model.sql` | 增加不可变市场热点快照及最小权限 | 当前依赖；Worker `SELECT/INSERT`、API `SELECT`、`authenticated` 不可直读 |
| `028_portfolio_import_item_update_policy.sql` | 补齐导入项 UPDATE RLS | 029 的前置迁移；只允许 OWNER/ADMIN/EDITOR 在父批次为 DRAFT 时锁定/更新行，列级 UPDATE 授权不扩大 |
| `029_holding_start_inference_metadata.sql` | 持久化持有起点的方法、可信度和原因 | 030 的前置迁移；扩展导入项与区间指标，允许 `PORTFOLIO_ACTIVITY_ESTIMATE`，并兼容回填既有记录 |
| `030_tiantian_job_status_read_policy.sql` | 补齐批次详情所需的数据任务状态只读能力 | 031 的前置迁移；只开放关联查询使用的六列，并由 RLS 限制为当前租户，不开放 Worker 租约和错误字段 |
| `031_import_draft_governance.sql` | 保存草稿取消原因和重解析替代链 | 032 的前置迁移；约束 `CANCELLED` 必须有明确原因，记录新草稿替代的同租户旧草稿，并授予 API 最小列权限 |
| `032_tenant_user_account_ownership.sql` | 分离平台与租户权限，增加默认租户、账户受益归属和个人租户邀请 | 033 的前置迁移；Dashboard 默认个人作用域、独立租户注册及 Jelly 迁移的共同前置条件 |
| `033_personal_tenant_report_jobs.sql` | 新个人租户原子初始化四时段报告计划 | 034 的前置迁移；只修改 `CREATE_PERSONAL_TENANT` 接受邀请分支，不回填已有租户；函数本身不新增任务表权限 |
| `034_tenant_name_management.sql` | 增加 OWNER 重命名当前租户所需的 UPDATE RLS 与列级授权 | 035 的前置迁移；只开放 `name`、`updated_at`，不允许 API 修改租户状态或基础币种，浏览器角色仍不可直写 |
| `035_personal_tenant_job_privilege_hardening.sql` | 关闭 migration 009 遗留的 API 任务 INSERT 能力 | 当前目标；撤销 `wealthsail_api` 对 `workflow.jobs` 的直接 INSERT 并移除休眠策略，保留 033 的 SECURITY DEFINER 原子初始化 |

不要修改已经在服务器执行过的 022–024 文件，也不要删除
`public.wealthsail_schema_migrations` 中的历史行。025 是正式的前向修复：它会在发现跨 tenant
`confirmed_by` 或一个 ledger event 已被多个 fill 引用时主动停止，要求先确认数据含义并用受审计
脚本修正，不能自动猜测金融事实。026～034 也是只前进 migration，已经执行后不得改写 SQL 或
checksum；035 同样是只前进 migration，发现问题必须新增编号做 forward-fix。

### C. dry-run：只看计划，不执行 SQL

迁移必须使用管理员/迁移专用 DSN，不能使用 API 或 Worker 运行时 DSN。把示例目标替换为命令
实际打印的 `host[:port]/database`，两处必须完全一致：

```bash
cd /opt/wealthsail
export MIGRATION_DATABASE_URL='postgresql://migration_admin:***@db.example:5432/postgres?sslmode=require'

.venv/bin/python scripts/migrate.py \
  --environment production \
  --confirm-target db.example:5432/postgres \
  --dry-run
```

如果从 Windows PowerShell 连接同一个生产 Supabase/PostgreSQL，命令等价如下。runner 没有
`--target 35` 参数；它会按照 migration ledger 自动应用全部缺失版本，直到仓库当前最新的 035：

```powershell
cd D:\develop\gitee\WealthSail
```

### D. 正式执行 migration，并理解 readback

去掉 `--dry-run` 执行同一目标：

```bash
.venv/bin/python scripts/migrate.py \
  --environment production \
  --confirm-target db.example:5432/postgres
```

Windows PowerShell 正式执行时只去掉 `--dry-run`：

```powershell
.\.venv\Scripts\python.exe scripts\migrate.py `
  --environment production `
  --confirm-target db.example:5432/postgres
```

成功结果末尾必须同时包含 035 已应用（或已跳过）和自动 readback 成功。从 025 升级的典型末尾是：

```text
APPLIED 026_wecom_callback_replay_guard.sql
APPLIED 027_market_hot_read_model.sql
APPLIED 028_portfolio_import_item_update_policy.sql
APPLIED 029_holding_start_inference_metadata.sql
APPLIED 030_tiantian_job_status_read_policy.sql
APPLIED 031_import_draft_governance.sql
APPLIED 032_tenant_user_account_ownership.sql
APPLIED 033_personal_tenant_report_jobs.sql
APPLIED 034_tenant_name_management.sql
APPLIED 035_personal_tenant_job_privilege_hardening.sql
READBACK OK: roles, RLS, runtime grants, Tiantian import, identity session, tenant governance and trade-integrity contracts
```

“migration readback”不是第二个命令。runner 在 SQL 逐个事务提交后自动检查角色、RLS、权限、
天天基金表、密码重置函数、`auth_version`、确认人复合外键、确认策略、event 唯一索引、026 回调
claim 表/SECURITY DEFINER 函数、027 market-hot 表和 API/Worker/browser 权限、028 导入项
UPDATE policy 的角色与 DRAFT 父批次约束、029 持有起点元数据列和约束，以及 030 数据任务状态
列级 SELECT 与当前租户 RLS、031 的取消原因与替代链、032 的平台角色、默认租户、账户归属、
个人租户邀请和最小权限、033 的个人租户四时段计划原子初始化、034 的 OWNER 租户名称更新策略
和列级最小权限，以及 035 对历史 API 任务 INSERT 权限和休眠策略的关闭。若 SQL
显示 APPLIED、随后 readback 失败，数据库迁移可能已经提交：此时停止发布并做 forward-fix，不能
回删 migration ledger，也不能重写 025–035。

### E. 手工回读关键结构

自动 readback 成功后，仍建议由发布人执行以下只读 SQL并保存脱敏结果：

```sql
SELECT version, filename, applied_at
FROM public.wealthsail_schema_migrations
WHERE version BETWEEN 21 AND 35
ORDER BY version;

SELECT column_name, data_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_schema='identity' AND table_name='profiles'
  AND column_name='auth_version';

-- L1 禁止的 RPC 必须为 0 行。
SELECT n.nspname, p.proname, pg_get_function_identity_arguments(p.oid)
FROM pg_proc p JOIN pg_namespace n ON n.oid=p.pronamespace
WHERE n.nspname='identity'
  AND p.proname IN ('register_with_tenant','create_tenant');

SELECT conname, pg_get_constraintdef(oid)
FROM pg_constraint
WHERE conrelid='ledger.trade_fills'::regclass
  AND conname='fk_trade_fills_confirmed_by_tenant';

SELECT indexname, indexdef
FROM pg_indexes
WHERE schemaname='ledger'
  AND indexname='uq_trade_fills_ledger_event';

SELECT policyname, cmd, roles, with_check
FROM pg_policies
WHERE schemaname='ledger' AND tablename='trade_fills'
  AND policyname='domain_api_update';

SELECT policyname, cmd, roles, qual, with_check
FROM pg_policies
WHERE schemaname='ledger' AND tablename='portfolio_import_items'
  AND policyname='domain_api_update';

SELECT policyname, cmd, roles, qual
FROM pg_policies
WHERE schemaname='workflow' AND tablename='job_runs'
  AND policyname='job_runs_api_select';

SELECT column_name,
       has_column_privilege(
           'wealthsail_api', 'workflow.job_runs', column_name, 'SELECT'
       ) AS api_can_read
FROM unnest(ARRAY[
    'id','tenant_id','status','job_type','payload','available_at'
]) AS allowed(column_name);

SELECT table_name, column_name, data_type, is_nullable, column_default
FROM information_schema.columns
WHERE table_schema='ledger'
  AND table_name IN ('portfolio_import_items','position_period_metrics')
  AND column_name IN (
      'holding_start_method','holding_start_confidence','holding_start_reasons'
  )
ORDER BY table_name, column_name;

SELECT column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_schema='ledger' AND table_name='portfolio_import_batches'
  AND column_name IN ('terminal_reason','supersedes_batch_id')
ORDER BY column_name;

SELECT conname, pg_get_constraintdef(oid)
FROM pg_constraint
WHERE conrelid='ledger.portfolio_import_batches'::regclass
  AND conname IN (
      'portfolio_import_batches_terminal_reason_value_check',
      'portfolio_import_batches_terminal_reason_check',
      'portfolio_import_batches_not_self_superseding_check',
      'portfolio_import_batches_tiantian_supersession_check',
      'fk_portfolio_import_batches_supersedes'
  )
ORDER BY conname;

SELECT to_regclass('workflow.wecom_callback_claims') AS replay_claim_table,
       to_regclass('market.market_hot_snapshots') AS market_hot_table;

SELECT n.nspname, p.proname, p.prosecdef,
       pg_get_function_identity_arguments(p.oid) AS args
FROM pg_proc p JOIN pg_namespace n ON n.oid=p.pronamespace
WHERE n.nspname='workflow' AND p.proname='claim_wecom_callback';

SELECT has_table_privilege('wealthsail_api','market.market_hot_snapshots','SELECT')
         AS api_can_read,
       has_table_privilege('wealthsail_worker','market.market_hot_snapshots','INSERT')
         AS worker_can_insert,
       has_table_privilege('authenticated','market.market_hot_snapshots','SELECT')
         AS browser_can_read;

SELECT pg_get_functiondef(
  'identity.accept_invitation(text,text,text,text)'::regprocedure
) AS accept_invitation_definition;

SELECT has_table_privilege('wealthsail_api','workflow.jobs','INSERT') AS api_can_insert_jobs,
       has_table_privilege('authenticated','workflow.jobs','INSERT') AS browser_can_insert_jobs;

-- 必须返回 0 行，避免未来误授表权限时重新开放直接创建任务。
SELECT policyname, roles, cmd, with_check
FROM pg_policies
WHERE schemaname='workflow' AND tablename='jobs'
  AND policyname='domain_api_insert';

SELECT has_column_privilege('wealthsail_api','identity.tenants','name','UPDATE')
         AS api_can_update_name,
       has_column_privilege('wealthsail_api','identity.tenants','updated_at','UPDATE')
         AS api_can_update_timestamp,
       has_column_privilege('wealthsail_api','identity.tenants','status','UPDATE')
         AS api_can_update_status,
       has_column_privilege('authenticated','identity.tenants','name','UPDATE')
         AS browser_can_update_name;

SELECT policyname, roles, qual, with_check
FROM pg_policies
WHERE schemaname='identity' AND tablename='tenants'
  AND policyname='domain_api_tenant_owner_update';
```

判定标准：migration ledger 连续包含 021–035；`auth_version` 为非空 BIGINT 且默认 1；两个禁止 RPC
查询为 0 行；确认人 FK 同时包含 `tenant_id, confirmed_by`；唯一索引带非空条件；UPDATE policy 的
WITH CHECK 含 `confirmed_by = auth.uid()`；026/027 两张表存在；claim 函数为 SECURITY DEFINER；
market-hot 权限必须是 API 可读、Worker 可写、browser 不可直读。导入项 UPDATE policy 的 `USING`
与 `WITH CHECK` 都必须同时包含 OWNER/ADMIN/EDITOR 角色检查和父批次 `status = 'DRAFT'` 约束。
导入项还必须具有非空的 `holding_start_method/confidence/reasons`，区间指标必须具有非空 confidence，
相关 CHECK 约束必须接受 `PORTFOLIO_ACTIVITY_ESTIMATE`。`job_runs_api_select` 必须只授予
`wealthsail_api`，条件包含 `identity.is_tenant_member(tenant_id)`；六个允许列均应可读，但整表
`SELECT` 必须仍为 false。批次表必须有 `terminal_reason`、`supersedes_batch_id` 和上述五个 031
约束；同租户替代外键不得允许新批次指向自身或其他租户批次。`accept_invitation` 定义必须只在
`CREATE_PERSONAL_TENANT` 分支插入上述四个 session 的启用任务；API 与 `authenticated` 的任务
INSERT 权限均必须为 false，且 `workflow.jobs` 不再存在 `domain_api_insert` 策略。033 不负责已有
租户回填。租户名称权限检查必须依次为 true、true、false、false；
`domain_api_tenant_owner_update` 必须只授予 `wealthsail_api`，且 `USING` 与 `WITH CHECK` 都包含
当前租户 OWNER 校验。

### F. 应用重启与最小冒烟

数据库和 `api.env` 都确认后，再按 API → Worker → 前端代理顺序重启。systemd 单服务部署执行：

```bash
sudo systemctl restart wealthsail
sudo systemctl status wealthsail --no-pager
sudo journalctl -u wealthsail -n 200 --no-pager
```

随后验证：受邀注册仍可用；登录后可访问 `/api/v1/auth/me`；登录页不存在自助注册；发起密码重置
后 URL 使用 `#reset-token=` 且页面读取后立即清理；重置前的 access/refresh token 都变为 401；
SELL 超卖、BUY 缺现金或出局条件均被拒且无部分账本写入；合法成交确认后持仓/NAV 当次可见；
同一已认证企业微信回调重复提交只进入领域一次；Worker 至少生成一条 market-hot 快照，已登录 API
读取同一快照且不会在 GET 内调用 Provider。固定时点短暂停机应在 15 分钟内 catch-up，近期
PENDING/FAILED report run 只在 30 分钟窗口、最多 5 次内恢复。

### G. 已有租户受控回填 POST_MARKET 计划

migration 033 只保证新个人租户具备四时段计划，不自动修改已有租户。已有 `so` 租户通过受控脚本
回填一个标准 `POST_MARKET` 计划。先用迁移/管理员连接执行只读查询，确认名称只命中预期租户并
记录 UUID；若出现多个同名租户，必须先人工核实，不能任选一行：

```sql
SELECT id, name, status
FROM identity.tenants
WHERE name = 'so'
ORDER BY id;
```

## 历史基线：migration 021 改了什么

`021_tiantian_fund_import_and_position_metrics.sql` 是向前兼容的增量迁移，主要包括：

1. `ledger.portfolio_source_bindings`：把匿名化天天基金来源账号绑定到一个专用投资账户；
2. 扩展 `portfolio_import_batches/items`：支持 v2 ZIP、DRAFT 预览、逐项差异、终态幂等和
   当前快照的 `POSITION_SNAPSHOT`；
3. `portfolio_import_source_records` 与 `portfolio_source_transactions`：保存可审计的第三方
   来源事实，历史流水不伪造为 WealthSail 成交/现金流；
4. `position_period_metrics`：物化持有起始日、官方单位净值最高/最低和区间位置；
5. 扩展 `workflow.job_runs`：支持可租约、可重试、进程重启后可恢复的

6. 增加复合外键、唯一索引、不可变触发器、RLS、API/Worker 最小授权和浏览器直写防线。

停止。数据库事务已经提交时应采用 forward-fix 修复读回问题，不能假装 migration 未执行。

### 3. 021 历史版本故障与回滚策略（仅供追溯）

- **dry-run 失败**：数据库尚未改变；修复目标、凭据、代码版本或 checksum 问题后重试。
- **SQL migration 失败**：单个 migration 在事务中执行，正常会回滚该版本；保留完整错误并检查
  ledger，修复后重跑。不要手工插入版本号。
- **021 已提交但 readback 失败**：停止部署新应用，保留数据库快照，以 forward-fix 修复权限或
  契约；不要 DROP 新表或删除 migration ledger。
- **应用启动失败**：设置 `TIANTIAN_IMPORT_ENABLED=false`，恢复上一版应用代码；021 是增量 Schema，
  可以保留，不需要向下迁移。修复后重新部署。
- **已发生确认导入后发现业务缺陷**：立即关闭功能开关阻止新写入，保留 Worker/数据库和审计证据；
  已确认账本只能通过业务 REVERSAL/新快照更正，禁止删表、删批次或回滚 migration。
- **只想暂停净值 Provider**：不要重放或删除已确认批次；可以停止 Worker 进行排障，但这会同时
  影响四时段报告和 Outbox，应安排维护窗口。任务会保留在数据库，恢复 Worker 后继续认领。

功能开关关闭只阻止新预览、确认、取消和手工重试；已有持仓、导入历史和指标仍应可读，便于
排障和向用户说明。完整数据库恢复只能使用升级前备份，并且仅适用于尚未产生新业务事实的情况。

```bash
psql "$MIGRATION_DATABASE_URL" \
  -X \
  -v ON_ERROR_STOP=1 \
  -c "
SELECT tenant_id, user_id, channel_type, COUNT(*) AS active_count
FROM identity.channel_bindings
WHERE status = 'ACTIVE'
GROUP BY tenant_id, user_id, channel_type
HAVING COUNT(*) > 1;
"
```

正常结果应为：

```text
(0 rows)
```

确认绑定函数已经收紧权限：

```bash
psql "$MIGRATION_DATABASE_URL" \
  -X \
  -v ON_ERROR_STOP=1 \
  -c "
SELECT
    p.oid::regprocedure AS function_name,
    p.prosecdef AS security_definer,
    p.proconfig AS fixed_configuration,
    p.proacl AS execute_acl
FROM pg_proc p
JOIN pg_namespace n ON n.oid = p.pronamespace
WHERE n.nspname = 'identity'
  AND p.proname = 'consume_binding_challenge';
"
```

预期应看到：

- `security_definer = t`
- `fixed_configuration` 包含固定 `search_path`
- `execute_acl` 包含 `wealthsail_api=X/...`
- 不应存在 PUBLIC EXECUTE

## 七、清除管理员 DSN

完成后立即清理 shell 环境中的管理员连接：

```bash

```

确认已经清除：

```bash
test -z "${MIGRATION_DATABASE_URL:-}" \
  && echo "OK: migration credential cleared" \
  || echo "WARNING: credential still exists"
```

## 最简可复制版本

确认已准备好管理员 DSN后，可以按下面这一组执行：

```bash
cd /opt/wealthsail

git pull origin master
git rev-parse --short HEAD

read -rsp "请输入 MIGRATION_DATABASE_URL: " MIGRATION_DATABASE_URL
echo
export MIGRATION_DATABASE_URL

MIGRATION_TARGET="$(
  .venv/bin/python -c \
  'import os; from scripts.migrate import safe_target_name; print(safe_target_name(os.environ["MIGRATION_DATABASE_URL"]))'
)"

printf '迁移目标：%s\n' "$MIGRATION_TARGET"

.venv/bin/python scripts/migrate.py \
  --environment production \
  --confirm-target "$MIGRATION_TARGET" \
  --dry-run

.venv/bin/python scripts/migrate.py \
  --environment production \
  --confirm-target "$MIGRATION_TARGET"

unset MIGRATION_DATABASE_URL
unset MIGRATION_TARGET

sudo systemctl restart wealthsail
sudo systemctl status wealthsail --no-pager -l

sudo journalctl -u wealthsail \
  --since "5 minutes ago" \
  --no-pager \
  -o cat

curl -fsS http://127.0.0.1:8000/healthz
echo
```

正式执行前，dry-run 的关键判断是：旧版本全部 `SKIP`，并且只出现一个 `PLAN 020_channel_binding_uniqueness_hardening.sql`。
