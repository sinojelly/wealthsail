# WealthSail 基金机会发现与买卖风控全流程说明

本文解释当前系统怎样把公开新闻转成可研究的基金机会，怎样用真实基金价格判断入场位置，以及跟踪基金、持仓基金在 14:30 如何进行风险复核。

核查日期为 **2026 年 10 月 21 日**。说明以当前仓库代码和当天本机运行环境的只读核查为依据。文中的“已实现”表示代码已有对应路径；是否实际自动执行，还取决于 Worker、任务、账号作用域、数据和通知配置。技术条件和研究分数均不表示收益保证。

## 一、先回答最关心的几个问题

| 问题 | 当前答案 |
| --- | --- |
| 系统会从新闻寻找基金吗？ | 会。公开新闻先形成产业主题，再到基金主数据中查找相关产品，与核心基金池共同研究。仅名字匹配不能证明基金真实持仓。 |
| 有相关新闻，就会建议立即买入吗？ | 不会。还要核对同一基金的真实净值历史、技术条件、买入区间、风险价格和入场保护。 |
| 股价或基金价格越高，机会分数就越高吗？ | 不是。系统区分技术候选、价格入区、过热和入场受限；高位基金会后排或暂缓入场。 |
| 点击“跟踪”就表示已经买入吗？ | 不表示。跟踪是研究记录；持仓来自已确认账本和持仓投影。 |
| 跟踪/持仓基金有自动卖出风险判断吗？ | 代码已有 14:30 风险复核，包括固定止损、目标一/目标二和 RSI 过热；它发出观察提示，不自动下单或确认成交。 |
| 14:30 应该参考当日估值吗？ | 应优先使用有效的当日盘中估值，代码也这样选择；过期、缺来源、日期不符的估值不参与当前判断。取不到有效估值时，才使用合格的已确认净值，并明确价格依据。 |
| 是否已有移动止损、最高点回撤自动卖出？ | 当前个人卖出风险模块没有这些规则。已有最大回撤/区间高低点等分析数据，不等于已经接入自动卖出判断。 |
| 本机现在已经每天自动监控了吗？ | 截至本文核查时，本机没有启用该机会推送所需的用户作用域和专用 Webhook，也没有有效跟踪基金或正份额基金持仓；未发现该链路的 14:30 执行记录。详见第九节。 |

## 二、从公开新闻到基金候选：先发现方向，再核对产品身份

当前流程可以按以下顺序理解：

1. 采集公开新闻、官方宏观数据、行业事件和可用行情。
2. 提取“发生了什么、属于什么行业、处于什么阶段、可能影响哪个环节”。
3. 根据行业主题查询真实基金主数据，得到可核验的基金代码、市场和产品类型。
4. 获取该基金自己的真实历史净值，计算双轨价格区间。
5. 模型组织投资假设、催化、风险和验证点；服务器校验来源、标的与价格。
6. 服务器叠加入场保护，计算研究优先级，形成机会卡片和扫描总表。
7. 用户决定是否跟踪；真实买入后，通过确认的账本/导入形成持仓。

### 2.1 新闻不是直接的买单

例如，新闻出现“存储行业订单改善”或“企业宣布回购计划”，系统可以将其识别为存储/半导体方向的研究线索。但还要区分：

- 计划、提议、宣布、已实施和媒体报道，不是同一种事实状态。
- 产业链受益分析是条件推导，不能写成基金必然上涨。
- 行业新闻与基金名称相关，只是候选发现线索，不能据此声称基金持有某家企业。
- 一条新闻缺少原始出处、发布时间或关键事实时，不能补造已经核实的结论。

`backend/macro/daily_research.py` 中的 `build_prompt()`、`validate_report()` 负责公共研究请求与报告校验；`backend/macro/value_directions.py` 将方向与已存在的公共来源、基金标的和服务器价格锚点绑定。模型可以解释和选择标的，不能自行编造净值、止损或目标价格。

### 2.2 当前代表池是“40 个核心代码 + 最多 6 个动态名额”

当前 `backend/investment/dynamic_discovery.py` 定义：

```text
CORE_FUND_CODES：40 个核心基金代码
DYNAMIC_LIMIT：最多 6 个新闻驱动动态名额
SELECTION_LIMIT：总共最多 46 个研究产品
```

这是受控的代表池扫描，不是“全市场每只基金每天都计算完毕”。新闻驱动的动态查询可以从更大的基金主数据中查找产品，再选入本轮研究。基金主数据、数据覆盖率和产品身份不足时，实际有价格的基金数可能低于上限。

主题识别涵盖存储、半导体、AI 算力、机器人、稀土有色、金融、创新药、黄金能源、航天军工、消费、红利低波，以及电力、游戏、化工等方向。代码会排除部分不适合本轮研究的产品名称，例如外币份额、后端收费或清盘类名称，并偏向合适的人民币份额。具体产品是否真正跟踪某指数，仍要看经过核验的产品关系，而不是名称相似度。

主要实现：

- `backend/investment/dynamic_discovery.py`：`event_themes()`、动态基金查询与名额限制。
- `backend/investment/discovery.py`：`select_research_assets()`、`build_discovery_packet()`、`discovery_packet()`。
- `reference.research_fund_catalog`：产品身份主数据。
- `reference.discovery_fund_universe`、`reference.theme_asset_graph` 和已核实的产品/指数关系：种子和关联证据。

### 2.3 公共研究与个人持仓分开

公共日报使用共享市场事实和基金研究坐标，不把个人账户、持仓金额或私有研究笔记交给公共研究模型。个人跟踪、持仓和卖出风险在后续按当前用户作用域单独读取。

因此，“今天日报推荐了某只基金”不等于“系统认为用户已经持有它”；“用户曾关注过某个行业”也不等于自动增加该行业仓位。

## 三、怎样判断基金价格是否适合入场

当前计算器为 `backend/indicators/actionable_zones.py`，方法版本为 `actionable-zones-v4`。它针对同一标的、同一价格口径计算：

- MA20、MA60、MA200。
- Wilder RSI14。
- 有真实高低价时的 Wilder ATR14。
- 20 期布林带、20 期动量。
- 单位净值场景下的净值波动尺度。
- 历史足够时，最近 220 个有效交易观察点中的净值分位。

### 3.1 必须区分四种状态

| 状态/字段 | 含义 | 不能推导出的结论 |
| --- | --- | --- |
| `CANDIDATE` | 该轨技术条件满足，是研究候选 | 不能单独表示当前可以买入。 |
| `inEntryZone` | 当前价格在区间内，是几何位置事实 | 技术未触发或有入场保护时，仍不算入场就绪。 |
| `entryReady` | 技术满足、价格入区、风险坐标可用，且没有生效的入场阻断 | 不表示已经下单、成交或一定盈利。 |
| `WATCH` / `INSUFFICIENT` | 条件尚待触发，或证据不足 | 不应编成“已入右侧买区”。 |

净值、轨道、日期、来源、单位和历史质量必须匹配。不能把指数点位当作基金净值，也不能把一只基金的价格放到另一只基金卡片上。

### 3.2 左侧：在低位或超卖时寻找低吸研究机会

左轨名称为 `LEFT_VALUE`。当前满足以下任一已知条件，可以形成左侧技术候选：

1. 有有效估值证据时，PE 历史分位不高于 40%。
2. 当前价格相对真实 MA200 的偏离不高于 -8%。
3. RSI14 不高于 38。
4. 当前价格不高于布林下轨的 1.02 倍。

这几个条件是“或”的关系，并不要求全部成立。普通基金单位净值本身没有可以直接套用的 PE，相关估值分支缺失时保持未知，不能虚构一个 PE 来凑候选。短历史缺 MA200，也不应抹掉真实存在的 MA20、RSI 等短期信息。

左侧候选说明位置可能值得研究，但价格持续下跌时仍可能继续跌。是否反转，需要结合真实催化、盈利兑现、价格结构和风险承受能力。

### 3.3 右侧：趋势满足以后，等待回踩 MA20

右轨名称为 `RIGHT_TREND`。当前基础技术条件为：

```text
当前价格 >= MA20
20 期动量 > 0
RSI14 <= 60
```

还要通过高位保护。当前实现并不是简单采用“MA20 >= MA60 且 RSI <=70”这一旧描述。

右侧入场区间固定锚在 MA20 周围：

```text
entry_low  = MA20 - 0.55 × scale
entry_high = MA20 + 0.25 × scale
```

有真实 OHLC 时，`scale` 为 ATR14；只有基金单位净值时，使用明确标注的净值波动尺度。当前价格不会被用于把买区上沿拉高到自己所在位置。

当净值高于上沿时，会显示类似：

```text
🚀 高于买区 3.50%·等待回踩均线
```

即使趋势尚好，也不应因此把已偏离均线的位置说成“已经进入右侧买区”。

### 3.4 没有真实 OHLC 时，不冒充 ATR

基金历史通常只有单位净值，没有每日最高、最低成交价。当前净值波动尺度取下列数值的最大值：

```text
最近 14 次净值绝对变化均值 × 1.4
最近 20 期净值总体标准差 × 0.65
最新净值 × 1.2%
```

方法标记为 `NAV_ABS_CHANGE_STD_V1`，它不是 ATR。这样可以计算有解释的风险参考价，同时避免声称掌握不存在的高低价数据。至少需要相应的真实连续净值历史；异常、无效或顺序冲突的观察不会被简单删除后拼成“完整历史”。

### 3.5 一年高位与 QDII 滞后保护

在基金有至少 220 个有效连续观察点时，计算当前净值在最近这 220 点中的经验分位。历史不足时分位保持未知，不把几个月历史冒充一年。

满足以下两个条件时，显示近一年高位警告并阻断入场：

```text
一年净值分位 >= 85%
且 当前净值 > MA20 × 1.02
```

QDII 还存在“最新已披露净值并未反映最新外盘”的问题。当前会把基金净值日期与对应外盘冲击日期对齐；对应标的出现至少 2% 的已发生下跌时，可覆盖为琥珀色暂缓入场警告。新闻中的预测、否定、旧闻或其他资产跌幅不能直接算到该基金上；美股纽约交易日与上海采集日也要分开判断，已经计入净值的同一交易日跌幅不能再次视作新冲击。

例如，`161129` 和 `162411` 的油气风险不能因为名字中有“标普”就套用标普 500 的跌幅。当前已知产品使用明确的市场映射。

对应实现：`backend/macro/daily_research.py` 的 `apply_entry_guards()`、`_fund_markets()`、`_current_market_losses()`。

### 3.6 申购现实约束也要看

申购状态来自已有 `reference.fund_profiles` 的有效记录，经只读视图 `reference.fund_subscription_status` 提供给研究链路：

- 暂停申购：显示红色“⛔ 暂停申购”。
- 确认的单日限额不超过 100 元：显示“⛔ 单日限购10元”等具体标签。
- 这些基金从首选建仓计划中剔除，扫描总表仍可保留观察和限制说明。

这也解释了为什么“行业看好、技术不错”仍可能不适合作为实际建仓产品。反过来，没有红标也不能证明柜台无限额：没有同步到的状态应理解为未知，实际申购仍应核对销售机构的最新规则。

对应实现：`backend/jobs/opportunity_market.py` 的 `read_fund_subscription_status()`、`normalize_subscription_status()`；数据库迁移 `088_research_fund_subscription_status.sql`。

## 四、建议区间、止损和 T1/T2 是怎样形成的

计算器会先给入场区间，再计算止损与目标，并验证显示后的顺序：

```text
止损 < 入场下沿 <= 入场上沿 < T1 < T2
```

按显示后的入场中点到止损的风险距离，目标还要至少满足：

```text
T1 距离 >= 1.5 × 风险距离
T2 距离 >= 2.4 × 风险距离
```

真实 ATR 与净值波动尺度的初始锚点略有不同；MA60、MA200、布林上轨等也会参与目标参考。最终还会检查舍入后价格是否为正、是否塌缩、顺序是否有效。基金净值通常显示四位小数，不能通过舍入把原本不成立的区间“修成成立”。

一个纯粹用于解释代码的平坦净值例子：最近净值都为 1.0000，MA20 为 1.0000，净值波动尺度为 0.0120。右轨的价格参考为：

```text
入场区间：0.9934–1.0030
止损参考：0.9760
T1：1.0315
T2：1.0540
```

但平坦序列的 20 期动量不为正，因此右轨仍是 `WATCH`。价格在区间内，不等于趋势已经触发。这个例子也说明不能只看一个区间或一个数字下决定。

这些是研究参考坐标，不是交易所挂单，也不是基金申赎的最终成交净值。基金通常按申赎规则确认成交，盘中看到的估值与最终确认净值可能有差异。

## 五、机会怎样排序：先分组，再看研究分数

`backend/investment/opportunity_scoring.py` 实现确定性的公共研究优先级，方法版本为 `opportunity-priority-v1`。

当前排序首先看分组：

1. 技术触发且价格入区、当前没有入场阻断的基金。
2. 尚在等待价格或技术条件的基金。
3. 当前价格已达到 T1，或 RSI 达到 70 及以上的高位观察基金。

同一组内再比较研究分数、收益风险比等。方向排序使用同组内合格基金的依据，受限或高位基金不能通过一个高分把整个方向推到可入场方向前面。服务器先验证标的和价格，再进行最终排序；模型自行输出的数字不是排序权威。

分数由以下部分组成：

| 分项 | 当前规则摘要 |
| --- | --- |
| 技术位置 | 入场就绪 40 分；只有技术候选 15 分；未触发但价格在参考区内 5 分；被阻断则该项为 0。 |
| 行业催化 | 符合日期、来源、行业主题和正向内容条件的独立新闻父来源，10 分起，最多 20 分；重复摘要不能算成多条独立催化。 |
| ETF 份额 | 有可核对的上交所 ETF 份额增长证据时 15 分，缺证据不补分。 |
| 收益风险 | 以入场区间中点、止损和 T1 计算，最多 15 分。 |
| 强度 | 左侧结合 RSI；右侧结合正动量，最多 10 分。 |

需要注意两个不同阈值：排序里的高位观察使用 **RSI >=70**，个人卖出风险里的 RSI 提醒使用 **RSI >=72**；右侧买点上限则是 **RSI <=60**。三者用途不同。

分数表达的是系统当前规则下的研究优先级，不是胜率、预期收益率或收益保证。行业新闻、同板块 ETF 份额与目标基金的关系有时只是 `SECTOR_PROXY`，不能解释为该基金已经获得同等资金流入。

## 六、“跟踪基金”和“持仓基金”分别是什么

### 6.1 跟踪保存的是研究计划

点击“+ 跟踪”后，系统建立用户私有研究轨迹，核心数据位于：

- `research.study_tracks`：是否启用、标的作用域等。
- `research.study_versions`：当时的研究版本和冻结的 `actionablePlan`。

冻结计划保存当时所选基金、轨道、买区、止损、目标、来源和日期。之后价格核对使用这些原始参考线，不会因为价格涨跌就悄悄重算成“又在买区内”。图表切换半年、两年或成立以来，也不应改变已经冻结的计划坐标。

只有启用、身份匹配且未过期的跟踪才进入当前风险目标。仅跟踪一个基金，不能证明用户已经买入，更不能计算出用户的真实盈亏。

### 6.2 持仓来自确认的账本与持仓投影

持仓权威链路是已经确认的 `ledger.ledger_events` / `ledger.ledger_legs`，再重放形成 `ledger.position_snapshots` 等投影。产品持仓接口 `portfolio.service.get_positions()` 读取最新持仓投影。

个人风险目标只接受当前用户有实益所有权或共同所有权的有效账户、有效基金身份，以及合格日期/质量的正份额持仓。只拥有某个账户的查看权限，不等于拥有这个账户的基金。

当前 `load_risk_targets()` 会将同一基金的“持仓”和“跟踪”关系合并：

1. 优先使用当前有效私有跟踪的冻结计划。
2. 已持仓但没有私有计划时，可以使用近 10 天内的合格日报同基金计划。
3. 没有可比计划时，不制造止损或 T1/T2；若有有效 RSI，仍可能生成 RSI 过热观察。

对应实现：`backend/investment/sell_risk.py` 的 `load_risk_targets()`；`backend/market/repository.py` 的 `rebuild_confirmed_holdings()`、`refresh_positions()`。

## 七、14:30 自动复核有两条相关但不同的链路

### 7.1 标准基金 14:30 报告与持仓估值

标准 `FUND_1430` 调度在上海时间 14:30 运行。Worker 为持有的场外基金刷新正式净值、公开持仓和盘中估值，持久化市场观察，再生成基金报告。

主要实现：

- `backend/jobs/scheduler.py`：`FUND_1430` 日程。
- `backend/jobs/runner.py`：持久化任务认领、行情刷新和报告执行。
- `backend/market/service.py`：`refresh_market()`、估值选择与持仓投影更新。
- `backend/reports/fund_1430.py`：基于持久化事实生成确定性基金报告。

这条链路还需要已经登记并启用的标准作业、可用的账号/账户数据和运行中的正式 Worker。手动日报刷新并不等于创建了这条标准基金报告作业。

### 7.2 机会中心的 14:30 价格核对与个人卖出风险

另有独立的 `alpha_opportunities` 循环，通常每 60 秒检查是否进入可执行时间窗：

```text
上海交易日 14:30 <= 当前时间 < 15:00
```

它会读取：

- 当前有效的私有冻结跟踪计划。
- 当日合格公共日报中的临时基金研究计划。
- 当前用户的有效跟踪基金、已确认持仓基金等个人风险目标。

这条链路有明确运行前提：

```text
ALPHA_OPPORTUNITY_ENABLED 启用
OPPORTUNITY_TENANT_ID / OPPORTUNITY_USER_ID 配置正确
对应租户成员仍然 ACTIVE
WECOM_OPPORTUNITY_WEBHOOK_URL 已配置
SSE 当天交易日已确认
Worker 的 alpha runtime 正在运行
```

当前配置只绑定一个明确的机会推送用户作用域，不能理解为系统会自动遍历所有租户所有用户。没有配置作用域时，`run_alpha_opportunity_service()` 直接退出；没有专用 Webhook 时，机会核对/推送返回禁用状态，不只是“判断了但没通知”。

执行结果记录到 `research.alpha_opportunity_runs`，用用户、日期和 slot 的唯一约束避免同一时段重复外发。停止跟踪、计划换版本、账户关系变化或任务运行已越过 15:00 时，代码会重新检查有效性，不能沿用启动时的旧目标继续发当前提醒。

主要实现：`backend/jobs/alpha_runtime.py`、`backend/jobs/alpha_opportunities.py` 的 `run_alpha_opportunity_service()`、`sync_alpha_opportunities()`、`load_opportunity_prices()`。

## 八、14:30 怎样使用新浪估值并判断风险

### 8.1 新浪盘中估值已经有真实实现

现有实现不是模型临时猜净值。`backend/integrations/market_data.py` 中：

- `fetch_fund_intraday_estimates()` 批量访问新浪基金估值接口。
- `parse_sina_fund_estimates()` 解析和校验基金代码、估值、估值日期/时间等。
- 方法版本为 `sina/fund-estimate/v1`，来源名为 `Sina-Fund-Estimate`。

标准估值刷新优先采用合格的最近交易日新浪估值；如果外部估值过旧或不可用，再采用本系统基于公开披露持仓的估算；都不合格时保留明确的旧值/不可用状态，不补造当日净值。

内部降级估值只对有披露权重且行情可用的成分进行加权，覆盖率至少 60% 才发布；披露过旧会降为 `STALE`。第三方新浪估值通常没有本系统可核实的完整持仓覆盖率，不会因此虚构一个覆盖百分比。

机会中心核对价格时，优先读取已经持久化的当日 `ESTIMATED_NAV`；缺少可用价格的基金，再按代码调用上述新浪接口。因此，未持仓但已经跟踪的研究基金也有取估值的路径，不局限于标准持仓报告。

完整估值链路的历史说明见 [22.WealthSail基金盘中估值真实数据链路与模拟数据治理.md](22.WealthSail基金盘中估值真实数据链路与模拟数据治理.md)。

### 8.2 哪些当日估值可以用于当前风险判断

个人卖出判断 `evaluate_sell_risk()` 会优先采用合格估值，否则采用合格确认净值。估值至少要满足：

- 同一基金、同一标的身份、同为 `UNIT_NAV`、单位可识别。
- 估值、采集时间和来源有效，不能来自未来。
- 估值属于当天，时间处于 14:00 至 15:00 之间。
- 当前判断仍在 15:00 前，距估值不超过 30 分钟。
- 有披露覆盖率时，覆盖率至少 60%；有上下界时，估值中心必须落在边界内。
- 数据质量和来源满足规则，不把过期或冲突的数值当作实时值。

过了 15:00，盘中估值不再作为“当前有效 14:30 估值”参与实时风险投影；已经运行的 14:30 任务结果仍保存在审计记录中。已确认净值的展示日期也必须保留，它可能是前一交易日或更早的 QDII 净值，不能写成“今天的成交净值”。

### 8.3 当前已有的个人卖出风险规则

目前 `backend/investment/sell_risk.py` 的 `evaluate_sell_risk()` 按以下优先级判定：

| 优先级 | 条件 | 状态 |
| --- | --- | --- |
| 1 | 有效比较价格 <= 冻结止损价 | `STOP_LOSS` |
| 2 | 有效比较价格 >= 冻结 T2 | `TAKE_PROFIT_T2` |
| 3 | 有效比较价格 >= 冻结 T1 | `TAKE_PROFIT_T1` |
| 4 | 有效确认净值序列计算出的 RSI14 >=72 | `RSI_OVERBOUGHT` |

这里的 RSI 来自真实确认净值历史，并要求 RSI 的所属日期与该确认净值匹配；不是拿新浪一个盘中估值点伪造一个新的 RSI。

例如，某只已经跟踪或持有的基金，冻结止损为 1.6000，T1 为 1.9000，T2 为 2.0000：

- 当天 14:29 合格估值为 1.5800，14:30 复核时会提示触及冻结止损。
- 估值为 1.9500，会提示触及 T1；达到 2.0100，优先提示 T2。
- 若只有昨天确认净值可用，提示依据应写“最新确认净值”，而不是伪装成今天盘中结果。
- 有效估值和确认净值都没有时，不产生一个假定的卖出信号。

对当日公共计划但用户既没跟踪也没持有的基金，代码会抑制把它说成用户应该卖掉。仅跟踪的基金可以出现研究风险观察，但依然不证明用户有可赎回份额。

### 8.4 当前没有实现的部分

下面这些不能因为系统有某些分析字段，就宣称已经自动执行：

- 根据买入成本自动设定每只基金百分比止损。
- 基于持仓以来最高净值的移动止损。
- “盈利回撤 X% 就卖出”的跟踪止盈。
- 个人基金最大回撤阈值触发的完整卖出状态机。
- 税费、赎回费、持有天数与基金申赎到账的完整优化决策。
- 自动向销售机构下单、自动赎回或回写真实成交。

当前模块主要是“对有效价格与冻结参考线进行比较，并给当前用户提示”。持仓区间高低点、回撤分析、账户风险预算或历史 MFE/MAE 等数据有各自用途，不等于这些规则已经连成了自动卖出策略。

## 十、怎样确认自动监控真正可用

建议按实际使用顺序核对：

1. **建立真实对象**：对感兴趣基金点击跟踪并保留完整冻结计划；真实持仓通过导入或确认交易进入账本，确认产品代码、账户归属和份额正确。
2. **确认 Worker**：正式 Worker 与机会 alpha runtime 正常运行，不是只有 API 和前端页面启动。
3. **配置作用域与通知**：为机会推送明确指定有效租户、用户及专用 Webhook；标准基金报告则要登记并启用相应 `FUND_1430` 作业。
4. **确认数据时效**：SSE 交易日历、基金身份映射、确认净值历史和当日新浪估值可用；缺数据时能够看到具体缺口，而不是假成功。
5. **在交易日窗口核查**：14:30–15:00 查看对应任务是否出现，结果是否包含正确的 `checked`、`checks`、`riskEstimates` 或 `sellRiskAlerts`。
6. **核对一条真实样本**：检查估值日期/时间、来源、所选价格依据、冻结止损/T1/T2 与提示状态，确认不是拿昨天净值冒充今天估值。
7. **检查实际通知与审计**：任务有结果、消息有投递证据；没有提醒还应区分“没有触发条件”“目标为空”“未启用”“数据不足”和“任务未执行”。

不能用“首页已经能看到日报”替代上述验证。公共日报刷新、基金行情刷新、私人跟踪和 14:30 风险推送是相互关联但各有前提的功能。
