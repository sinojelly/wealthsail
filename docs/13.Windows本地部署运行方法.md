> **当前模型配置**：即时聊天、常规报告中的模型生成和每日公开投研统一使用 Codex。Windows 可使用 [本地启动器](26.Windows-local-development.md) 显式自动发现原生 CLI，或在下文 `.env` 中设置 `CODEX_PATH`；NAS 的独立 runner 与登录文件管理见 [Codex 操作指南](32.Codex统一模型与NAS认证操作指南.md)。

可以。推荐拓扑是：

```text
Windows 浏览器
  → 本地 Vite 前端 localhost:5173
  → 本地 FastAPI localhost:8000
  → 远程 Supabase PostgreSQL
```

前端不要直接保存 Supabase 数据库密码；只有本地 Backend/Worker 连接 Supabase。

如果这是正在运行的生产 Supabase，强烈建议先克隆一个开发/预发布项目。连接生产库时，本地 API 具备真实写权限，并且不要同时启动本地 Worker，否则它会和服务器 Worker 竞争调度、Outbox、净值回填及企微发送任务。

## 1. 获取 Supabase 连接信息

进入 Supabase 项目，点击顶部 `Connect`，记录：

- Project Ref
- Session Pooler Host
- 数据库 `postgres` 用户密码
- 所在 Region

Windows 网络通常以 IPv4 为主，因此建议：

| 用途 | 连接方式 | 端口 |
|---|---|---:|
| Migration | Direct；IPv6 不通时用 Session Pooler | 5432 |
| 本地 API | Transaction Pooler | 6543 |
| 本地 Worker | Session Pooler | 5432 |

Supabase 官方也建议迁移使用 Direct Connection，IPv4 环境的持久客户端使用 Session Pooler；Transaction Pooler 不支持 prepared statements，因此本项目 API DSN 会追加 `statement_cache_size=0`。[Supabase 连接方式说明](https://supabase.com/docs/guides/database/connecting-to-postgres)

共享 Pooler 的用户名格式是：

```text
数据库角色.ProjectRef
```

例如：

```text
postgres.abcdefghijklmnop
wealthsail_api_login.abcdefghijklmnop
wealthsail_worker_login.abcdefghijklmnop
```

[Supavisor 用户名格式说明](https://supabase.com/docs/guides/troubleshooting/supavisor-faq-YyP5tI)

## 2. 迁移 Supabase 到 029

如果服务器上的 Supabase 已经迁移到 `029`，只需 dry-run 检查，不要重复人工执行 SQL。`028` 补齐天天基金导入确认阶段使用 `SELECT ... FOR UPDATE` 时所需的导入明细 UPDATE RLS；`029` 保存持有日期推导方式、可信度和原因。新代码必须先完成 029 再启动，否则预览与后台指标任务会访问不存在的列。

在 PowerShell 中设置迁移管理员 DSN。直接从 Supabase `Connect → Session pooler` 复制，然后填写密码：

```powershell
$env:MIGRATION_DATABASE_URL = "postgresql://postgres.ProjectRef:数据库密码@aws-0-区域.pooler.supabase.com:5432/postgres?sslmode=require"
```

取得确认目标：

```powershell
Set-Location D:\develop\gitee\WealthSail

$target = .\.venv\Scripts\python.exe -c `
  "import os; from scripts.migrate import safe_target_name; print(safe_target_name(os.environ['MIGRATION_DATABASE_URL']))"

$target
```

先 dry-run：

```powershell
.\.venv\Scripts\python.exe scripts\migrate.py `
  --environment development `
  --confirm-target $target `
  --dry-run
```

如果显示 `029` 已经 `SKIP`，说明已经升级。

如果存在未执行版本，备份数据库后正式迁移：

```powershell
.\.venv\Scripts\python.exe scripts\migrate.py `
  --environment development `
  --confirm-target $target
```

最后必须出现：

```text
READBACK OK: roles, RLS, runtime grants, Tiantian import, identity session and trade-integrity contracts
```

详细说明见 [数据库升级方法](11.数据库升级方法.md)。

## 3. 创建 API/Worker 数据库登录角色

迁移会创建：

- `wealthsail_api`
- `wealthsail_worker`

但应用还需要两个带密码的登录角色：

- `wealthsail_api_login`
- `wealthsail_worker_login`

在 Supabase SQL Editor 中执行仓库里的 [provision_supabase_roles.sql](../scripts/provision_supabase_roles.sql)。

生成两个独立密码：

```powershell
.\.venv\Scripts\python.exe -c `
  "import secrets; print('API=' + secrets.token_urlsafe(32)); print('WORKER=' + secrets.token_urlsafe(32))"
```

在 Supabase SQL Editor 中设置密码：

```sql
ALTER ROLE wealthsail_api_login
    WITH PASSWORD '替换成API随机密码';

ALTER ROLE wealthsail_worker_login
    WITH PASSWORD '替换成Worker随机密码';
```

不要让 API 使用 `postgres` 或 Supabase service role；也不要让 API 和 Worker 共用登录角色。

## 4. 测试两个连接

API 使用 Transaction Pooler：

```powershell
$apiDsn = "postgresql://wealthsail_api_login.ProjectRef:API密码@aws-0-区域.pooler.supabase.com:6543/postgres?sslmode=require&statement_cache_size=0"
```

Worker 使用 Session Pooler：

```powershell
$workerDsn = "postgresql://wealthsail_worker_login.ProjectRef:Worker密码@aws-0-区域.pooler.supabase.com:5432/postgres?sslmode=require"
```

测试 API 权限：

```powershell
psql $apiDsn -c @"
SELECT session_user,
       pg_has_role(session_user, 'wealthsail_api', 'SET') AS can_set_api,
       pg_has_role(session_user, 'wealthsail_worker', 'SET') AS can_set_worker;
"@
```

预期：

```text
can_set_api = true
can_set_worker = false
```

测试 Worker 权限：

```powershell
psql $workerDsn -c @"
SELECT session_user,
       pg_has_role(session_user, 'wealthsail_api', 'SET') AS can_set_api,
       pg_has_role(session_user, 'wealthsail_worker', 'SET') AS can_set_worker;
"@
```

预期两项均为 `true`。

## 8. 登录账号

如果 Supabase 已经有 WealthSail 用户，直接使用原账号登录。

空的开发 Supabase 需要建立首个 `OWNER`。先生成密码哈希：

```powershell
.\.venv\Scripts\python.exe -c `
  "from getpass import getpass; from backend.common.auth import hash_password; print(hash_password(getpass('请输入密码：')))"
```

然后在 Supabase SQL Editor 执行一次：

```sql
BEGIN;

WITH new_profile AS (
    INSERT INTO identity.profiles (
        id, email, nickname, password_hash
    )
    VALUES (
        gen_random_uuid(),
        'owner@wealthsail.local',
        '本地管理员',
        '替换为刚生成的bcrypt哈希'
    )
    RETURNING id
),
new_tenant AS (
    INSERT INTO identity.tenants (
        id, name, status, base_currency
    )
    VALUES (
        gen_random_uuid(),
        '开发测试租户',
        'ACTIVE',
        'CNY'
    )
    RETURNING id
)
INSERT INTO identity.tenant_members (
    tenant_id, user_id, role, status
)
SELECT new_tenant.id, new_profile.id, 'OWNER', 'ACTIVE'
FROM new_profile, new_tenant;

COMMIT;
```

之后使用：

```text
邮箱：owner@wealthsail.local
密码：刚才输入的密码
```

登录后可以在 Web 管理页面生成邀请码。

## 生产 Supabase 的额外注意事项

如果连接的是服务器正在使用的真实生产 Supabase：

- 不要执行开发 Seed。
- 不要启动本地 Worker。
- 不要设置 `TIANTIAN_IMPORT_ENABLED=true`，除非明确要写入生产持仓。
- 本地 API 不是只读模式，页面操作可能修改生产数据。
- 不要用 `postgres` 管理员 DSN 运行 Backend。
- 最好创建 Supabase Branch/独立项目或恢复一份脱敏备份用于本地开发。
- Migration 只在确认备份、目标和计划后执行。
- 调试完成后清除迁移管理员变量：

```powershell
Remove-Item Env:MIGRATION_DATABASE_URL
```

完整的 API/Worker 分权和连接池设计见 [前后端实现与部署规范](10.WealthSail-MVP前后端实现与系统部署规范.md)。
