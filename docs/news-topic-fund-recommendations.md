# 新闻机会到基金推荐

研究主题直接挂载真实基金关联。即使模型返回 `valueDirections=[]`、行业身份尚未登记、风险查询缺少执行回执或审核预算已用尽，主题仍进入基金匹配。页面位置遵循[UI契约25](25.投资机会UI设计.md)的四入口设计：“今日重点”摘要最多3个精选机会，完整主题基金资料按需展开；“经济事件”只引用关联机会入口，不重复铺开全量基金卡。完整主题目录默认收起、展开时才读取。此处描述目标契约，实施与NAS验收以任务证据为准。

展示报告匹配读取`displayedReportId`自身归档；本次研究观察使用`currentResearchId`独立读取并标注来源/日期。历史READY与当前RUNNING/FAILED/UNCERTAIN/跨日STALE共存时，不能用当前ID覆盖历史匹配或让模块静默消失。404、未归档/匹配待处理、资料不足和明确零匹配分别说明；零直接候选不代表相关观察基金也为零。摘要排序不改变资格，名称候选/风险关联/间接观察继续准确标注，缺少原归档价位不补造买卖数字。完整基金桌面左信息右图、窄屏上下排列，保留价格与曲线各自日期；个人持仓/跟踪不并入此公共匹配源。

事件阅读沿用用户已定方案1：不同报告事件完全独立，即使ID相同也不能借作同一故事进展或跨run基金关联。只在同份研究内按明确事件ID、来源和证据关系去重，保留原runId、事件、来源、发生/发布时间与核验；未知发生时间不借其他日期。可用归档日期与历史链接只表达接口实际提供的当前安全成果/保留有效报告，不承诺全历史或跨日已核实故事；缺档、部分失败或错误关联需明确。未来稳定故事ID与可审计可撤销关联另立阶段，本轮不改DB、模型、Prompt或研究验收核心。

## 匹配与排序

只读接口为 `GET /api/v1/investment/daily-research/topic-fund-recommendations/{run_id}`。接口先验证当前有效成员及可见 INITIAL 验收记录，再读取同一研究时间的完整归档主题。手动研究遵守原租户可见性；不会借用另一轮成功报告的主题或私有原始材料。

每个主题展示最多三个独立的真实人民币场外产品。`matchLevel` 保留精选池／动态召回的来源标签，关联依据另按以下顺序评估：

1. `DIRECT_INDEX`：已核验的跟踪指数或 ETF 联接关系匹配主题检索词。
2. `CATEGORY_MATCH`：既有登记行业范围支持关联。
3. `NAME_CANDIDATE`：仅基金名称关键词匹配，持仓关联待核验。
4. `BROAD_FALLBACK`：可解释的宽基／大类资产间接观察，单独置于 `indirectFunds`，不计入直接推荐数量。

光模块／CPO、电网设备、低空经济、人形机器人、固态电池和创新药等叙事先映射为标准基金／指数词根，防止长标题挤占检索预算。指数关系证据优先于名称命中，不推断基金的具体持仓比例。

只有完全不存在前三类产品时才考虑间接观察；直接基金暂停申购不能成为推宽基的理由。国内细分产业不再默认套用沪深300；国内宏观政策支持须有明确语义。海外地域及债券利率敞口不得借用国内宽基或中国国债。

同一产品的 A/C/E/I/Y 份额按主干名归组，最多显示一种主力份额，其余作为附属份额展示。当前可申购份额优先，A 暂停时可选择 C；ETF、联接、发起式等标识保留，避免误并独立产品。只接纳既有主数据中 `FUND`／`LOF` 场外产品，场内 ETF 不冒充天天基金可申购品种。

优先显示有当前有效申购记录的产品。暂停、额度受限、状态未知或超过三日的记录不能当作正常开放；仍可保留相关真实基金及具体缺口。主库没有合适产品时返回原因，不编造基金代码或承诺必然有可申购品种。未知海外地域不会套用 A 股宽基。

全量主题先按直接推荐覆盖、明确关联事件的重要性、已核验来源数、关联可信程度、量化得分和风险核验完成度排序，原顺序作稳定末项；完整详情模式展示前十项及可展开的其余项，今日重点精选摘要最多3项，不改写历史目录的 ordinal。

主题按自身经济叙述分为 `POSITIVE_OPPORTUNITY`、`NEGATIVE_RISK`、`MIXED`、`MACRO_OBSERVATION`、`UNDETERMINED`，同时给出分类说明。这是确定性的文字信号分流，不是对经济结论真实性的认证。正向／混合主题须具备全部引用来源的唯一核验支持才进入直接推荐；纯负面主题只列 `relatedRiskFunds`，宏观和方向不明主题只列 `observationFunds`，不以基金数量凑正向机会。

对最终展示产品批量读取本地公开净值历史，沿用图表的来源选择、120 样本下限、连续性和新鲜度检查，支持原46只池子之外的产品。`pricePosition` 显示进入技术参考区间、中性观察、短期高位／防追高或净值数据待同步。高位优先于入场标签，技术区间不称为基本面低估或自动可买；无足够可信历史就不评分、不编价格。

## 归档缓存与部署

部署须先应用 migration **104**。原068基金名称 GIN trigram索引继续复用；104补充指数名称索引、候选缓存、RLS与授权、版本和目录变更失效机制。迁移器会读回验证这些约束。

NAS 升级、扩展权限、冷启动验收及耗时观测步骤见[机会推荐 NAS 部署检查](opportunity-nas-readiness.md)。

归档成功后，worker 在独立事务中预计算稳定的“主题→基金身份／关联依据”。匹配失败不回滚经济档案、不消耗模型调用；服务启动首轮即有界补建旧归档，按验收时钟优先处理最新周期，再处理旧周期积压。缓存按研究快照、摘要、验收时钟、算法版本、目录修订号和目录生效日校验，每主题至多24组、每组4种份额，整轮 JSON 不超过8MiB。租约120秒、最多8次退避重试，失败状态可读；API不能读租约token或写缓存。

页面 GET 不执行全量模糊匹配。缓存命中后仅按候选代码重验当前身份、申购状态，再拼接最终展示基金的本地净值；这些动态事实不写进稳定缓存。MISS 返回 `FUND_RECALL_PENDING`，重试耗尽返回 `FUND_RECALL_FAILED`。前端仅对明确的主题归档／匹配 pending 每3秒自动检查，最多10次，完成、失败、身份变化或收起面板时停止，保留手动检查入口。

候选已就绪但净值仍待同步时，卡片提示资料待补齐并提供手动重新检查入口。后台落库后需重新读取才显示新净值，不为 NAV 待同步新增自动轮询。

本地隔离 PostgreSQL 18.1 上，30,023 条基金主数据、72 个主题／75 个检索词的合成样本实测：匹配 SQL `EXPLAIN (ANALYZE, BUFFERS)` 从48,289.789ms降至634.484ms，结果同为1,755行；完整发现约884.96ms，稳定候选JSON约1.99MB。优化将主库名称、规范名称和指数名称匹配提前，再只对命中代码读取产品身份。以上不是 NAS 实机性能承诺。

## 风险与投资动作

风险检查不再阻断这条推荐链，三种标注与推荐基金并列展示：

- `VERIFIED_SAFE`：对应完整范围的五类核查及执行证据可核验，主题来源和范围匹配，且审核距当前不超过三日。文案为“风险核查已完成”，不承诺无风险。
- `RISK_ALERT`：存在关联行业负面记录或主题自身有负面经济信号，同时展示摘要及分歧。确认行业风险扣二十分，其他风险线索扣十分；既有量化行业扣分不会重复计算。
- `UNVERIFIED_RISK`：凭证缺失、延期、范围未解决或审核过期。基金匹配继续展示，缺口保留。

推荐基金与实时买入许可分开。此接口不生成虚构价格、不授予自动下单资格，也不改写历史正式报告。正式计划继续使用原有净值连续性、价格区间和交易限制保护。

## 审核预算与持久化

新分配优先使用冻结前真实可见的当日正向新闻行业，其次为服务器显式提供的真实持仓行业，剩余名额再处理历史风险和积压。最多十个行业、五十条查询；未排入的范围保留延期信息。单次模型随后新发现的主题直接进入上述推荐链，不增加模型调用或追加超预算搜索。旧冻结输入按原契约回放。

公共研究任务不读取个人持仓。其 `public_packet` 是共享材料，直接写入个人持仓行业或持仓优先原因会暴露偏好；因此 `holdingIndustryIds` 只作为分配器的显式输入接口，本轮未向共享任务接入私有持仓。

持久化验收投影保留逐项 `riskChecks` 的安全核验字段，经过数据库存储及再次投影后，完整证据不再退化为 `PENDING_PROOF`。重复或未知核查项不会通过裁剪被洗成完整核验。

原公共研究 NAV 采集保持 `RESEARCH_SELECTION_LIMIT=46` 成本边界；逐主题基金召回独立于该边界，最多七十二个主题、每主题三个展示品种。新的独立 NAV 后台服务扫描最近至多四轮有效候选缓存，按代码统一去重、复用本地可信历史并跳过冷却，实际供应商采集全局每轮至多24个产品，补齐原池外产品的本地历史；不会承诺一次覆盖全部主题产品。读取接口只查询本地数据库，不发起 AI 或基金供应商网络请求。
