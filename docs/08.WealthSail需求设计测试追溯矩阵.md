## 1. 使用规则

1. 新需求先在 PRD 分配唯一 ID，再进入本矩阵；
2. L0/L1 Must 至少有一个正常测试和一个异常/安全测试；
3. `PASS` 必须填写 run ID/报告链接、commit、环境、migration 和 fixture/model/provider 版本；
4. UI 原型测试通过只证明原型交互，不得把后端/系统用例改为通过；
5. 需求变更时同步更新设计章节、API/表、测试和兼容影响；
6. 需求退休保留行并标为 RETIRED，不复用 ID。

## 10. 当前实现边界

截至 v2.3 实现基线：

- `frontend/` 已按 `figma/v2-code` 与 `docs/09` 实现并连接 Domain API；`figma/v1-mobile` 已废弃，不能再作为当前实现边界或验收依据；
- `backend/` 已包含 FastAPI Domain API、认证/租户、组合/行情/报告/风险/Chat、Worker、Scheduler、Outbox、企业微信 Adapter，以及天天基金 ZIP 预览/确认、来源事实留存、持有期推断和官方净值异步物化；数据库采用受检的 001–021 schema migration，006/010 演示数据已移到 `seeds/dev/`；
- `frontend/` 已提供可恢复的“导入 / 更新持仓”向导、账户选择、逐项复核、空账户确认、批次历史和 READY/PENDING/PARTIAL/CONFLICT 区间指标展示；`VIEWER` 只读，缺值不展示为零；
- 本地自动化已有认证轮换、投影完整性、基金 14:30 确定性估值、报告证据、任务 lease、Outbox 收件人路由、企微适配、Chat 模型白名单、天天基金采集/包校验/确认/净值任务和前端错误态等回归。这些是代码回归证据，不自动等价于上表的系统验收 Run；
- 当前仍缺目标 Supabase 的 021 Migration/RLS readback、正式 Provider/企微/生产模型网关联调、TLS/备份恢复、性能/完整无障碍和 72 小时试运行证据，因此相关正式状态保持 `NOT_RUN`；本地空库迁移回读只能记入实现报告，不能冒充生产验收；
- 后续每次实施只更新具有 commit、环境、版本与原始报告的具体行，禁止把组件测试或 dry-run 批量换算为系统 `PASS`。
