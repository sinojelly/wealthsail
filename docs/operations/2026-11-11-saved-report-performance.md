## 三个已确认的耗时来源

1. **保存报告 GET 仍等待外部净值补齐。** 阅读已有成果被外部来源拖住，重试会再次经过同一链路。新的保存报告读取显式使用 `repair_nav=False`，只读本地历史和已保存的可信服务端曲线，不调用净值修复、外部报价或写入 RPC。持仓等原有显式补齐入口保留其行为。
2. **同一曲线在业务投影中反复完整复制。** 真实报告剖析记录约 1,498 万次 `deepcopy` 调用，主要发生在排名、风险处理与基金引用组装。剖析运行有额外开销，不能把剖析耗时当作普通请求耗时。现将读取副本中的完整 JSON 曲线转换为嵌套不可变容器，后续深复制直接安全复用它；业务价格、风险和轨道字段仍独立复制。叙事投影仅跳过这些新只读曲线，普通叙事及旧可变对象维持原合同。
3. **同一曲线在多个机会位置重复传输。** 新增可选 `chartFormat=shared-v1`：按完整曲线内容生成引用表，包含来源、时间、扩展元数据及全部点。前端在 API 边界恢复原内联形状。不同来源、时间、点顺序或数值绝不按基金代码混用；没有点数截断、机会数量上限或主题过滤。旧客户端默认内联格式保持兼容。

SQL 同时改为明确列投影。失败或未结束的最新执行仅传回展示所需的六类冻结输入，保留全部 46 只扫描基金及其审计、风险和申购信息；不重复传回无用历史和文档。最新执行若已成功，直接复用该行，不再重复读取同一份报告。历史列表使用独立窄查询，保留原时间边界和逐日选择逻辑。

当本地历史缺失时，仅复用满足当前服务端方法版本、基金身份、双轨道、完整输入窗口、最后净值及来源/观测时间一致性的保存曲线。它保留原观测时间与已披露日涨跌幅，不把旧数据伪装成新行情；不可信或缺失数据保持明确的不可用状态。

## 同一份生产报告的只读复测

在 NAS 现有 worker 镜像中启动短命 Python 进程，将本地变更仅加载到该进程；使用原 API 的租户上下文和同一份已保存报告。数据库事务为只读，禁止外部 HTTP 和净值补齐，并核验其调用次数为 **0**。输出仅含耗时、大小和数量，没有导出报告正文或用户身份。

## 浏览器等待与定位

保存报告读取上限统一为 **90 秒**；方向和指数依赖仍为 30 秒。该上限是慢网兜底，不增加 AI 运行时间，也不会启动研究或自动连串重试。慢读、取消、离线、后台刷新保留内容及手动只读重试维持原行为。

通过 `?perf=1` 启用的浏览器性能日志现在输出可读取的 JSON 字符串，包含脱敏路径、请求 ID、`headersMs/bodyMs/parseMs/durationMs/serverMs`；失败阶段区分 `HEADERS` 与 `BODY`。不记录查询参数、Token、响应正文或任意异常文本。结合服务端 `perf_stage`、`response.chart_compaction`、`response.chart_sharing` 和请求 ID，后续能区分服务器组装慢、正文下载慢与解析慢。

本地真实流式 HTTP 夹具验证：正文延迟约 35 秒仍可成功读取并显示完整机会；只有 GET，没有 POST。桌面及手机检查包含加载状态、9 个方向、12 个主题、基金价位和按需显示的图表，未发现溢出或页面错误。这是受控夹具测试，不是生产网速测试。
