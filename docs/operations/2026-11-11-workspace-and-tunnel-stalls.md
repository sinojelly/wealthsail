## 工作区占位是另一个阶段

“正在加载工作区…”来自路由的 React Suspense；机会页模块还未执行时，日报请求尚未发出。原机会页静态依赖包含 Recharts，即使图表尚不在可视区域，也会阻止页面模块完成加载。本地产物的页面静态闭包约1.19 MB，gzip约372 KB；Vite会预加载这些依赖，并非日报接口在这阶段串行等待。

本次将 `FundNavTrendChart` 原实现完整移入独立模块，原路径成为按需加载入口，等待与错误边界仅包住图表。这样正文、参考买卖点和数据请求可以先运行；图表仍保留全部点、周期、色带、来源与价格字段。变化后静态闭包约817 KB、gzip约263 KB，减少约109 KB压缩脚本，Recharts不再是工作区首屏的必要依赖。

该拆分减少工作区门控，不能保证网络链路停流时任意资源都能及时下载。图表有独立等待和错误边界；加载失败时正文与价位继续保留，按钮明确执行整页刷新，不把无法清除的React.lazy失败缓存伪装成局部重试。既有应用级过期构建恢复逻辑保持原行为：首次失败可能先自动刷新一次，其冷却内或不可用时由局部错误边界保住报告。

全部前端性能事件改为可读取的JSON字符串。静态资源事件增加 `queueMs/headersMs/bodyMs/encodedBytes/protocol`，仅记录同源 `/assets/` 文件名和封闭计时字段，丢弃query/hash；原导航、脚本就绪、会话及路由计时保留。

## 可回滚 HTTP/2 对照

新增 [compose.cloudflared.http2.yaml](../../external-access/compose.cloudflared.http2.yaml) 仅设置官方 `TUNNEL_TRANSPORT_PROTOCOL=http2`。Cloudflare 官方说明 `auto` 优先 QUIC，无法建立UDP连接时才退回 HTTP/2；“能建立但持续不稳”不等同于一定自动回退。[官方运行参数](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/run-parameters/#protocol)

NAS 已对现有项目、原2份配置文件和原2份环境文件做只读渲染验证：添加此overlay后仅传输变量变化，端口仍无公开映射，secret声明与其他配置完全一致。没有执行重建。

连接器同时承载 WealthSail 与 StudyOS，重建可能使两站短暂中断，因此生产切换单独等待用户授权。以下命令适用于NAS中已定义的 `WEALTH_ROOT`、`ACCESS_DIR`，必须保留当前实际使用的环境文件与storage overlay：

```bash
cf_base() {
  docker compose --env-file "$WEALTH_ROOT/deployment/nas.env" \
    --env-file "$ACCESS_DIR/.env" \
    -f "$ACCESS_DIR/compose.yaml" \
    -f "$ACCESS_DIR/compose.cloudflared.storage.yaml" "$@"
}
cf_base -f "$ACCESS_DIR/compose.cloudflared.http2.yaml" config --quiet
cf_base -f "$ACCESS_DIR/compose.cloudflared.http2.yaml" \
  up -d --no-deps --pull never cloudflared
```

切换前核对本地镜像与现运行镜像相同，避免把版本升级混入传输对照。复测同一浏览器的只读报告GET、工作区静态资源、健康连接与错误增量。该参数控制连接器到Cloudflare，既不改变Nginx到API的HTTP/1.1，也不改变浏览器到Cloudflare的HTTP版本。保留Access及连接器侧验证。

若没有改善或出现回归，使用相同基础文件移除可选overlay即可回滚：

```bash
cf_base up -d --no-deps --pull never cloudflared
```
