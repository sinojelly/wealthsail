# AI 用量跟踪与运维展示设计

## 需求与默认选型

AI 用量放在「运维监控」的「AI 用量」标签页，与作业运行、审计日志并列。这是本次实现的默认选型，不是等待用户审批的提案。页面内容区采用浅底、深色文字、明确边框和带文字的高对比状态色；保留全站导航的现有主题。

运维人员需要知道当前服务端 Codex 账户、会员类型及可观测额度，查看历史任务的整体消耗，并展开一次任务内多次模型推理。推理成功与业务成功必须分开：模型返回成功后仍可能因校验、业务保存或通知失败导致任务失败。失败记录具有故障定位价值，不能自动认定为模型消耗；没有模型调用的任务应显示「未调用」。

现有 `intraday_tracking` 每五分钟核对真实持仓与已有行情：单标的绝对涨跌幅达到 3%，或组合绝对涨跌幅达到 2% 才生成波动提醒，同一目标 30 分钟去重；没有触发时跳过且不调用 AI。它用于发现盘中异常波动，不是持续跟踪基金买卖点的同义任务。`DataError` 代表运行错误类别，失败行保留排错价值，但重复错误需要修复根因，不能当作有用的投资结论。

## 范围与权限

- 只读取当前服务器已配置的 Codex 账户；不从浏览器读取凭据，不向前端返回密钥、认证文件、提示词或模型正文。
- 平台管理员可查看共享账户状态和公共研究任务；租户运维只查看本租户任务，账户卡显示权限受限。接口必须在服务端执行权限过滤。
- 从功能启用后采集，旧历史没有采集数据时不虚构回填。外部 Codex 会话的调用无法由本系统完整归因。
- 本功能用于观测，不自动推理、充值、变更账户或下单。读取账户失败不阻断原业务执行。

## 采集与数据口径

一次业务执行对应一个任务；其内每次真实模型调用对应一条推理记录。任务记录类型、可读名称、起止时间、业务结果；推理记录模型、调用类型、起止时间、成功/失败/执行中/结果不确定、脱敏错误类别及供应商返回的 token。任务成功不等于推理成功；重试中一次失败、一次成功时，任务推理状态为「部分成功」。中断未得到最终响应应标记不确定，不能伪装成功。

Token 包括输入、缓存输入、输出及总量。缓存输入是输入的子集，不可重复相加；总量采用供应商总量或输入加输出，缺失不推算成零。任务聚合任一调用缺失的字段显示未知，避免展示不完整的精确总数。

每次推理前后分别采集独立的新鲜账户额度快照，以同账户、同额度窗口与同重置周期的剩余额度差估算消耗。
采样绕过页面缓存及页面正在进行的账户读取，要求 READY、有效的独立观测标识和观测时间。前后时间相同、
观测标识相同、过期或历史快照不用于估算。窗口百分比使用「百分点」，credits 使用供应商原单位，均不是
人民币金额。多窗口独立显示，不能相加；只有两次有效独立采样的百分比未发生可见变化时，才可显示该精度下为零。

下列情况不生成负数、跨周期或虚假的用量：余额上升（重置或充值）、跨月/重置时间变化、账户变更、缺少任一快照、未知余额、非有限数、超出 0–100 的百分比。可能与系统内并发调用重叠时标注无法归因；系统外并发可能影响估算，界面持续提示这一限制。任务聚合必须保留无效或缺失原因，不把未知调用按零合计。

## API 合同

`GET /v1/operations/ai-usage?limit=20&offset=0` 沿用 Domain API 的 `data` / `meta` envelope。返回 `account`、`tasks`、`total`、`limit`、`offset`、`limitations`。任务默认开始时间倒序，每页 20 个任务，其下包含调用详情。账户读取应有短时缓存和超时保护，页面仅在进入该标签页后读取，可手动刷新。

同一受保护接口增加 `view=tasks|account|all`，默认 `all` 兼容原调用。前端任务查询使用 `view=tasks`，
仅返回任务、分页和 limitations，完全不读取 Codex 账户；账户查询使用 `view=account`，仅返回 `account`，
不扫描任务表。`refresh_account=true` 请求重新采集账户元数据，仍受权限、并发合并和失败冷却控制；
不能借此触发推理、修改认证或绕过平台管理员检查。所有视图仍先校验租户 OWNER / ADMIN，读取账户还需
有效的 PLATFORM_ADMIN；任务查询继续使用租户事务与原有 RLS。

- `account`：`status`（READY / STALE / UNAVAILABLE / UNAUTHENTICATED / NOT_CONFIGURED / RESTRICTED）、`provider`、仅平台管理员可见的账户 `email`、`planType`、`authType`、`observedAt`、额度 `windows`、可选 `credits` 与 `limitations`。窗口含 key、label、usedPercent、remainingPercent、windowMinutes、resetsAt（Unix 秒）。供应商未公开余额时为 null，页面显示未知。STALE 保留最后一次成功的 observedAt，并附 ACCOUNT_STALE，不把失败发生时间冒充成功观测时间。
- `tasks`：id、taskType、taskName、startedAt、finishedAt、inferenceStatus、businessStatus、models、callCount、inputTokens、cachedTokens、outputTokens、totalTokens、quota、calls。
- `calls`：id、model、callType、startedAt、finishedAt、status、errorClass、四类 token 和 quota；不含提示词、正文和认证信息。
- `quota.windows`：key、label、consumedPercent、status；`quota.credits`：consumed、status。状态包括 ESTIMATED、UNKNOWN、RESET_OR_TOPUP、PERIOD_CHANGED、ACCOUNT_CHANGED、CONCURRENT、INCOMPLETE，界面显示中文解释。

## 展示与交互

顶部基金估值卡、作业成功率、最近作业耗时、净值快照新鲜度、消息待投递和脱敏说明是所有标签共享的
运维概览。切换「作业运行 / 审计日志 / AI 用量」只切换下方详情，概览及基金估值操作始终保留；
AI 用量加载、失败或重试期间也不隐藏概览。AI 用量仍在进入该标签后才读取，两个刷新操作各自独立。

账户区显示账户状态、会员/认证方式、额度窗口剩余百分比和下次重置时间、credits 余额与观测时间；未知、未配置、未登录和受限分别解释。历史列表一行一个任务，展示任务类型/名称、北京时间、推理与业务两种结果、模型、调用次数、输入/缓存/输出/总 token、估算用量。展开后显示每次调用及失败类别，可观察重试成本。

提供刷新、上/下一页、加载、加载失败重试和空状态；分页按任务，禁止把调用拆到另一页。所有运维时间明确使用 Asia/Shanghai，避免 UTC 直接截字符串造成八小时时差。移动端允许数据表局部横向滚动，页级内容不得溢出；账户卡和操作按钮换行。

任务列表约每 30 秒刷新，账户约每 180 秒刷新，分页不会重新采集账户。手动刷新同时重新读取任务并请求
采集账户，两者独立显示加载与错误。READY 代表最近成功观测，可能来自 180 秒缓存，不能称作实时余额；
STALE 明确显示「历史快照」及「最后成功观测时间」。账户读取失败不隐藏任务列表，也不清空已知历史快照。
认证失效、权限受限或运行账户改变时，不沿用旧身份的余额。浏览器缓存按租户和用户隔离；切换身份后
晚到的旧请求只能更新原身份缓存，不能污染新用户页面。

## 账户缓存、新鲜采样与诊断（2026-10-28）

共享账户缓存位于 Codex Runner 进程，API/Worker 不各自设置第二个 180 秒 TTL，避免重新认证失效被
另一层缓存遮蔽。成功 TTL 为 180 秒；同代认证的并发元数据请求合并为一次采集，一个等待者取消不取消
其他等待者的读取。失败冷却为 20 秒，冷却期间不重复启动 App Server；有成功快照则返回 STALE，否则
返回明确的不可用状态。显式手动刷新跳过成功 TTL，但合并正在执行的读取并遵守失败冷却，不自动重试。

账户 RPC 成功但额度 RPC 单独失败，也不将本次缺失窗口当作 180 秒的完整成功值。同身份已有完整历史时
返回旧 STALE，保留原观测时间和额度，20 秒后可重试；首次只有部分账户信息时保留真实已知字段，额度
保持未知并使用短冷却。独立推理采样仍只得到本次缺失的额度，不能借用历史窗口。身份改变或无法确认
一致时优先清除旧身份，完整读取恢复后才重新进入成功 TTL。

Runner 只检查认证文件的 stat 元数据来识别登录、退出、替换和重新认证，不读取或记录认证文件内容。
认证代际变化即清空成功值、冷却与旧请求引用，旧代未完成读取不能回写新代。明确未认证会移除旧账户。
已知认证已变更但新读取失败时，用 `ACCOUNT_AUTH_CHANGED` 明确通知调用端清除旧身份；前端和传输层
不得将这种失败当作普通网络故障继续回退旧快照。明确身份失效后再次传输失败，仍保持失效语义直到
获取新的成功观测，不得重新显示旧身份。
同代成功读取发现账户身份改变也切换代际。显式本地 CLI 模式使用同等进程内策略；NAS 的认证目录仍只
挂载给 Runner，API/Worker 不获得认证文件访问权。

API/Worker 传输失败时可保留最后已知的 Runner 成功值，但只作为 STALE 历史值，下一次普通查询仍联系
Runner，不新增长期缓存。更换 Runner 地址/内部凭据或收到明确身份变化后丢弃旧值。Runner 完全失联时，
调用端无法即时获知它刚发生的外部重新登录；此时页面只展示带旧观测时间的历史信息，不保证当前账户身份。
缓存为进程内数据，重启不会恢复旧快照，多个 Runner 副本各有缓存，本版本不引入共享数据库或 Redis。

推理前后使用受内部认证保护的 `fresh=true` 路径，每次单独读取 App Server，既不共享页面缓存，也不共享
页面正在进行的采集；失败不回退到历史额度。独立观测 ID、认证代际和账户指纹仅在内部归因使用，不进入
浏览器账户 DTO。单次 App Server 读取上限 15 秒，内部 HTTP 上限 23 秒、客户端整体上限 25 秒，tracker
单次上限 26 秒、前后采集总预算 52 秒（不含模型执行和既有持久化步骤）；没有额外自动重试。账户读取
子进程的退出/强制清理亦有短预算，避免清理将 15 秒读取拖成另一轮长等待。

额度缺失、窗口重置、跨周期、认证变化和并发无法归因时保留 UNKNOWN 或具体不可估算原因，consumed
为 null。Token 只使用真实推理返回数据，与额度快照是否成功无关；采样超时、取消或余额未知不能抹掉
已获得的 Token，也不能把未知用量写成零。

诊断只记录固定阶段、异常类别与耗时：App Server spawn、initialize、account_read、rate_limits_read、
cleanup、snapshot，缓存 cache_fetch，客户端 transport，API operations_api，以及 tracker before/after。
不记录异常原文、邮箱、Token、认证路径/文件内容、HTTP 头或原始供应商响应。`observedAt` 属于用户界面
数据，保持成功观测时刻；错误耗时用于定位读取/传输/额度窗口/清理阶段。元数据检查仅使用账户 RPC，
不创建模型 thread/turn，不占每日研究执行槽位。

## TDD 实施与验证计划

1. 先写失败测试覆盖账户读取、任务/调用记录、额度差值边界及权限隔离，再完成后端采集和 API。
2. 前端先以接口边界替身编写失败测试：懒加载入口、聚合与展开、推理/业务区分、未知数据、异常额度说明、分页刷新、错误重试、北京时间；再实现页面。
3. 运行相关测试的 RED/GREEN，随后执行后端与前端完整测试、类型检查、Lint 和构建；不触发真实付费推理。
4. 使用本地 mock API 在桌面和手机视口验证浅色可读性、详情展开、翻页和错误状态，保留仓库外截图证据。真实 NAS 账户额度及外部并发仍需部署后观察验证。
5. 按功能拆分本地提交；提交前检查差异和脱敏，保留用户已有改动，不推送、不部署。

## 上线条件与限制

首次启用 AI 用量账本需要已有 `091_ai_usage.sql`。本次缓存、刷新解耦和采样改造不增加数据库迁移；观测
元数据沿用既有 JSON 字段，无需执行生产 SQL。重新构建后端共享镜像和前端镜像，并重建 `codex-runner`、
`api`、`worker`、`frontend` 四个服务，保持采集、内部 DTO 与页面同版本。只更新前端不会修复后台采样；
数据库未升级时页面仍明确提示初始化未完成，不将空列表解释为历史消耗为零。

平台管理员通过服务端角色检查后才能查看共享 Codex 账户与公共研究任务；租户 OWNER / ADMIN 只读本租户任务，账户详情受限。数据库策略与 API 过滤共同执行该边界。历史仅从启用采集后开始，不回填旧任务；额度估算依赖供应商提供快照，缺失和不可靠归因均保留未知状态。

正常异常、超时和流式取消会完成终态记录；进程硬杀或宿主崩溃可能来不及执行收尾，保留 `RUNNING` 与未完成的时间。此类记录不能据此认定推理仍在执行或消耗为零，需要结合 Worker / Runner 存活状态核查，当前版本不自动猜测其终态。
