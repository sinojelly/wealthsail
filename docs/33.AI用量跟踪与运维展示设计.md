# AI 用量跟踪与运维展示设计

## 需求与默认选型

AI 用量放在「运维监控」的「AI 用量」标签页，与作业运行、审计日志并列。这是本次实现的默认选型，不是等待用户审批的提案。页面内容区采用浅底、深色文字、明确边框和带文字的高对比状态色；保留全站导航的现有主题。

运维人员需要知道当前服务端 Codex 账户、会员类型及可观测额度，查看历史任务的整体消耗，并展开一次任务内多次模型推理。推理成功与业务成功必须分开：模型返回成功后仍可能因校验、业务保存或通知失败导致任务失败。失败记录具有故障定位价值，不能自动认定为模型消耗；没有模型调用的任务应显示「未调用」。

现有 `intraday_tracking` 每五分钟核对真实持仓与已有行情：单标的绝对涨跌幅达到 3%，或组合绝对涨跌幅达到 2% 才生成波动提醒，同一目标 30 分钟去重；没有触发时跳过且不调用 AI。它用于发现盘中异常波动，不是持续跟踪基金买卖点的同义任务。`DataError` 代表运行错误类别，失败行保留排错价值，但重复错误需要修复根因，不能当作有用的投资结论。

## 范围与权限

- 只读取当前服务器已配置的 Codex 账户；不从浏览器读取凭据，不向前端返回密钥、认证文件、提示词或模型正文。
- 平台管理员可查看共享账户状态和公共研究任务；租户运维只查看本租户任务，账户卡显示权限受限。接口必须在服务端执行权限过滤。
- 从功能启用后采集，旧历史没有采集数据时不虚构回填。外部 Codex 会话的调用无法由本系统完整归因。
- 本功能用于观测，不自动推理、充值、变更账户或下单。读取账户失败不阻断原业务执行。

## 采集与数据口径

一次业务执行对应一个任务；其内每次真实模型调用对应一条推理记录。任务记录类型、可读名称、起止时间、业务结果；推理记录模型、调用类型、起止时间、成功/失败/执行中/结果不确定、脱敏错误类别及供应商返回的 token。任务成功不等于推理成功；重试中一次失败、一次成功时，任务推理状态为「部分成功」。中断未得到最终响应应标记不确定，不能伪装成功。

Token 包括输入、缓存输入、输出及总量。缓存输入是输入的子集，不可重复相加；总量采用供应商总量或输入加输出，缺失不推算成零。任务聚合任一调用缺失的字段显示未知，避免展示不完整的精确总数。

每次推理前后采集账户额度快照，以同账户、同额度窗口与同重置周期的剩余额度差估算消耗。窗口百分比使用「百分点」，credits 使用供应商原单位，均不是人民币金额。多窗口独立显示，不能相加；百分比未发生可见变化只表示该快照精度下为零。

下列情况不生成负数、跨周期或虚假的用量：余额上升（重置或充值）、跨月/重置时间变化、账户变更、缺少任一快照、未知余额、非有限数、超出 0–100 的百分比。可能与系统内并发调用重叠时标注无法归因；系统外并发可能影响估算，界面持续提示这一限制。任务聚合必须保留无效或缺失原因，不把未知调用按零合计。

## API 合同

`GET /v1/operations/ai-usage?limit=20&offset=0` 沿用 Domain API 的 `data` / `meta` envelope。返回 `account`、`tasks`、`total`、`limit`、`offset`、`limitations`。任务默认开始时间倒序，每页 20 个任务，其下包含调用详情。账户读取应有短时缓存和超时保护，页面仅在进入该标签页后读取，可手动刷新。

- `account`：`status`（READY / UNAVAILABLE / UNAUTHENTICATED / NOT_CONFIGURED / RESTRICTED）、`provider`、仅平台管理员可见的账户 `email`、`planType`、`authType`、`observedAt`、额度 `windows`、可选 `credits` 与 `limitations`。窗口含 key、label、usedPercent、remainingPercent、windowMinutes、resetsAt（Unix 秒）。供应商未公开余额时为 null，页面显示未知。
- `tasks`：id、taskType、taskName、startedAt、finishedAt、inferenceStatus、businessStatus、models、callCount、inputTokens、cachedTokens、outputTokens、totalTokens、quota、calls。
- `calls`：id、model、callType、startedAt、finishedAt、status、errorClass、四类 token 和 quota；不含提示词、正文和认证信息。
- `quota.windows`：key、label、consumedPercent、status；`quota.credits`：consumed、status。状态包括 ESTIMATED、UNKNOWN、RESET_OR_TOPUP、PERIOD_CHANGED、ACCOUNT_CHANGED、CONCURRENT、INCOMPLETE，界面显示中文解释。

## 展示与交互

顶部基金估值卡、作业成功率、最近作业耗时、净值快照新鲜度、消息待投递和脱敏说明是所有标签共享的
运维概览。切换「作业运行 / 审计日志 / AI 用量」只切换下方详情，概览及基金估值操作始终保留；
AI 用量加载、失败或重试期间也不隐藏概览。AI 用量仍在进入该标签后才读取，两个刷新操作各自独立。

账户区显示账户状态、会员/认证方式、额度窗口剩余百分比和下次重置时间、credits 余额与观测时间；未知、未配置、未登录和受限分别解释。历史列表一行一个任务，展示任务类型/名称、北京时间、推理与业务两种结果、模型、调用次数、输入/缓存/输出/总 token、估算用量。展开后显示每次调用及失败类别，可观察重试成本。

提供刷新、上/下一页、加载、加载失败重试和空状态；分页按任务，禁止把调用拆到另一页。所有运维时间明确使用 Asia/Shanghai，避免 UTC 直接截字符串造成八小时时差。移动端允许数据表局部横向滚动，页级内容不得溢出；账户卡和操作按钮换行。

## TDD 实施与验证计划

1. 先写失败测试覆盖账户读取、任务/调用记录、额度差值边界及权限隔离，再完成后端采集和 API。
2. 前端先以接口边界替身编写失败测试：懒加载入口、聚合与展开、推理/业务区分、未知数据、异常额度说明、分页刷新、错误重试、北京时间；再实现页面。
3. 运行相关测试的 RED/GREEN，随后执行后端与前端完整测试、类型检查、Lint 和构建；不触发真实付费推理。
4. 使用本地 mock API 在桌面和手机视口验证浅色可读性、详情展开、翻页和错误状态，保留仓库外截图证据。真实 NAS 账户额度及外部并发仍需部署后观察验证。
5. 按功能拆分本地提交；提交前检查差异和脱敏，保留用户已有改动，不推送、不部署。

## 上线条件与限制

上线时先应用 `091_ai_usage.sql` 数据库迁移，再更新并重启 API、Worker 和 Codex Runner，确保业务任务入口、推理采集和账户 RPC 使用同一版本。只更新前端不会补出用量记录；数据库未升级时页面明确提示初始化未完成，不将空列表解释为历史消耗为零。

平台管理员通过服务端角色检查后才能查看共享 Codex 账户与公共研究任务；租户 OWNER / ADMIN 只读本租户任务，账户详情受限。数据库策略与 API 过滤共同执行该边界。历史仅从启用采集后开始，不回填旧任务；额度估算依赖供应商提供快照，缺失和不可靠归因均保留未知状态。

正常异常、超时和流式取消会完成终态记录；进程硬杀或宿主崩溃可能来不及执行收尾，保留 `RUNNING` 与未完成的时间。此类记录不能据此认定推理仍在执行或消耗为零，需要结合 Worker / Runner 存活状态核查，当前版本不自动猜测其终态。
