## 每日流程与单次消费

所有时刻使用Asia/Shanghai。API、Worker及NAS系统时间需要一致；计划时间不证明后台在线。

| 时点/任务 | 当前行为与边界 |
| --- | --- |
| 08:30公开采集 | 有界读取公开宏观、新闻、赔率、发射计划和主题基金确认NAV，写入market.alpha_public_batches；每天一个持久采集槽。迟启动可消费当天尚未使用的槽，重启不重复请求当日源。 |
| 08:30公共日报 | 沿用每日Codex唯一槽，读取最新可见公共包和真实程序价格锚点。成功READY后，配置完整的机会用户可向指定群发送当日日报摘要与关注计划；旧READY保留原日期，不冒充今日补发。 |
| 交易日14:30 | 在[14:30,15:00)内对指定用户启用跟踪的冻结场外计划及当日日报中有明确映射的场外计划核对一次。只取已核验身份对应代码的当日估值；无真实交易日历事实时不按星期推断。采集完成后再次检查时钟，跨15:00则EXPIRED，不发盘中操作提醒。 |
| 14:30汇总 | 最多一条Markdown，区分入场闭区间、冻结止损、T1、区间外及数据未知；估算NAV不是最终成交净值，用户自行决定并提交申赎。价格不匹配时不借指数或其他基金代替。 |
| 确认NAV表现 | 18:00后检查当日、次晨补最近明确交易日的确认NAV；数据未发布时不提前占用确认槽。有数据后按原冻结版本计算MFE/MAE，部分标的缺报继续显示缺口。 |
| 既有15分钟检查 | 场外基金的价位计划退出15分钟价格轮询；普通宏观研究和其他资产用途保留。机会服务的60秒唤醒只检查时钟/数据库，不每分钟向基金供应商取价。 |

公开采集、日报模型及机会提醒各自使用持久唯一槽。机会槽在估值/外发之前提交claim；失败、取消、超时或外发结果未知均永久消费，不自动重发、不换通道，也不通过删除数据库标记“补一次”。这一取舍避免重复消息，不承诺恰好送达。旧宏观/官方证据队列的租约与重试机制仍按各自规则运行，不能套用于新机会槽。

MFE/MAE以冻结currentPrice/asOf为不变基准，只使用同标的、同口径、同单位的确认价格，分别表示最大有利/不利变化百分数，**不是实际成交盈利**。估算NAV不进入指标；更新不会把基准挪到新行情或当日模型计划。旧收益指数若无真实同点close/unitNav配对，14:30转换为UNKNOWN；确认表现缺同口径历史时也保留缺口。

## 页面刷新与真实输入

浏览器刷新、筛选、分页、切标签、开图及API的GET只读数据库，不现场抓供应商或新派发模型。显式刷新命令只进入既有耐久后台队列，仍需要消费者；保存跟踪/复盘不会新增模型会话。NOT_COLLECTED、未知或0个样本不表示经济数值为零。

| 数据 | 来源及必须保留的定义 |
| --- | --- |

各源保留观察期、公布时刻（未知为null）、抓取/可得时刻、单位、定义和限制。每项指标分别保留有界最新历史，不用总数组截尾把某整类指标裁掉；未来观察不能进入当前研究。公开补抓不认证历史PIT，抓取时刻不填作当时公布时刻。单源403、429、451、超时、许可或字段变化不认证成功，也不使其他源连带失效。

图谱中的产品代码/名称核验与当前持仓核验分开。主动基金仅为主题研究候选，未有最新持仓披露就不声称“当前重仓”或给出比例。主题关系不自动建立任意指数映射。QDII如161129按设计28第27节，以完整来源证明的真实披露NAV生成研究区间，标为LATEST_DISCLOSED_NAV并说明跨市场延迟；它不是当日估值，14:30仍需当日同基金估值。缺证明或过期时才说明相应缺口。

境内基金的NAV日历假设为：18:00前以此前日历日为核对截止，18:00后包含当日，再从已存逐日事实中寻找应有交易日；不是按周一至周五猜测。缺日历、缺应有净值或日历冲突时保留真实历史价格/指标，清空依赖“当前有效”的入场、止损与目标，并显示具体原因。

## 自动发现与方向跟踪

当前prompt v5采用量化＋催化双引擎，目标6—8方向、每方向1—2基金。程序quantitativeScan逐只列出实际技术状态、当前是否进入区间和距离；媒体快讯的UNVERIFIED只表示没有二次官网核对，不能据此降研究优先级。七行业＋OTHER索引均衡提供真实快讯，一个媒体线索加同基金真实量化证据即可研究；纯技术方向必须实际触发相应条件，不编新闻。

087将明确代表池扩至21只，详细名码和官方资料见[087配置](../migrations/087_core_fund_coverage.sql)。每次正式研究前检查核心池，当日alpha槽已消费也补查；调试采集共用准备步骤。近730天有界补抓、保留末500实际点，220点为覆盖目标，至少20点可计算参考。成功历史追加fund_research_nav_histories；同日新鲜且已确认完整的短历史可复用，仍显示实际点数和SHORT_HISTORY，不反复补造。

主适配完整分页后生成providerHistoryProof，AKShare单位净值备源在独立子进程硬超时执行；LOF只取单位净值，绝不取场内成交价代替。QDII证明须绑定本基金、查询截止、真实样本摘要和抓取时间，最近披露参考与已核海外日历分开。API读公共包/缓存不直接采集或执行模型；旧失败/已消费槽不删除，原冻结价位不重算。

五主题图谱是种子，不限定发现范围。目录中已核验指数关系、主题种子与共享研究身份进入有界候选；净值每轮最多32只、总网络预算240秒，超预算保留已采数据并标明BUDGET_EXHAUSTED，不声称逐日覆盖全部基金历史。

086新增reference.discovery_fund_universe，提供16只经基金公司官网核验的跨行业代表身份，详细来源和核验日期随[迁移086](../migrations/086_discovery_fund_universe.sql)保存。AI、资源、券商、机器人、医药、消费、黄金和海外能源科技等各行业先取代表，再补充目录候选，至少预留8个目录扩展席位（实际不足则由其他候选补足）。旧五主题及其芯片等产品继续合并；不是只有这16只可研究。代表分类不证明主动基金当期持仓，也不创建未经核验的指数关系。

评审示例中的错配不入库：008086按实际5G通信联接分类，嘉实主要消费用009179；020988和001556不作为文章所称科创芯片/人工智能基金播种。新池的QDII要求在统一日历入口重验，包含手动刷新的历史缓存；禁用采集也不把海外基金改成只需境内日历。公共输入discoveryCoverage记录候选数、所选代码、实际有历史/有价格的代码及行业，便于检查覆盖，不把选择名额当采集成功数。

前阶段prompt v4先综合同链资金意向、经营景气、政策/会议和技术位置，目标4—6个独立方向（当前v5已扩为6—8）。提议可提供积极催化，阶段与兑现条件准确说明；缺价格可输出WATCH，已有价格仍由程序决定。方向的catalysts/risks有当前来源，随后一起冻结；首屏一套价格表，算法和综合依据按需展开。

valueDirections引用多项真实新闻/宏观及服务器价格锚点，模型不自报价格。方向卡片逐基金一键保存，DAILY_DIRECTION仅提交报告、方向、标的与轨道身份。服务器冻结原日报逻辑、多来源和价位，同方向/基金/轨道跨报告幂等，不覆盖原版本。新闻无创建跟踪入口；旧记录仍可读。复盘使用DISCOVERY:<key>命名空间，原始私人文字不进入公共包。

084的代码+市场产品指数关系支持主数据已存在但无UUID的沪深300联接产品。TRACKS/ETF_LINK有官方资料和有效期；主动基金BENCHMARK、过期/未来核验、同码异市场不冒充跟踪。缺行情仍可显示真实候选身份，不能显示虚构买卖点。

## NAS配置与用户作用域

运行新增迁移084后启动受限Worker/macro_worker。新配置应写入实际后台使用的环境文件；Webhook key只在后台环境，不能放进前端、API环境、响应、日志或Git。示例中的占位符必须替换为自己的值：

~~~dotenv
ALPHA_PUBLIC_ENABLED=true
DAILY_RESEARCH_ENABLED=true
ALPHA_OPPORTUNITY_ENABLED=true
WECOM_OPPORTUNITY_WEBHOOK_URL=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=<自己的机器人key>
OPPORTUNITY_TENANT_ID=<自己的活动租户UUID>
OPPORTUNITY_USER_ID=<自己的用户UUID>
~~~

ALPHA_PUBLIC_ENABLED和ALPHA_OPPORTUNITY_ENABLED默认开启，但没有完整、有效的tenant/user scope或不属于ACTIVE成员时，私有机会任务关闭。没有Webhook URL不发送群消息。DAILY_RESEARCH_ENABLED生产需明确启用；Windows启动器原有默认开启。Codex由运行后台的同一系统用户登录，仍支持DAILY_RESEARCH_CODEX_PATH和DAILY_RESEARCH_MODEL，不改用额外模型会话补验收。

登录自己的应用后，可从现有GET /api/v1/auth/me响应的data.profile.id取得用户ID、data.activeTenantId取得活动租户ID，并核对data.tenants中对应成员状态为ACTIVE。不要复制其他用户ID或用全库查询代替当前身份核对。群提醒只取这个作用域的启用研究标的与程序价位；原始私人reason/lessons、账户、持仓和成本不进入群消息或公共包。

083增加主题图谱、公共采集包、actor规则、机会槽和确认表现表。规则/表现读取保持actor RLS；为核验实际已实现成交，仅给Worker必要的ledger.trade_fills与identity.account_members列级SELECT，不新增账本写权限。这些私有读取不把原始笔记或成交明细传给公共模型。校准包只含许可的固定类别模板、聚合计数及统计口径；判断支持率与实际已实现盈利胜率分别表示，缺可核验成交样本时盈利胜率保持null。

NAS需保持后台在线及上海时区。两类Worker若同时存在，持久唯一槽仍防重复消费；不要额外用cron重复调用来规避当日失败记录。原WebSocket实验、单聊outbox和旧报告通道保持各自边界，新群Webhook不作未知结果的替代发送通道。

## Windows载入新代码与既有采集

一键启动使用.local/macro.env供独立后台读取。重启时保留已有五项Phase 2配置（ALPHA_PUBLIC_ENABLED、ALPHA_OPPORTUNITY_ENABLED、Webhook URL、tenant/user）；当前进程环境的同名设置优先。因此修改后仍需重启自己的后台，浏览器刷新不会更新API/Worker代码。DAILY_RESEARCH_ENABLED沿用启动器环境/default逻辑，需要关闭时在启动环境明确设置。

先确认是自己的实例，再按[运行手册26](26.Windows-local-development.md)操作：

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1 -Action Status
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1 -Action Stop
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1 -SkipInstall
~~~

启动器按现有逻辑执行迁移及检查；本轮需要084。生产静态前端另需构建。-SkipMacro可读取已有事实，但不会运行独立宏观/日报消费者，也不会自动填空库。

既有四指标保留启动缺口检查、每日06:30常规更新和不完整后一小时重试；官方证据、指数研究保留原启动与耐久队列规则。需手动补抓既有宏观时可使用start-local.ps1 -Action RefreshMacro；只更新指数可在受限Worker环境运行python -m backend.jobs.index_research --once。这些命令不代表所有来源成功，需分别检查顶层coverage及各源status/sourceResults；不重置机会槽、不执行交易。

日志可用Get-Content .local\logs\macro.stderr.log -Tail 80查看；先核对目标实例、087迁移、日历、启用配置与作用域，再看具体源异常。凭据及带key的Webhook URL不应出现在日志。

## 本地验证与证据记录

本地启动器默认设置DAILY_RESEARCH_AUDIT_DIR=.local/research-audit，保存公开模型原始输出、来源核对及最终校验诊断；自定义路径或显式空值在重启后保留。按run UUID查找JSON，诊断不是READY日报，失败状态仍以数据库为准。配置默认值、2MB限制和隐私边界见设计28第29节；普通日志只记异常类型，勿将诊断目录提交Git。
