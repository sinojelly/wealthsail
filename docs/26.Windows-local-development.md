# Windows 本地编译运行与测试账号

本文适用于在 Windows 打开 WealthSail 网页、用测试账号体验交互的场景。
入口是仓库根目录的 `start-local.ps1`，运行真实 FastAPI、前端生产构建及独立本地数据库。

## 1. 没有 PostgreSQL，也不安装 Docker，能运行吗？

**可以。一键脚本直接启动便携 PostgreSQL，无需 Docker，也无需安装 Windows 数据库服务。**

脚本优先使用 `.local/postgres/pgsql/bin` 中的 PostgreSQL；也可以用 `-PostgresBin` 指定已经下载并解压的 `bin` 目录。
没有可用程序时，脚本下载官方 EDB PostgreSQL **16.10 Windows x64** 二进制压缩包，只解压 `bin`、`lib`、`share`，成功后删除下载包，避免保留完整安装器、pgAdmin 等组件。

数据库仍是 PostgreSQL，数据保存在项目目录 `.local/pgdata`。
当前后端依赖 `asyncpg`、PostgreSQL schema、RLS 和数据库角色，不能直接替换成 SQLite。
前端测试 fixture 只供测试使用，`pnpm dev` 不会自动启用假数据，`AUTH_DEV_MODE=true` 也不能绕过密码验证。

不需要配置 Supabase、创建根目录 `.env`，也不需要模型或企业微信密钥。

## 2. 一次性准备与磁盘空间

准备以下工具，安装后重新打开 PowerShell，让 PATH 生效：

| 工具 | 要求 | 检查命令 |
| --- | --- | --- |
| Windows PowerShell | 5.1 或 PowerShell 7 | `$PSVersionTable.PSVersion` |
| Python | **3.12**，安装时启用 Python launcher 或加入 PATH | `py -3.12 --version` |
| Node.js | **22.12 以上**，推荐 22 或 24 | `node --version` |
| pnpm | 建议 10；锁文件使用 lockfileVersion 9 | `pnpm.cmd --version` |

下载入口：[Python Windows](https://www.python.org/downloads/windows/)、[Node.js](https://nodejs.org/en/download/)。

安装 pnpm：

~~~powershell
npm.cmd install --global pnpm@10
~~~

首次自动准备 PostgreSQL 需要下载约 **322 MB** 的压缩包；下载、解压、初始化数据库期间还需要额外可用空间。
Python/Node 依赖也会占用空间，不能仅按压缩包大小估算全部需求。
脚本把 PostgreSQL、数据库、临时文件、日志及新环境缓存放在项目所在盘；建议把仓库放在有空间的 D 盘等数据盘。
已有 `node_modules` 时复用既有 pnpm store，避免再创建第二份依赖；既有 store 仍位于原来的存储盘。

已有兼容的 `.venv` 会被优先复用；只有没有可用 Python 3.12 虚拟环境时才创建 `.venv-local`，避免重复安装一份依赖。
前后端依赖已经安装完成时，用 `-SkipInstall` 跳过依赖安装，仍会重新编译前端和执行迁移。
已有便携 PostgreSQL 时无需重复下载，后续运行不需要 Docker 镜像或 Docker 数据卷。

## 3. 一键编译并运行

在仓库根目录执行：

~~~powershell
Set-Location D:\develop\gitee\WealthSail
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1
~~~

`ExecutionPolicy Bypass` 只针对这次 PowerShell 进程，不修改系统执行策略。
无需管理员启动项目，也不用手动激活虚拟环境。

脚本依次完成：

1. 检查 Python、Node、pnpm 和服务端口，选择可用虚拟环境。
2. 安装 `requirements.txt`、Windows 时区所需的 `tzdata` 及前端锁文件中的依赖。
3. 执行 `pnpm build`，完成 TypeScript 检查和 Vite 构建。
4. 使用已有便携 PostgreSQL，或下载并按需解压；初始化 `.local/pgdata`，启动数据库并等待就绪。
5. 执行当前仓库的全部迁移，创建专用 API 登录角色、OWNER 测试账号及示例现金。
6. 启动 FastAPI 和 Vite preview，检查数据库、网页及测试账号登录，然后打开浏览器。

默认地址和账号：

| 项目 | 值 |
| --- | --- |
| 网页 | <http://127.0.0.1:5173> |
| API 文档 | <http://127.0.0.1:8000/docs> |
| 健康检查 | <http://127.0.0.1:8000/healthz> |
| PostgreSQL 端口 | `55432` |
| 测试邮箱 | `local-owner@wealthsail.test` |
| 初始密码 | `LocalDemo-2026!` |
| 租户角色 | `OWNER` |
| 初始示例资产 | 手工现金账户，人民币 `100000.00`，7 天净值记录 |

测试密码只用于这个隔离本地库，后端通过正常 bcrypt 登录流程校验。
首次初始化后，脚本不会重置你修改过的昵称、租户、密码或投资数据；修改密码后请使用新密码登录。

**保持启动窗口打开。** 在该窗口按 `Ctrl+C`，脚本会停止自己启动的 API、前端和数据库，保留本地数据。
下次重新执行同一个命令即可继续。

已有依赖时，跳过安装：

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1 -SkipInstall
~~~

依赖文件更新后，运行不带 `-SkipInstall` 的命令。

如果已在其他位置解压 PostgreSQL，指定其 `bin` 目录：

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1 `
  -PostgresBin 'D:\tools\postgresql\pgsql\bin' -SkipInstall
~~~

该目录的父目录应包含同一套 PostgreSQL 的 `lib`、`share`，不要只复制 `postgres.exe`。
数据库数据仍保存在本仓库的 `.local/pgdata`。

端口占用时可以调整全部端口；脚本会同步设置前端 API 代理：

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1 `
  -DbPort 55433 -ApiPort 8001 -WebPort 5174 -NoBrowser
~~~

`-NoBrowser` 关闭自动打开浏览器。全部服务只监听 `127.0.0.1`。

## 4. 查看状态与停止服务

在另一个 PowerShell 窗口查看本地服务状态：

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1 -Action Status
~~~

停止脚本记录的本地服务，包括后台启动的服务：

~~~powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1 -Action Stop
~~~

停止后保留数据库和测试账号，下次运行默认启动命令即可。
启动窗口仍打开时，也可以直接在该窗口按 `Ctrl+C`。

## 5. 可以体验哪些交互？

建议按以下顺序体验：

1. 输入测试邮箱和密码，进入资产看板，查看 10 万元示例现金及净值曲线。
2. 查看研报、风控和运维页面；新租户没有报告或任务运行记录时，页面显示空状态。
3. 在账号设置中修改昵称、租户名称或报告订阅，刷新页面确认保存。
4. 退出登录，重新登录；浏览器刷新也通过本地 refresh session 恢复会话。
5. 根据需要体验手工持仓或导入流程；行情查询和标的搜索还需要可用的外部数据源网络。

默认只运行 **数据库、API、前端**。
Worker 调度、自动行情刷新、AI 报告、邮件和企业微信投递需要额外配置，不属于本地基础体验的必需条件。
未配置这些能力时，报告列表、投资机会或市场模块可能显示空数据/数据不可用状态。
示例现金不是实时行情，也没有预置完整股票持仓或历史研报。

一键启动使用独立 `.local/api.env`，不读取或修改根目录已有 `.env`。
子进程过滤已有的数据库、模型和企业微信环境变量；不会因根目录配置了远程生产库而自动连接它。
数据库初始化函数只接受回环地址、`postgres` 管理员及数据库名 `wealthsail_local`。

## 6. 文件、数据与日志

| 路径 | 用途 |
| --- | --- |
| `start-local.ps1` | Windows 一键入口及参数 |
| `scripts/local_dev.py` | 依赖准备、数据库初始化、启动、健康检查和停止 |
| `.venv/` 或 `.venv-local/` | 优先复用已有的 Python 3.12 虚拟环境 |
| `.local/postgres/pgsql/` | 自动准备的 PostgreSQL 程序，只保留 `bin`、`lib`、`share` |
| `.local/pgdata/` | 本地 PostgreSQL 数据，包括账号及页面保存的修改 |
| `.local/secrets.json` | 随机生成、持续复用的本地数据库密码和会话密钥 |
| `.local/api.env` | 本地 API 参数 |
| `.local/logs/api.stdout.log`、`api.stderr.log` | 后端日志 |
| `.local/logs/frontend.stdout.log`、`frontend.stderr.log` | 网页服务日志 |
| `.local/cache/`、`.local/tmp/` | 安装缓存和临时文件 |
| `frontend/dist/` | 编译后的网页 |

运行文件已加入 Git 忽略规则。不要提交 `.local` 的密码、备份或测试导入资料。
**不要单独删除 `.local/secrets.json` 后保留 `.local/pgdata`**，否则新生成的数据库密码与旧库不一致。
要保留本地修改时，停止服务后备份 `.local/pgdata` 和 `.local/secrets.json`。

查看日志和健康状态：

~~~powershell
Get-Content .local\logs\api.stderr.log -Tail 80
Get-Content .local\logs\frontend.stderr.log -Tail 80
Invoke-RestMethod http://127.0.0.1:8000/healthz
~~~

健康检查预期包含 `status: ok`、`db: up`。

## 7. 前端开发调试与远程开发库

需要修改前端并自动刷新时，先保持一键服务运行，再在另一窗口启动独立开发端口：

~~~powershell
Set-Location D:\develop\gitee\WealthSail\frontend
$env:VITE_API_BASE_URL = '/api'
$env:WS_LOCAL_API_TARGET = 'http://127.0.0.1:8000'
pnpm.cmd dev --host 127.0.0.1 --port 5174 --strictPort
~~~

打开 <http://127.0.0.1:5174>，页面通过代理使用已运行的本地 API。
开发窗口按 `Ctrl+C` 停止；一键服务用第 4 节命令停止。
如果调整了 API 端口，同步修改 `WS_LOCAL_API_TARGET`。

如需连接独立远程 PostgreSQL/Supabase 开发库，另见 [Windows 本地部署运行方法](13.Windows本地部署运行方法.md)。
这条路径不会使用本文的隔离本地数据库和测试账号，页面编辑会保存到所连接的库，应使用独立开发项目。
迁移应执行当前代码的 **全部迁移**，不要按旧说明只迁移到固定 `029`；步骤见 [数据库升级方法](11.数据库升级方法.md)。

## 8. 常见问题

| 现象 | 处理 |
| --- | --- |
| 脚本被执行策略拦截 | 使用第 3 节带 `-ExecutionPolicy Bypass` 的命令 |
| 找不到 Python 3.12 | 安装 Python 3.12 并启用 launcher/PATH，重新开终端 |
| Node 版本不满足或依赖安装失败 | 换 Node 22.12+，使用 pnpm 按锁文件安装；不要改锁文件来跳过错误 |
| `ZoneInfoNotFoundError: Asia/Shanghai` | Windows 需要 `tzdata`；不带 `-SkipInstall` 重跑，或用选中的虚拟环境安装 `tzdata` |
| 下载失败/磁盘空间不足 | 检查网络和项目所在盘空间；有已解压的程序时用 `-PostgresBin`，依赖完整时用 `-SkipInstall` |
| 指定 PostgreSQL 后仍启动失败 | 检查 `bin` 的父目录是否含同版本的 `lib`、`share`，查看 PostgreSQL 日志 |
| 端口被占用 | 先用 `-Action Status` 检查自己的服务；或用 `-ApiPort/-WebPort/-DbPort` 改端口 |
| API 启动失败 | 看 `.local/logs/api.stderr.log`，确认数据库就绪、迁移完成 |
| 登录失败 | 核对邮箱、大小写、初始密码；如果改过密码，使用新密码 |
| 市场或 AI 数据为空 | 检查外部数据源网络；基础本地运行不启动 Worker 或配置模型密钥 |
| 异常关闭窗口后服务仍在运行 | 先执行 `-Action Status` 和 `-Action Stop`；若启动窗口被强制终止且仍有 API/前端残留，从任务管理器检查属于本项目的进程及占用端口 |
