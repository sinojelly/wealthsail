# WealthSail L2–L4 全功能测试与验收规范（v2.0）

> 初始状态：全部 `NOT_RUN`
>
> 本文定义增量能力的进入条件和风险测试，不表示这些能力已实现
>
> L0/L1 基线见：[MVP 测试规范](./04.WealthSail-MVP功能验收与自动化测试规范.md)

## 1. 进入条件

任何 L2–L4 开发前必须：

- L0/L1 对应主路径和安全/恢复 Gate 已通过；
- 新需求有稳定 ID、owner、数据许可、威胁分析和退出条件；
- 核心 tenant/instrument/account/ledger/source/report ID 不重建；
- 采用 additive schema/event/API 或完成 expand–migrate–contract 计划；
- 现有客户端 contract tests 保持兼容；
- 测试状态继续默认 `NOT_RUN`，不因编写规范改成通过。

## 11. 发布规则

- 每个 Level 独立发布；L4 用例不能替代 L0/L1 回归；
- 新 Provider/Runtime/模型/Skill/市场均运行影响范围回归和 tenant 安全测试；
- P0/P1 无未解释失败；高风险 WAIVED 必须有批准和到期日；
- 报告记录 commit、migration、数据/模型/Prompt/Skill/Runtime/Provider 版本；
- 回测好看、多 Agent 票数或短期收益均不能单独作为生产发布证据；
- 订单和公开收费服务需要产品测试之外的独立合规批准。
