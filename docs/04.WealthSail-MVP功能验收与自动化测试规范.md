## 1. 验收原则与测试分层

1. **金融事实优先**：数量、金额、成本、收益、费税、估值区间和数据质量均与手算/fixture 对比，模型文案不能充当 oracle。
2. **决策与成交分离**：采纳建议只追加 decision；只有确认 fill 才能产生 ledger event。
3. **失败关闭**：缺来源、陈旧、冲突、超时、结构非法和缺凭据都必须明确降级/弃权，不能用常量、空值或模拟成功替代。
4. **租户纵深防御**：应用授权、RLS、组合外键、缓存/队列/检索 namespace 和收件人全部做 A/B/C 测试。
5. **副作用故障注入**：在事务提交、Outbox 发送前后和回执未知点 kill/retry，验证一个业务效果与可恢复审计。
6. **真实 E2E 不偷换**：内存单元测试、UI 原型和 dry-run 不能标记数据库、Provider、Worker 或企微真实链路通过。

| 层级 | 目标 | 典型环境 |
|---|---|---|
| UT / Property | 纯函数、领域不变量、边界值 | 本地 Python，无网络 |
| Contract | Provider/模型/Schema/质量状态 | 冻结 fixture + fake server |
| Integration | PostgreSQL、RLS、Migration、并发、Outbox | 临时 PostgreSQL/Supabase |
| E2E | Auth → Domain API → Worker → DB → 企业微信 | 隔离试点环境与测试应用 |
| NFR / Chaos | 性能、恢复、成本、安全与无障碍 | 类生产环境 |

正式测试数据使用固定交易日 `2026-08-24`，涉及“当前时间”的用例必须注入 clock；不得依赖运行机器的周末、时区或真实当日行情。

## 7. 执行、证据与放行

### 7.1 当前可执行的实现回归

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify.ps1
```

该入口依次执行 Python lint/编译/测试、Migration 发现与 checksum、文档契约校验、前端 lint/组件测试/生产构建和差异空白检查。CI 还会启动临时 PostgreSQL、生产前端包与真实 API，执行登录/Refresh/注销浏览器冒烟；受保护 master 可继续验证专用远程 Supabase。具体边界、Secret 配置、脚本和故障证据见 [CI 与全栈冒烟测试规范](./12.WealthSail-CI与全栈冒烟测试规范.md)。当前自动化已覆盖部分认证会话、投影完整性、可解释基金估值、报告证据、Scheduler lease、Outbox、企微发送适配、Chat 治理以及 Web 错误态；但本地单元/组件测试通过仍不等于正式验收通过。

以下必须在隔离的真实环境生成独立 Run 证据后才能更新上表状态：空库 PostgreSQL Migration 与 RLS 权限回读、多 Worker/Outbox 故障注入、真实行情/基金披露契约、企业微信测试应用收发、生产模型网关、TLS、备份恢复、性能/无障碍检查和 72 小时试运行。正式状态继续保持 `NOT_RUN`，避免把“代码已有测试”误写为“系统已经验收”。

### 7.2 每次 Run 的证据字段

`run_id`、commit、UTC 时间、环境、Python/Node/PostgreSQL 版本、Migration checksum、fixture/clock、Provider contract 版本、模型/Skill 版本、测试选择表达式、原始报告链接、失败日志脱敏位置、执行人/审批人。

### 7.3 L1 放行规则

- 所有 L0/L1 Must 的正常与异常/安全测试均有有效证据；
- 无跨租户、错发、假数据、重复经济效果、决策直接入账和不可恢复数据缺陷；
- 高严重度失败为零，其他失败有 owner、期限和明确风险接受；
- 数据许可、试用协议、人工暂停、回滚、备份恢复和事故联系人就绪。
