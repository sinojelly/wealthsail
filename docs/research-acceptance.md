# 每日投研分层验收：第一阶段

本阶段保留 READY / FAILED / UNCERTAIN 和所有正式报告消费门槛。严格 `validate_report` 接口继续存在；新增收集式验收记录完整问题，并将可信的部分成果保存为独立、不可交易的观察资料。不会引入 PARTIAL 正式终态。

`ValidationOutcome.decision` 的 COMPLETE / PARTIAL / EMPTY / REJECTED 只是独立验收结论。只有原严格接口完整通过，才能产生正式 payload 并写 READY；部分通过仍写 FAILED 和 NULL payload，旧 READY 报告的回退逻辑不变。Codex 推理计量只记录原调用一次，验收及离线重放不计作新模型调用。

## 数据依赖与边界

冻结输入决定基金身份、行业、价格轨道、宏观事实和14日历史风险；来源核验快照决定引文身份及核验强度；行业审查与方向分别核实五类风险。方向、事件、日历依赖有效来源，事件和日历还依赖有效方向。排序及入场保护只在严格验收内运行；独立展示数据禁止调用交易动作、跟踪来源和机会通知。

验收首先运行原严格路径。预期业务错误启动逐来源、行业审核、方向、事件、日历的收集式验收，保留原风险字段，不删风险核查项、不改 FOUND/UNVERIFIED、不造审核或价格。逐项完成后再检查引用闭包、历史风险和入场保护。只允许在确有匹配服务器审查时确定性关联行业；未知引用不猜测修复。无法解析、越界、不可信URL及安全内容整体拒绝，内部异常向外传播。

## 存档与可见性

不可变产物存储保留原始模型输出、冻结输入、来源核验快照、原验证时钟、哈希、大小和缺失理由。独立验收记录保存版本、完整结构化问题、依赖及安全观察投影。正式结果与初次验收记录在同一事务写入；部分成果的 FAILED 结果仍没有普通 payload。数据库错误不伪装成功。

普通成员只能读取安全观察投影和固定问题说明；管理员经实时成员校验可读完整问题、原始材料并离线重放。手动任务资料按原请求租户隔离，公共定时任务资料遵循公共研究范围；重放记录另按发起租户隔离。重放使用原始时钟和保存的来源核验结果，禁止模型调用或重新联网补证，产生新的不可变记录，不覆盖历史报告。

每个问题包含研究ID、条目类型、原始位置、稳定业务标识、规则、缺失编码、处理结果和依赖。大小或条目数超预算时明确拒绝或注明原始材料不可重放，不通过无声截断宣称问题列表完整。观察投影不含计划、买卖价格、跟踪origin、交易按钮或推送资格。

存储分为 `research.research_validation_artifacts`（每研究一次）和 `research.research_validation_records`（INITIAL 一次，REPLAY 追加）。材料先独立提交，正式结果与 INITIAL 验收记录再原子提交；后一个事务失败时仍可留存材料，但不能显示虚假的验收成功。运行时角色无 UPDATE / DELETE 权限；FORCE RLS、实时租户成员状态和管理员数据库读取函数共同约束访问，不能仅凭前端角色或请求参数取得原文。

预算为冻结输入 4 MiB、原始输出 2 MiB、来源快照 512 KiB，结构深度最多32层，问题最多1000条。超大的材料只保存哈希、字节数和明确缺失理由，不保存截断后冒充完整的输入。验收记录按768 KiB控制，数据库每份私有结果或公开摘要最多1 MiB。必要时只节选观察正文并标记 `acceptedContentComplete=false`，页面明确提示；不得节选掉风险检查来取得通过。问题清单超过预算时标记 `issueListComplete=false` 并拒绝部分发布，不能将预算失败伪装成完整清单。严格通过报告的正式 payload 不因观察投影节选而被改写。

## 接口与页面

- `GET /investment/daily-research/validation/{run_id}`：有效成员的安全观察摘要；管理员同时获得完整结构化问题，可按类别筛选和查看缺失行业代码。
- `GET /investment/daily-research/validation/{run_id}/artifacts`：仅有效管理员，读取冻结输入、模型输出和来源核验快照及完整性信息。
- `POST /investment/daily-research/validation/{run_id}/replays`：管理员提交 UUID `commandKey`，同一租户、操作者、命令幂等；核对材料哈希并按原时钟重放。
- `GET /investment/daily-research/validation/{run_id}/replays`：管理员查看本租户最近20次重放，结果独立展示。

重放只运行当前版本的验收器，不重新搜索、补证、执行模型或更新正式报告。不存在材料、哈希不一致或材料超预算时明确拒绝重放。原执行失败、来源核验未完成或系统异常只能留证并拒绝，不能仅因附带合法 JSON 就宣称 COMPLETE。系统异常不吞入“部分成功”。

页面在每日研究报告中增加独立只读验收区域，展示通过数、隔离数、固定错误说明和来源证据。管理员原文使用纯文本展示，普通成员没有原文入口。手动任务失败后只刷新报告上下文以显示本次验收，不触发跟踪买入、机会推送或正式报告发布。

## 部署顺序与运行限制

先对目标数据库应用迁移099，再更新相互匹配的 API、Worker、Codex Runner（使用远程执行器时）与 Frontend。迁移仅新增存档、验收、权限及读取函数，不回填或改写既有 FAILED / READY 记录，不重置调度名额，也不触发研究。旧运行没有冻结材料时页面保持原行为，不能事后伪造原始资料。

部分成果不会进入现有 READY 消费路径，包括行业风险传承、评分、研究跟踪、通知及买入。完全合格方向也仅以观察形式展示，这是本阶段的安全边界。来源核验沿用保存的实际核验结果，不声称补齐独立搜索执行凭证。每条记录有大小限制，但总量保留周期和容量告警仍需运营策略；本次没有增加自动删除不可变材料的任务。进程未返回任何输出的超时可能只有材料缺失记录，不自动重跑。

## 后续阶段

若引入正式 PARTIAL 终态，必须先统一修改数据库 CHECK、DTO、旧报告回退、历史行业风险、评分、手动队列、study三类 DAILY 来源、持仓风险上下文及 SCHEDULED+READY 通知路径。本阶段不做这些变更。

本地测试使用固定模型输出和独立临时 PostgreSQL；不修改既有执行记录、不重置自动名额、不调用真实 Codex、不部署。验证完成后依用户要求提交并推送代码。
