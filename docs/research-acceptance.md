# 每日投研分层验收：第一阶段

本阶段保留 READY / FAILED / UNCERTAIN 和所有正式报告消费门槛。严格 `validate_report` 接口继续存在；新增收集式验收记录完整问题，并将可信的部分成果保存为独立、不可交易的观察资料。不会引入 PARTIAL 正式终态。

`ValidationOutcome.decision` 的 COMPLETE / PARTIAL / EMPTY / REJECTED 只是独立验收结论。只有原严格接口完整通过，才能产生正式 payload 并写 READY；部分通过仍写 FAILED 和 NULL payload，旧 READY 报告的回退逻辑不变。Codex 推理计量只记录原调用一次，验收及离线重放不计作新模型调用。

## 数据依赖与边界

冻结输入决定基金身份、行业、价格轨道、宏观事实和14日历史风险；来源核验快照决定引文身份及核验强度；行业审查与方向分别核实五类风险。方向、事件、日历依赖有效来源，事件和日历还依赖有效方向。排序及入场保护只在严格验收内运行；独立展示数据禁止调用交易动作、跟踪来源和机会通知。

验收首先运行原严格路径。预期业务错误启动逐来源、行业审核、方向、事件、日历的收集式验收，保留原风险字段，不删风险核查项、不改 FOUND/UNVERIFIED、不造审核或价格。逐项完成后再检查引用闭包、历史风险和入场保护。只允许在确有匹配服务器审查时确定性关联行业；未知引用不猜测修复。无法解析、越界、不可信URL及安全内容整体拒绝，内部异常向外传播。

## 存档与可见性

不可变产物存储保留原始模型输出、冻结输入、来源核验快照、原验证时钟、哈希、大小和缺失理由。独立验收记录保存版本、完整结构化问题、依赖及安全观察投影。正式结果与有界、持久化的归档待办在同一事务提交；材料及初次验收记录由独立归档事务写入。部分成果的 FAILED 结果仍没有普通 payload。数据库错误不伪装成功。

普通成员只能读取安全观察投影和固定问题说明；管理员经实时成员校验可读完整问题、原始材料并离线重放。手动任务资料按原请求租户隔离，公共定时任务资料遵循公共研究范围；重放记录另按发起租户隔离。重放使用原始时钟和保存的来源核验结果，禁止模型调用或重新联网补证，产生新的不可变记录，不覆盖历史报告。

每个问题包含研究ID、条目类型、原始位置、稳定业务标识、规则、缺失编码、处理结果和依赖。大小或条目数超预算时明确拒绝或注明原始材料不可重放，不通过无声截断宣称问题列表完整。观察投影不含计划、买卖价格、跟踪origin、交易按钮或推送资格。

存储分为 `research.research_validation_artifacts`（每研究一次）和 `research.research_validation_records`（INITIAL 一次，REPLAY 追加）。归档待办保存不可变的冻结材料描述和验收结果；Worker提交正式终态后尝试归档，失败时保留 AUDIT_PENDING 和安全错误类别，由恢复服务重试，严格通过的 READY 不被附加归档故障撤销。恢复服务不依赖手动研究开关，不运行模型、重新验收或重新联网；领取使用租约和并发隔离，耗尽8次尝试后标记 UNRECOVERABLE。原正式结果和待办的核心数据库事务无法提交时仍应报错，不能承诺在数据库整体不可写时完成落库。

正式材料与验收结果的运行时角色无 UPDATE / DELETE 权限；归档待办仅允许受限修改状态、租约和尝试元数据，不能改写冻结正文。FORCE RLS、实时租户成员状态和管理员数据库读取函数共同约束访问，不能仅凭前端角色或请求参数取得原文。INITIAL 尚未归档时，成员可见固定的待恢复说明；管理员可定位研究、查看可恢复的冻结材料及缺失理由，不会把暂无验收记录误判为业务失败。

预算为冻结输入 4 MiB、原始输出 2 MiB、来源快照 512 KiB，结构深度最多32层，问题最多1000条。超大的材料只保存哈希、字节数和明确缺失理由，不保存截断后冒充完整的输入。验收记录按768 KiB控制，数据库每份私有结果或公开摘要最多1 MiB。必要时只节选观察正文并标记 `acceptedContentComplete=false`，页面明确提示；不得节选掉风险检查来取得通过。问题清单超过预算时标记 `issueListComplete=false` 并拒绝部分发布，不能将预算失败伪装成完整清单。严格通过报告的正式 payload 不因观察投影节选而被改写。

## 接口与页面

- `GET /investment/daily-research/validation/{run_id}`：有效成员的安全观察摘要；管理员同时获得完整结构化问题，可按类别筛选和查看缺失行业代码。
- `GET /investment/daily-research/validation/{run_id}/artifacts`：仅有效管理员，读取冻结输入、模型输出和来源核验快照及完整性信息。
- `POST /investment/daily-research/validation/{run_id}/replays`：管理员提交 UUID `commandKey`，同一租户、操作者、命令幂等；核对材料哈希并按原时钟重放。
- `GET /investment/daily-research/validation/{run_id}/replays`：管理员查看本租户最近20次重放，结果独立展示。

重放只运行当前版本的验收器，不重新搜索、补证、执行模型或更新正式报告。不存在材料、哈希不一致或材料超预算时明确拒绝重放。原执行失败、来源核验未完成或系统异常只能留证并拒绝，不能仅因附带合法 JSON 就宣称 COMPLETE。系统异常不吞入“部分成功”。

重放按上海自然日限制每个租户操作者10次、每份研究累计20次及20 MiB结果存储预算；失败或超时的尝试也计入次数，同一命令键重试不新增尝试。操作者和研究级非阻塞并发锁防止重叠执行。纯校验子进程最多执行30秒，超时或取消时终止并回收，不把同步校验放入无法终止的后台线程。版本除人工接口版本外，同时保存已部署校验规则的 SHA-256 修订号；原INITIAL不修改，重放另存本次修订号，缺失构建源码时明确标记版本不可得，不能因此撤销严格通过报告。

页面在每日研究报告中增加独立只读验收区域，展示通过数、隔离数、固定错误说明和来源证据。仅在对应研究进入终态后读取，终态/完成时间变化时重新查询，避免同runId早期404遮蔽后续结果；旧历史404继续静默。来源逐项显示 SOURCE_CHECKED / UNVERIFIED / UNAVAILABLE，方向和行业核查显示风险等级、未解决标记与证据缺口，不能把结构验收等同于引文已核实。管理员原文使用纯文本展示，普通成员没有原文入口。手动任务失败后只刷新报告上下文以显示本次验收，不触发跟踪买入、机会推送或正式报告发布。

宏观总纲可独立保留summary、macroCycle和逐项合法coverage，始终标注 MODEL_UNVERIFIED。现有总纲没有逐句来源引用，因此仅在全部全局来源通过验收且非空时保留；有来源隔离时，总纲依赖不明，明确隔离而不猜测独立性。不得把内部验收的中性占位文字展示为原始研究。

## 部署顺序与运行限制

先对目标数据库应用迁移099、100，再更新相互匹配的 API、Worker、Codex Runner（使用远程执行器时）与 Frontend。迁移仅新增存档、验收、补偿、重放预算、权限及读取函数，不回填或改写既有 FAILED / READY 记录，不重置调度名额，也不触发研究。旧运行没有冻结材料时页面保持原行为，不能事后伪造原始资料。

部分成果不会进入现有 READY 消费路径，包括行业风险传承、评分、研究跟踪、通知及买入。完全合格方向也仅以观察形式展示，这是本阶段的安全边界。来源核验沿用保存的实际核验结果，不声称补齐独立搜索执行凭证。每条记录有大小限制，重放有累计预算，但跨研究的总量保留周期和容量告警仍需上线前配置；归档待办与正式材料各有一份冻结副本，应一并计入数据库容量、备份和卷空间报警。本次没有增加自动删除不可变材料的任务或修改个人NAS配置。进程未返回任何输出的超时可能只有材料缺失记录，不自动重跑。

重放额度约束针对正式API入口；持有数据库运行角色凭据直接执行SQL的边界沿用既有099授权，不能将API额度宣传为数据库管理员也无法绕过的配额。生产应限制该角色凭据与数据库网络访问。本次未扩大原文读取或REPLAY写入角色授权。
