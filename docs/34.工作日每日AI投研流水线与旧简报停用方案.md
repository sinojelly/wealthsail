# 每日 AI 投研流水线、可配置调度与旧简报停用方案

## 需求与边界（2026-10-31修订）

本方案取代旧文档中“每天08:30、公共采集和研究分别调度、每日研究开关同时控制盘前简报”的约定。参考分析报告59、60、61；用户最新要求将上一版固定周一至周五07:00改为默认每天07:00，并可配置频率与时间。保留原文件名以避免已有链接失效。

| 编号 | 要求 |
| --- | --- |
| FR-PIPE-001 | 默认北京时间每天07:00启动，包含周末；允许配置DAILY或WEEKDAYS及24小时HH:MM时间。WEEKDAYS仅周一至周五，与大陆调休日历和A股交易日历独立。 |
| FR-PIPE-002 | `DAILY_RESEARCH_ENABLED`是流水线唯一主开关，统一控制公共机会采集、质量检查、输入冻结、Codex研究和报告保存。 |
| FR-PIPE-003 | 同一天公共采集未完成、失败或质量不合格时，不调用模型；不能因为等待超过10分钟而越过门禁。 |
| FR-PIPE-004 | 正式研究必须关联实际使用的当日采集批次，不能自动回退到其他日期或调试批次；事实保留其观察、公布、获取时间。 |
| FR-PIPE-005 | 同一天最多登记一次正式模型执行；并发、重启、返回验证失败或结果不确定都不能自动再次调用模型。 |
| FR-PIPE-006 | 旧08:30宏观简报、08:35个性化简报及对应消息默认关闭，历史数据保留；旧待发送消息也必须遵守开关。 |
| FR-PIPE-007 | 每日AI机会研究的晨间企微推送独立默认关闭，不影响14:30检查、盘中跟踪和盘后复盘。 |
| FR-PIPE-008 | 页面展示可读主状态和当前阶段，状态后括号注明实际触发时间；未启动时明确标为计划时间，保留历史报告与失败诊断。 |

晨间机会推送读取的是成功的Codex研究报告，不是转发上述两份旧简报。保留它的实现与独立开关，避免和旧简报通知混淆。

## 调度与开关

| 配置 | 默认值 | 职责 |
| --- | --- | --- |
| `DAILY_RESEARCH_ENABLED` | `false` | 整条每日自动AI流水线 |
| `DAILY_RESEARCH_SCHEDULE_MODE` | `DAILY` | 每天，包括周末；WEEKDAYS仅周一至周五 |
| `DAILY_RESEARCH_SCHEDULE_TIME` | `07:00` | Asia/Shanghai的24小时HH:MM，例如08:00、08:15；非法格式启动时拒绝 |
| `DAILY_RESEARCH_START_WINDOW_MINUTES` | `120` | 从计划时间起允许新领取/恢复流水线的窗口，默认07:00至09:00，不是模型派发截止时间 |
| `DAILY_RESEARCH_PIPELINE_TIMEOUT_SECONDS` | `7200` | 从首次开始计的总运行期限，含重启前时间，允许600至14400秒 |
| `DAILY_RESEARCH_CATCH_UP` | `true` | 重启后仅在当天允许的启动窗口内补启动 |
| `PRE_MARKET_REPORTS_ENABLED` | `false` | 两份旧盘前简报的自动生成、恢复及消息发送 |
| `MORNING_OPPORTUNITY_PUSH_ENABLED` | `false` | 每日AI机会研究结果的晨间群推送 |
| `ALPHA_PUBLIC_ENABLED` | 保留兼容 | 不再作为每日AI采集的第二开关；每日AI开启时不注册独立采集循环 |
| `ALPHA_OPPORTUNITY_ENABLED` | 保留原配置 | 机会服务总约束，不能替代晨间推送开关 |

`FUND_1430_ENABLED`、`INTRADAY_TRACKING_ENABLED`、`POST_MARKET_REVIEW_ENABLED`继续分别控制原功能。API与Worker应使用一致的研究开关、频率、时间及启动窗口。只调整公开模板与初始化默认值，不自动覆盖个人环境文件。修改配置后，已有当天流水线保留其最初计划时间，后续日期才按新配置安排；当日模型唯一槽不会因修改时间而释放。

07:00表示开始准备研究，并非承诺07:00报告完成。09:00启动窗口结束后，不再新领或恢复当天流水线；已持有效租约的流水线可以完成准备并首次派发模型，不因窗口结束而终止。例如08:55启动、09:02准备完成可以继续，但仍受首次启动后7200秒的总限时、数据时效和独立模型超时约束。默认DAILY的周五之后安排周六；WEEKDAYS才跳到周一，不在计划时间前突然补跑。

时间可设为00:00至23:59，但研究必须使用同一北京时间自然日的数据。临近午夜启动且准备跨日时，在模型前安全终止，不挪用第二天执行槽；此功能以早间研究为主要用途。

### 大陆工作日历与交易日的区别

大陆行政工作日可依据[国务院2026年节假日安排](https://www.beijing.gov.cn/zhengce/zhengcefagui/202511/t20251104_4258873.html)维护，包含法定假期和周末补班，需要每年更新已公布范围。证券交易日另遵循[交易所休市公告](https://investor.szse.cn/disclosure/notice/general/t20251222_618087.html)：例如2026年10月10日行政补班，交易所仍周末休市。现有市场日历用于净值质量证明，不代表行政调休。当前日程只提供DAILY和WEEKDAYS，不调用在线节假日API，不把缺失年份静默当成已确认大陆工作日。

## 串行依赖与数据门禁

流水线依次执行：公共采集 → 校验批次及质量 → 构建并冻结公开研究输入 → Codex预检 → 领取唯一模型执行槽 → 调用模型 → 来源与报告核验 → 保存最终报告。

自动研究开启时，`run_alpha_runtime`只注册上述研究入口，不再同时注册独立的早间公共采集服务。其他无关数据刷新、队列、盘中和盘后服务保持独立。

| 当日指定采集批次状态 | 模型行为 |
| --- | --- |
| 不存在 | 先采集，不能直接使用历史批次 |
| `CLAIMED` | 等待原采集者完成；长时间等待也不能当作成功，重启不抢占或重复采集 |
| `FAILED` | 停止，记录失败阶段和原因；包括采集取消已落FAILED的批次，不自动重采或覆盖 |
| `PARTIAL` | 仅在明确的关键事实与本基金净值质量检查通过后允许降级研究，保留缺失说明 |
| `READY` | 仍需检查批次身份、时间与真实输入，不能只信状态字符串 |

数据质量沿用既有来源和时效规则：月度CPI、M2等不要求观察期等于今天；检验真实公布/观察期、来源、抓取时间和可用窗口。无有效公开事实、净值依据不足、未来时间、错误币种/标的或批次不一致不能进入模型。冻结指定批次后不额外重采基金净值，也不悄悄换成另一个批次。

当前允许PARTIAL研究的最低标准是：至少一条通过既有来源校验的宏观观察，或一条7天内、来源采集成功/部分成功且时间可用的催化事实；同时至少一只人民币基金有近两年不少于120条真实净值、最新净值不超过7天、来源核查不超过36小时，并通过完整供应商或交易日历证明。全部原始历史仍参与来源证明校验，不能拿多年前样本凑近两年门槛。缺失来源列表与降级状态随本次输入和报告保留。

## 持久化、并发与诊断

新增前向迁移`095`，记录每日流水线及阶段；保留现有公共采集批次、研究执行和最终结果表。数据库唯一约束与租约负责跨进程去重，租约令牌防止旧执行者覆盖新状态；模型执行仍受既有每日唯一槽约束。

流水线记录`state`、`stage`、计划/开始/更新时间、结束时间、采集批次ID、研究执行ID和安全错误类别。阶段覆盖`COLLECTING`、`WAITING_SOURCES`、`VALIDATING_INPUT`、`MODEL_RUNNING`、`VERIFYING_OUTPUT`、`PERSISTING`。只有报告验证与保存成功才返回`READY`；模型登记后取消或结果不确定保留`UNCERTAIN`。不通过删除历史批次、运行记录或账本来重试。

模型槽尚不存在时，正常Worker取消释放前置阶段租约，进程死亡导致COLLECTING/VALIDATING_INPUT租约过期也允许在启动窗口内安全重领，原开始时间、计划时间及来源批次不变。重领先查询来源批次：READY/PARTIAL直接复用并重新验证，CLAIMED等待，FAILED终止；并不保证任意采集故障自动恢复。模型槽已登记、模型阶段超时或终态不能自动再生成。

运行中的owner每30秒用正确且尚未过期的令牌续租；旧令牌、过期令牌和终态均拒绝续租。心跳丢失停止当前owner后续派发；总运行期限不因续租或重启延长。报告终态写入前停止心跳，再在同一事务内验证租约并写报告与流水线终态，避免成功提交后被心跳误判为失租。

预检失败不消耗模型执行槽。已领取并开始的模型调用、验证失败及不确定结果都不自动重新生成。已有当日正式执行记录照常去重；旧报告和个人冻结研究版本不重写。

日志记录阶段、运行ID、采集批次ID、研究ID、耗时及错误类别，不记录提示词、认证信息、完整供应商响应或连接字符串。采集和构包前失败也可通过流水线状态定位，而非笼统显示“尚未派发”。

## 页面状态

主状态区分尚未启动、准备/研究中、研究成功、失败、异常待核实、错过启动时段、非工作日和自动研究关闭。运行中优先说明当前阶段；不重复拼接“已登记每日研究·今日已登记派发”。频率与时间来自API的`schedule={mode,time,timezone,startWindowMinutes}`，旧响应缺失时使用中性说明，不硬编码07:00或周一至周五。

时间采用北京时间，格式示例：`正在采集公共数据（触发时间：2026年10月30日07:00，北京时间）`。实际时间取流水线开始时间，兼容旧记录中的研究执行时间；只有计划时间时明确写`计划触发`，没有可信时间时不伪造。旧报告始终注明其实际研究/完成日期，今日失败不能被旧的READY报告遮住。

## 部署与验收

先按现有数据库升级流程应用新增迁移，再更新API、Worker、前端；已有093、094等迁移不能改写。Worker未启动、挂载目录缺失、迁移缺失不能用页面历史报告冒充新流程正常。运行环境配置示例：

```dotenv
DAILY_RESEARCH_ENABLED=true
DAILY_RESEARCH_SCHEDULE_MODE=DAILY
DAILY_RESEARCH_SCHEDULE_TIME=07:00
DAILY_RESEARCH_START_WINDOW_MINUTES=120
DAILY_RESEARCH_PIPELINE_TIMEOUT_SECONDS=7200
PRE_MARKET_REPORTS_ENABLED=false
MORNING_OPPORTUNITY_PUSH_ENABLED=false
```

仅重启容器不会重读环境文件，需沿原Compose入口重建相应容器。无需新增NAS cron，不触发真实模型来测试调度，不删除当天执行记录补跑。实现通过本地TDD、隔离数据库测试及页面替身验证后提交；真实NAS数据源、登录及首个计划日自动执行仍需部署验收。

Review 61指出的095事务控制在此次上线前删除，由Python迁移器唯一持有DDL与账本的事务边界；静态扫描阻止新迁移带顶层事务语句，旧已应用迁移包装仅冻结例外。真实PostgreSQL通过注入095账本写入失败验证DDL同回滚。不改093/094，也不协调生产账本校验和；若已经部署旧095，必须先核对实际迁移历史，不能直接套用“尚未部署”的升级前提。
