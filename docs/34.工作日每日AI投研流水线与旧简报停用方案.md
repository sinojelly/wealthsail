# 工作日每日 AI 投研流水线与旧简报停用方案

## 需求与边界（2026-10-30）

本方案取代旧文档中“每天08:30、公共采集和研究分别调度、每日研究开关同时控制盘前简报”的约定。参考分析报告59、60；时间以用户最新要求为准。

| 编号 | 要求 |
| --- | --- |
| FR-PIPE-001 | 北京时间周一至周五07:00启动一条自动投研流水线；周末不启动。这里的工作日按周一至周五计算，与A股交易日历独立，不补造法定节假日判断。 |
| FR-PIPE-002 | `DAILY_RESEARCH_ENABLED`是流水线唯一主开关，统一控制公共机会采集、质量检查、输入冻结、Codex研究和报告保存。 |
| FR-PIPE-003 | 同一天公共采集未完成、失败或质量不合格时，不调用模型；不能因为等待超过10分钟而越过门禁。 |
| FR-PIPE-004 | 正式研究必须关联实际使用的当日采集批次，不能自动回退到其他日期或调试批次；事实保留其观察、公布、获取时间。 |
| FR-PIPE-005 | 同一天最多登记一次正式模型执行；并发、重启、返回验证失败或结果不确定都不能自动再次调用模型。 |
| FR-PIPE-006 | 旧08:30宏观简报、08:35个性化简报及对应消息默认关闭，历史数据保留；旧待发送消息也必须遵守开关。 |
| FR-PIPE-007 | 每日AI机会研究的晨间企微推送独立默认关闭，不影响14:30检查、盘中跟踪和盘后复盘。 |
| FR-PIPE-008 | 页面展示可读主状态和当前阶段，状态后括号注明实际触发时间；未启动时明确标为计划时间，保留历史报告与失败诊断。 |

晨间机会推送读取的是成功的Codex研究报告，不是转发上述两份旧简报。保留它的实现与独立开关，避免和旧简报通知混淆。

## 调度与开关

| 配置 | 默认值 | 职责 |
| --- | --- | --- |
| `DAILY_RESEARCH_ENABLED` | `false` | 整条工作日07:00自动AI流水线 |
| `DAILY_RESEARCH_START_WINDOW_MINUTES` | `120` | 当天允许启动/恢复准备阶段的窗口，默认07:00至09:00 |
| `DAILY_RESEARCH_CATCH_UP` | `true` | 重启后仅在当天允许的启动窗口内补启动 |
| `PRE_MARKET_REPORTS_ENABLED` | `false` | 两份旧盘前简报的自动生成、恢复及消息发送 |
| `MORNING_OPPORTUNITY_PUSH_ENABLED` | `false` | 每日AI机会研究结果的晨间群推送 |
| `ALPHA_PUBLIC_ENABLED` | 保留兼容 | 不再作为每日AI采集的第二开关；每日AI开启时不注册独立采集循环 |
| `ALPHA_OPPORTUNITY_ENABLED` | 保留原配置 | 机会服务总约束，不能替代晨间推送开关 |

`FUND_1430_ENABLED`、`INTRADAY_TRACKING_ENABLED`、`POST_MARKET_REVIEW_ENABLED`继续分别控制原功能。API与Worker应使用一致的研究开关及启动窗口。只调整公开模板与初始化默认值，不自动覆盖个人环境文件。

07:00表示开始准备研究，并非承诺07:00报告完成。09:00启动窗口结束后，尚未启动的任务显示已错过时段；已经开始的模型由自身超时控制，不因窗口结束而强制中断。周五之后的下一次计划时间为周一07:00，不在夜间或周末突然补跑。

## 串行依赖与数据门禁

流水线依次执行：公共采集 → 校验批次及质量 → 构建并冻结公开研究输入 → Codex预检 → 领取唯一模型执行槽 → 调用模型 → 来源与报告核验 → 保存最终报告。

自动研究开启时，`run_alpha_runtime`只注册上述研究入口，不再同时注册独立的早间公共采集服务。其他无关数据刷新、队列、盘中和盘后服务保持独立。

| 当日指定采集批次状态 | 模型行为 |
| --- | --- |
| 不存在 | 先采集，不能直接使用历史批次 |
| `CLAIMED` | 等待完成；长时间等待也不能当作成功 |
| `FAILED` | 停止，记录失败阶段和原因 |
| `PARTIAL` | 仅在明确的关键事实与本基金净值质量检查通过后允许降级研究，保留缺失说明 |
| `READY` | 仍需检查批次身份、时间与真实输入，不能只信状态字符串 |

数据质量沿用既有来源和时效规则：月度CPI、M2等不要求观察期等于今天；检验真实公布/观察期、来源、抓取时间和可用窗口。无有效公开事实、净值依据不足、未来时间、错误币种/标的或批次不一致不能进入模型。冻结指定批次后不额外重采基金净值，也不悄悄换成另一个批次。

当前允许PARTIAL研究的最低标准是：至少一条通过既有来源校验的宏观观察，或一条7天内、来源采集成功/部分成功且时间可用的催化事实；同时至少一只人民币基金有近两年不少于120条真实净值、最新净值不超过7天、来源核查不超过36小时，并通过完整供应商或交易日历证明。全部原始历史仍参与来源证明校验，不能拿多年前样本凑近两年门槛。缺失来源列表与降级状态随本次输入和报告保留。

## 持久化、并发与诊断

新增前向迁移`095`，记录每日流水线及阶段；保留现有公共采集批次、研究执行和最终结果表。数据库唯一约束与租约负责跨进程去重，租约令牌防止旧执行者覆盖新状态；模型执行仍受既有每日唯一槽约束。

流水线记录`state`、`stage`、开始/更新时间、结束时间、采集批次ID、研究执行ID和安全错误类别。阶段覆盖`COLLECTING`、`WAITING_SOURCES`、`VALIDATING_INPUT`、`MODEL_RUNNING`、`VERIFYING_OUTPUT`、`PERSISTING`。只有报告验证与保存成功才返回`READY`；取消或模型结果不确定保留`UNCERTAIN`。不通过删除历史批次、运行记录或账本来重试。

预检失败不消耗模型执行槽。已领取并开始的模型调用、验证失败及不确定结果都不自动重新生成。已有当日正式执行记录照常去重；旧报告和个人冻结研究版本不重写。

日志记录阶段、运行ID、采集批次ID、研究ID、耗时及错误类别，不记录提示词、认证信息、完整供应商响应或连接字符串。采集和构包前失败也可通过流水线状态定位，而非笼统显示“尚未派发”。

## 页面状态

主状态区分尚未启动、准备/研究中、研究成功、失败、异常待核实、错过启动时段、非工作日和自动研究关闭。运行中优先说明当前阶段；不重复拼接“已登记每日研究·今日已登记派发”。

时间采用北京时间，格式示例：`正在采集公共数据（触发时间：2026年10月30日07:00，北京时间）`。实际时间取流水线开始时间，兼容旧记录中的研究执行时间；只有计划时间时明确写`计划触发`，没有可信时间时不伪造。旧报告始终注明其实际研究/完成日期，今日失败不能被旧的READY报告遮住。

## 部署与验收

先按现有数据库升级流程应用新增迁移，再更新API、Worker、前端；已有093、094等迁移不能改写。Worker未启动、挂载目录缺失、迁移缺失不能用页面历史报告冒充新流程正常。运行环境配置示例：

```dotenv
DAILY_RESEARCH_ENABLED=true
DAILY_RESEARCH_START_WINDOW_MINUTES=120
PRE_MARKET_REPORTS_ENABLED=false
MORNING_OPPORTUNITY_PUSH_ENABLED=false
```

仅重启容器不会重读环境文件，需沿原Compose入口重建相应容器。无需新增NAS cron，不触发真实模型来测试调度，不删除当天执行记录补跑。实现通过本地TDD、隔离数据库测试及页面替身验证后提交；真实NAS数据源、登录及首个工作日自动执行仍需部署验收。
