# Review75：投研可信度与重复工作优化

用户授权：参考75号审查优化；保持本地实现、验证和提交，不推送、不部署、不访问生产、不执行真实模型。

## 已核实的边界与设计

1. 研究任务50条只是计划。CLI JSONL可以提供部分工具完成事件，不能在服务商发出搜索前拦截，也不能看到隐藏重试。新增闭合、有界执行凭证与工作量统计，能力标识明确false/unknown；不能声称实现了实际搜索或金额硬上限。超额观测不丢弃有效终稿，不自动二次调用模型。
2. V2的NOT_FOUND必须有服务器保存、绑定本研究/原manifest/原时钟的完整执行凭证才能关闭任务。结构齐全、执行事件核验和原文证据核验独立统计；无凭证维持待审。FOUND仍需原文、近期事件和行业归属，不用搜索次数代替事实。
3. 冻结预算按已知版本/profile验证；当前运行预算改变不使旧材料变损坏。未知版本明确INCOMPATIBLE。原始冻结packet/hash不变，模型只收到单份精简行业任务视图。
4. V2允许方向仅引用完整顶层审核，服务器重新合并同范围五项核查、来源和历史保护。模型可输出industryCycle=null或保留独立阶段证据，不重复输出五项详细检查；V1不放宽。
5. 页面分别显示严格计算、自动发布和待补证状态。兼容旧目录字段缺失，修复缺少隔离数组时的展示异常。

### 离线版本诊断兼容

未知冻结契约在离线预检、受限子进程、管理员历史预览/生成、旧验收重放与文件 CLI 中独立归类为 `INCOMPATIBLE`，固定提示“该冻结契约版本暂不受支持”；已知版本的哈希损坏仍归材料无效。100/101 已发布迁移中的尝试表错误码闭集不含该新分类，因此底层失败尝试继续保存 `VALIDATOR_FAILED`。同一 commandKey 重试仅只读检查原冻结契约以恢复专属说明，不启动子进程、不新增尝试或计额；不修改旧记录和约束。CLI 仅对该固定分类增加 `errorCode`，不回显版本原文或异常内容。
