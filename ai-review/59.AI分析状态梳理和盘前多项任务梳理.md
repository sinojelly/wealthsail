当前 WealthSail（我检查的仓库版本为 `589da2e`）中，“每日 AI 研究”和“08:30 盘前报告”不是同一个任务。它们只是集中在早上执行，部分功能还共用了一个总开关。



我建议把“任务状态”和“调度状态”彻底分开显示，并逐步把早间任务改成独立开关。



\## 一、每日 AI 研究有哪些状态？英文与推荐中文



\### 1. 研究执行状态 `state`



| 英文状态        | 当前中文    | 建议中文           |

| ----------- | ------- | -------------- |

| `NOT\_RUN`   | 今日尚未研究  | 今日尚未启动         |

| `RUNNING`   | 已登记每日研究 | 正在研究中          |

| `READY`     | 日报已完成   | 研究成功 · 报告已生成   |

| `FAILED`    | 今日研究失败  | 研究失败           |

| `UNCERTAIN` | 执行结果待确认 | 执行异常 · 待核实     |

| `STALE`     | 历史日报    | 今日未完成 · 显示历史报告 |

| `DISABLED`  | 每日研究未启用 | 自动研究已关闭        |



这里有两个特别需要说明的地方。



`RUNNING` 不代表模型已经开始生成。 当前代码先采集数据、组装输入、执行 Codex 预检，然后登记数据库执行记录。只有登记之后，网页才可能显示 `RUNNING`。



`UNCERTAIN` 也不一定代表研究失败。 当前代码在已有执行记录、但超过 20 分钟还没有最终结果时，也会推断为 `UNCERTAIN`。建议界面区分“运行超时，状态待确认”和“数据库明确记录了 UNCERTAIN”。



\### 2. 调度状态 `scheduleState`



这与执行状态是两个独立字段。



| 英文状态                 | 建议中文        | 含义                   |

| -------------------- | ----------- | -------------------- |

| `NOT\_DUE`            | 等待计划时间      | 尚未到北京时间 08:30        |

| `DUE\_NOT\_DISPATCHED` | 已到时间 · 尚未启动 | 已过 08:30，但没有成功登记当日任务 |

| `DISPATCHED`         | 今日任务已登记     | 已登记今日研究名额，不代表成功      |

| `DISABLED`           | 自动调度已关闭     | 功能开关关闭               |



例如你今天看到的：



> 已登记每日研究 · 今日已登记派发



实际上代表：



`state=RUNNING` + `scheduleState=DISPATCHED`



更合适的页面显示是：正在研究中 · 今日任务已登记。



当数据库最终结果为 `READY` 时，再显示“研究成功 · 报告已生成”。



另外，代码中还有一些内部状态，例如 `SKIPPED`（本次跳过）、`NOT\_DUE`（尚未到期）、`WAITING\_PUBLIC\_DATA`（等待公共数据采集）。它们是调度函数的返回值，不应该全部混入网页主状态。



\## 二、为什么早上 08:30 会有多个任务？



目前至少有 4 类早间任务，其中 3 类可以从 08:30 开始，另有 1 类在 08:35 执行。



早间任务时间线



北京时间 Asia/Shanghai



08:30



公共机会数据采集



采集市场事实、热点和机会线索



08:30



每日 Codex AI 研究



收集输入、调用模型、验证来源、生成报告



08:30



盘前宏观简报



生成交易日宏观报告，不等同于 Codex 日报



08:35



个性化盘前简报



根据用户持仓、关注和风险信息生成个人报告



08:30 后



晨间机会推送



等待当日研究报告 READY，再根据条件推送



晨间机会推送不是独立固定的 08:30 定时任务，而是轮询等待可用研究报告。上述任务也不保证按所列顺序依次完成。



另外，早上 06:30 还有 `INVESTMENT\_RESEARCH\_REFRESH`（投资研究基础数据更新），这是数据刷新任务，不是 08:30 的 Codex 日报。



因此你看到很多基金历史净值请求，不一定全是每日 AI 研究触发的。Worker 启动时的后台补数据、数据队列任务也可能同时抓取。



\## 三、现在能不能分别关闭？



这是目前最需要改进的地方。



| 功能                | 现有配置                                                   | 目前能否独立关闭   |

| ----------------- | ------------------------------------------------------ | ---------- |

| 08:30 公共机会数据采集    | `ALPHA\_PUBLIC\_ENABLED`                                 | 可以         |

| 08:30 Codex AI 研究 | `DAILY\_RESEARCH\_ENABLED`                               | 与盘前报告共用    |

| 08:30 盘前宏观简报      | `DAILY\_RESEARCH\_ENABLED`                               | 与 AI 研究共用  |

| 08:35 个性化简报       | `DAILY\_RESEARCH\_ENABLED`                               | 与 AI 研究共用  |

| 晨间机会推送            | `DAILY\_RESEARCH\_ENABLED` + `ALPHA\_OPPORTUNITY\_ENABLED` | 不能单独关闭晨间推送 |



具体来说：



`DAILY\_RESEARCH\_ENABLED=false` 是总开关，会同时关闭每日 Codex 研究、08:30 宏观简报、08:35 个性化简报及晨间机会推送。不会关闭由 `ALPHA\_PUBLIC\_ENABLED` 单独启用的公共机会数据采集。



`ALPHA\_OPPORTUNITY\_ENABLED=false` 可以关闭晨间机会推送，但也会停止同一个机会服务中的其他功能，包括 14:30 机会检查和相关跟踪处理，所以不能视为真正的晨间独立开关。



`ALPHA\_PUBLIC\_ENABLED=false` 可以关闭其独立采集循环，但 AI 研究可能仍使用已保存的公共数据，或从其他数据来源采集输入。这不是“关闭所有行情和资料获取”。



盘前简报还有两层控制：数据库中的 `workflow.jobs.is\_enabled` 可以按租户关闭 `PRE\_MARKET` 作业，但会同时影响宏观和个性化两个阶段；个人报告订阅则主要控制消息接收，并不会停止后台生成任务。



所以，目前还不能做到“只关闭 08:30 宏观简报，保留 08:35 个性化简报和每日 AI 研究”这种真正独立的配置。



\## 四、我建议改成真正独立的开关



如果接下来要完善 WealthSail，建议将早间任务拆成以下配置。这部分是修改建议，目前代码还不支持这些新变量。



| 建议新增的配置项                           | 对应中文       | 建议默认值   |

| ---------------------------------- | ---------- | ------- |

| `DAILY\_CODEX\_RESEARCH\_ENABLED`     | 每日 AI 机会研究 | `false` |

| `PRE\_MARKET\_MACRO\_ENABLED`         | 盘前宏观简报     | `false` |

| `PRE\_MARKET\_PERSONALIZED\_ENABLED`  | 个性化盘前简报    | `false` |

| `MORNING\_OPPORTUNITY\_PUSH\_ENABLED` | 晨间机会推送     | `false` |



已有 `ALPHA\_PUBLIC\_ENABLED` 继续管理公共机会数据采集，不需要再引入重复配置。



建议保留当前 `DAILY\_RESEARCH\_ENABLED` 作为兼容总开关，同时在未来版本中允许每项独立覆盖。这样升级时不会因为旧配置改变而突然开启或关闭任务。



\### 推荐的实际使用组合



以你的 WealthSail 投研目标来说，我比较建议：



推荐的早间自动任务配置（设计目标）



08:30 公共机会数据采集



08:30 每日 Codex AI 研究



08:30 盘前宏观简报



08:35 个性化盘前简报



晨间机会推送



这是建议的未来独立配置预览，不会更改现有 NAS 服务。



\&#x20;复制建议配置



如果暂时不改代码，只想在现有部署中关闭晨间机会推送、保留 Codex 每日研究，可以将 Worker 的 `ALPHA\_OPPORTUNITY\_ENABLED=false`，但这会连带关闭其他机会服务，不是完全等价的独立控制。



调整已有环境变量后，需要重建相应容器才能生效；只执行 `restart` 不会重新读取环境文件。修改当天还要注意每日研究补跑和防重复执行机制。



\## 五、页面状态也建议一起优化



目前网页把“研究是否完成”和“今日执行名额是否使用”并排显示，容易造成误解。



我建议新的主界面以 研究执行状态为主，再展示调度状态、开始时间、完成时间、失败原因。对于 `READY` 显示“报告已生成”；对于 `RUNNING` 显示“正在执行”；对于超过执行窗口的记录显示“超时待核实”，而不是继续显示“已登记”。



另外，最好让早间的公共数据采集、Codex 研究、宏观简报、个性化简报分别拥有自己的状态和最近执行记录。这样下次出现 Worker 故障、数据源失败或者 Codex 失败时，一眼就能看出是哪个任务出了问题。



总结：目前英文状态基本够用，主要需要改善中文表达和状态展示；早间任务的核心问题则是 `DAILY\_RESEARCH\_ENABLED` 管了太多不完全相关的功能。建议先把各任务的独立开关、状态和失败原因做清楚，再优化重试和调度可靠性。
