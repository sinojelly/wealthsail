可以省略。 在你使用的 Docker Compose `.env` / `env\_file` 配置中，数字、`true`、`false`、普通 URL 和十六进制 Token 都不需要加单引号。



而且我发现你的配置中有一个更重要的问题：`DAILY\_RESEARCH\_ENABLED` 重复定义了两次，值还互相冲突！



\## 一、引号可以这样省略



以下写法都是正确的：



```

DB\_POOL\_MAX\_SIZE=6

DATA\_TASK\_CONCURRENCY=2

OUTBOX\_DELIVERY\_CONCURRENCY=2



DAILY\_RESEARCH\_ENABLED=true

DAILY\_RESEARCH\_DEBUG\_ENABLED=false

AUTH\_DEV\_MODE=false



CODEX\_RUNNER\_URL=http://codex-runner:8090

CODEX\_RUNNER\_TOKEN=这里保留原来的密钥



CODEX\_TIMEOUT\_SECONDS=90

CODEX\_CHAT\_TIMEOUT\_SECONDS=900



INTRADAY\_TRACKING\_ENABLED=false

FUND\_1430\_ENABLED=false

POST\_MARKET\_REVIEW\_ENABLED=false

```



注意，虽然没有引号，但环境变量传入容器时仍然是字符串。WealthSail 的配置解析器会把 `"6"` 转成整数 `6`，把 `"true"` 转成布尔值 `True`。



\## 二、你现在最大的配置问题



原文件中有：



```

DAILY\_RESEARCH\_ENABLED='true'

```



后面又有：



```

DAILY\_RESEARCH\_ENABLED=false

```



对于 Docker Compose 的这类环境文件，重复变量通常由后面的定义覆盖前面的定义。



所以最终很可能是：



DAILY\_RESEARCH\_ENABLED=false



这就可能解释了你之前看到的 WealthSail “每日研究未启用”。



如果你希望自动执行每天的公共 AI 投资研究，建议只保留：



```

\# 每日公共AI研究

DAILY\_RESEARCH\_ENABLED=true

DAILY\_RESEARCH\_DEBUG\_ENABLED=false



\# 14:30基金估值、买卖点检查和推送

FUND\_1430\_ENABLED=false



\# 15:30盘后复盘

POST\_MARKET\_REVIEW\_ENABLED=false



\# 盘中持仓异动检查

INTRADAY\_TRACKING\_ENABLED=false

```



这里表示只启用每日公共研究，其他三个自动任务仍然关闭。



API 和 Worker 的 `DAILY\_RESEARCH\_ENABLED` 应保持一致。 另外，生产环境不要打开 `DAILY\_RESEARCH\_DEBUG\_ENABLED`。



\## 三、修改后如何生效？



修改以下两个文件：



\- `deployment/env/api.env`

\- `deployment/env/worker.env`



不需要重新编译 Docker 镜像。



执行：



```

sudo "$NAS\_TOOLS/nas-compose" ws config --quiet



sudo "$NAS\_TOOLS/nas-compose" ws up \\

&#x20; -d --no-build --pull never \\

&#x20; --no-deps --force-recreate \\

&#x20; --wait --wait-timeout 180 \\

&#x20; api worker

```



然后检查实际生效的值：



```

for svc in api worker; do

&#x20; echo "===== $svc ====="



&#x20; sudo "$NAS\_TOOLS/nas-compose" ws exec -T "$svc" \\

&#x20;   python -c '

import os

for key in (

&#x20;   "DAILY\_RESEARCH\_ENABLED",

&#x20;   "DAILY\_RESEARCH\_DEBUG\_ENABLED",

&#x20;   "FUND\_1430\_ENABLED",

&#x20;   "POST\_MARKET\_REVIEW\_ENABLED",

&#x20;   "INTRADAY\_TRACKING\_ENABLED",

):

&#x20;   print(key, os.getenv(key))

'

done

```



这样检查的是容器实际生效的环境变量，不是只看文件内容。



注意：如果你开启每日研究且当前已过北京时间 08:30，默认补执行机制可能立即触发研究任务并消耗 Codex 额度。



\## 四、还有一个安全问题需要处理



你刚才贴出了完整的 `CODEX\_RUNNER\_TOKEN`。这是 API、Worker 和 Codex Runner 之间的内部认证密钥。



建议把它视为已暴露并进行轮换。



可以在 NAS 上生成新的密钥：



```

openssl rand -hex 32

```



然后将新值同步写入：



\- `deployment/env/api.env`

\- `deployment/env/worker.env`

\- `deployment/env/codex.env`



随后重新创建 `codex-runner`、`api` 和 `worker`，使三个进程使用同一新密钥。不要将新密钥发到聊天中或提交 Git。



总结：引号都可以去掉，真正需要优先修复的是重复变量。



尤其是 `DAILY\_RESEARCH\_ENABLED`，每个文件中只能保留一个明确的值。你如果打算正式启用每天的 AI 投资分析，就在 API 和 Worker 两个配置文件中统一设置 `DAILY\_RESEARCH\_ENABLED=true`。
