* **报告铁证**：打开 `WealthSail 投研助手10.pdf` 第 4~5 页的 30 只基金扫描总表，你会发现一个自相矛盾的现象：

* `富国中证消费50 008975`：**`已入右侧买区` | `右侧趋势 技术条件待触发**`

* `招商中证白酒 161725`（RSI 53.42）：**`已入右侧买区` | `右侧趋势 · 技术条件待触发**`

* `华宝油气LOF 162411`：**`已入右侧买区` | `右侧趋势 · 技术条件待触发**`



* **代码根因**：在 `actionable_zones.py` 中，右轨（右侧趋势）的买入区间定义为 `[MA20 - 0.35*ATR, MA20 + 0.45*ATR]`。当一只基金处于震荡或下跌趋势时，只要某天净值碰巧跌到 `MA20` 附近，代码算出 `distanceToBuyZonePct == 0`，前端就直接打上了绿色的 **`已入右侧买区`** 标签并排到表格最前面！但实际上它的右侧趋势条件（`MA20 > MA60` 且 `20日动量 > 0`）根本不成立（即 `技术条件待触发`）。


* **改进方案**：
* **右轨（趋势回踩买点）必须以“趋势已成立（`candidate == True`）”为前提**！如果 `rightTrack.candidate == False`（趋势未走好），就算当前价格碰巧在 `MA20` 附近，状态也必须标为 **`趋势未触发（价格近均线）`**，绝不能标为 **`已入右侧买区`**，更不能按“已入买区”排在表格前列误导买入！



##### 2. 【核心漏抓修复】把《财联社早间新闻精选》和《投资日历》按序号拆解为独立原子线索！

##### 3. 【买卖点算法进化】引入「波动率自适应系数」与「止盈风险收益比（R:R）硬约束」

* **现状问题**：检视 `backend/indicators/actionable_zones.py`，目前所有基金共用一套固定的布林带/ATR 乘数，导致部分基金的**潜在涨幅与止损空间不成比例**。例如看总表第 2 页 `南方中证全指证券公司 004069`：


* 最新净值 `1.1190`，建议买入区间 `1.0986 - 1.1230`，止损参考 `1.0718`（向下止损约 **-4.2%**），而止盈目标一 `1.1650`（向上空间仅 **+4.1%**），止盈目标二 `1.1793`（仅 **+5.4%**）！券商作为高弹性品种，盈亏比（Reward-to-Risk Ratio）只有 `1 : 1`，止盈设得太保守（因为近期 MA20 压得太低）。




* **改进方案**：
* 在 `actionable_zones.py` 中加入 **最低盈亏比保护（Minimum R:R Floor）**：左轨低吸策略要求 `T1` 至少满足 $\max(\text{MA20}, \text{EntryMid} + 1.5 \times \text{Risk})$，`T2` 至少满足 $\max(\text{BB\_upper}, \text{EntryMid} + 2.5 \times \text{Risk})$，避免在均线陡峭下跌初期把止盈目标算得比手续费高不了多少。
* **融合 14:30 盘中实时估值（`fund_estimator.py`）**：目前早报的净值基准是周五（10月16日）的收盘净值，但周一早上 08:01 财联社已报出 **“韩国 KOSPI 低开 3.17%，SK 海力士跌逾 4%，三星电子跌超 3%”**。应在卡片上增加一行 **「盘前外盘/盘中实时估值偏离提示」**，在交易日盘中（特别是 14:30 核对点）直接用实时估算净值（`estimated_nav`）去比对买入区间，而不是只看昨晚的静态净值。





##### 4. 【跨日对比修复】按「基金代码 (`targetCode`)」而非 `directionKey` 匹配历史计划

* **报告铁证**：无论在 PDF 10 还是默认版 4 页 PDF 中，全部 14 只基金的 `计划调整` 依然清一色写着：**`首次建立区间。缺少此前同方向可比计划 / 无合格前次动态方向可比`**！


* **代码根因**：在 `daily_research.py` 中，系统是通过 `directionKey` 去关联前一日计划的。而模型每次生成的动态方向 Key（如 `DYNAMIC_CHIP_...`）稍微变两个字母，代码就认为“前次无同方向可比计划”，从而永远触发 `INITIAL（首次建立区间）`！


* **改进方案**：将历史计划对比的主键改为 **`targetCode`（6 位基金代码）**！只要前一日有效报告里出现过 `008281`，今天再出现 `008281`，就直接对比这两天的 `buyZone` 和 `stopLoss`：若区间未变（变化 `< 0.5%`），直接由 Python 后端确定性判定为 **`MAINTAINED（维持关注区间）`**，不再让模型瞎猜“无前次可比”。

#### 维度 B：性能优化、省 Token 与稳定性提升（架构级 Code Review）

##### 1. 省 Token 优化（预计可节省 55% ~ 65% 的 Token 消耗，且大幅加快生成速度）

* **问题诊断（`backend/macro/daily_research.py` & `codex_research.py`）**：


1. **Output Token 严重浪费（重复抄写量化数字）**：目前 `actionable-zones-v3` 的所有数字（最新净值、左轨入场/止损/T1/T2、备选右轨入场/止损/T1/T2、RSI、MA20、ATR 等）明明在调模型前就已经由 Python 算好了，但 Schema 却要求大模型在 JSON 输出里把每只基金的这十几个浮点数和长串技术说明**原封不动重新吐一遍**！这不仅浪费了近一半的 Output Token，还增加了模型填错数字、触发重试的概率。


2. **Input Token 冗余**：`public_packet` 把 30 只基金的全量嵌套字典、未过滤的噪音电报（如《新闻联播》25条、奥地利航空改航线）、以及所有宏观指标的冗长元数据全塞进了 Prompt。




* **优化方案（Thin-LLM Schema 模式）**：
* **让 LLM 只做“推理与选择”，数字由 Python 100% 确定性回填**：模型在 `actionablePlans` 中只需输出 4 个极简字段：`{"targetCode": "008281", "selectedTrack": "LEFT", "positionAdvice": "小额分批", "revisionReason": "一句话理由"}`。Python 拿到模型返回的 `targetCode` 和 `selectedTrack` 后，直接从本地预计算好的 `quant_map[targetCode]` 中把 `latestValue`、`buyZone`、`stopLoss`、`takeProfit1/2`、`alternativeTrack`、`technicalBasis` 毫秒级拼装进去！**仅此一项即可砍掉 50% 的 Output Token，且数字准确率 100%！**



##### 2. 性能优化（将“重新采集并分析”耗时缩短 50% 以上）

* **问题诊断（`daily_sources.py` & `opportunity_market.py`）**：


* 每次运行 `daily_research` 时，多个外部源采集（财联社 15 页分页、国债、Shibor、社融、4 城房价、美联储、台积电等）以及 30 只基金的净值检查存在大量串行 I/O 等待。




* **优化方案**：
* **净值增量水位线跳过（Watermark Skip）**：A 股基金净值每天只更新 1 次（晚间披露当日净值，周末不更新）。在 `opportunity_market.py` 中，先用 1 条 SQL 批量查询候选基金池在 `fund_nav_daily` 中的 `MAX(nav_date)`；如果已经等于最近一个已收盘交易日（例如周末跑的时候发现已经有周五 `10月16日` 的净值），**直接跳过 AKShare 网络请求，0 秒读取本地数据库计算指标**！
* **财联社增量时间戳短路**：分页拉取财联社电报时，一旦发现某页最后一条电报的 `ctime` 早于本地数据库已存的最新电报时间（或早于 24 小时窗口），立即 `break` 停止翻页，无需每次固定爬满 15 页。
