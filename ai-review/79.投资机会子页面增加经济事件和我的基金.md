\## 二、当前界面真正的问题在哪里？



从截图看，不是功能少，而是信息的重要性、详细程度和呈现位置没有匹配。



\### 1. “今日重点”更像一份很长的专业报告



你现在的首屏包含研究运行状态、错误诊断、宏观总纲、PMI 等指标、个人基金表格、方向分析、买卖区间、走势图、来源和技术解释。



它们都有价值，但不应该拥有相同的视觉权重。



当前截图中最值得改善的四处



| 研究错误区域    | 占据大量首屏空间。错误代码、数组索引、研究执行 ID 应放入可展开诊断，首屏保留研究不可用的明确提示。 |

| --------- | --------------------------------------------------- |

| 历史宏观研判    | 一段很长的密集文字，用户难以立刻理解结论。应该提炼为一两句判断，专业数据移到“市场证据”。       |

| 持续跟踪基金    | 横向表格包含大量数据，但缺少直观走势图与状态判断。应该移到“我的基金”。                |

| 价值方向与基金分析 | 同一方向下，每只基金都展开完整价格、图表、说明，导致页面过长。应该先比较机会，再按需展开。       |



尤其要注意截图中的研究失败状态。



2026 年 11 月 4 日的研究显示 `DIRECTION\_INDUSTRY\_REVIEW\_UNKNOWN`，但页面同时展示历史研判与新行情。这不只是美观问题，还关系到用户是否误以为旧研究代表今天的新结论。



建议把研究状态改成一行提示，例如：



今日研究未通过业务校验



当前展示上次有效研究及已更新的独立行情。历史投资建议不代表今日重新确认。



本次运行：11 月 4 日 · 具体失败原因可在研究诊断中查看



真实的风控警报仍须醒目展示，不能为了简洁而一起隐藏。



\### 2. 走势图本身不错，但使用方式不理想



截图中两只军工基金都有直观的净值曲线、买入区间和止损线，这部分是值得保留的。



问题是当前它们嵌套在一张非常长的“投资方向”卡片里。用户必须不停滚动，才能比较不同基金。



另外，例如 024194，截图中的最新确认净值已经更新到 11 月 4 日的 1.1410，但走势图标注的最新点仍是 11 月 3 日的 1.0788。两个数据各有日期，未必是计算错误，但应避免让用户误以为图中的末端就是最新确认净值。



同样，标有“研究时已进入低吸买区”的历史状态，也不应被理解成“当前仍在买区”。



页面应该清楚显示研究时状态、当前价格位置、走势图数据截止日，三者不能混为一谈。

\### 页面 4：市场证据——保留功能，但更加清爽



你当前的“市场证据”比之前已经合理不少，宏观指标有了独立卡片。



不过我认为还可以再简化：首先展示真正影响当前市场判断的几个指标，其他指标按经济类别组织。



建议每张指标卡只保留四个信息：最新数值、变化趋势、经济含义、数据截止时间。



例如制造业 PMI 不是只写 49.3，还应该直接告诉用户“低于 50 的荣枯分界线，表明本期制造业景气偏弱”，再提供走势图和完整来源。



点击“查看完整证据”时，应当在同一位置展开对应曲线，而不是发生布局变化却没有内容的情况。图表要有加载中、数据缺失、错误重试三种清晰状态。



专业研究、数据来源、统计口径以及其他待补充证据可以放在次级区域，不需要默认全部展开。



\## 四、“我的跟踪与复盘”到底有什么用？要不要删除？



我检查了实际的 `StudyTracking.tsx`，它比截图显示的内容丰富得多。



当前代码已经包含冻结研究快照、版本修订、研究条件核验、初始与最新事实比较、MFE/MAE 行情偏移、人工决策、复盘记录以及真实成交关联。



这些功能并不是“持仓基金列表”的重复。



| 功能         | 我的基金 | 研究与复盘    |

| ---------- | ---- | -------- |

| 看当前基金净值    | 主要功能 | 辅助数据     |

| 看走势图和买卖点   | 主要功能 | 查看冻结历史计划 |

| 看本人持仓状态    | 主要功能 | 引用已确认成交  |

| 保存最初投资逻辑   | 查看摘要 | 主要功能     |

| 判断研究是否得到验证 | 显示结果 | 主要功能     |

| 研究修订与版本历史  | 跳转查看 | 主要功能     |

| 记录错误原因和经验  | 查看摘要 | 主要功能     |



所以我建议：



删除“我的跟踪与复盘”这个顶层标签，但保留它的全部业务功能，迁移到“我的基金”里面。



普通用户每天主要查看基金状态；只有需要解释为什么跟踪、为什么买入、为什么没有买、先前判断是否正确时，才进入详细复盘。



这样既不会丢失 WealthSail 已经建立的研究闭环，也不会增加一个日常使用率很低的顶层页面。



\## 五、从代码角度怎样调整最合理？



建议采取渐进式改造，不要推倒现有研究架构。



我读到的前端结构已经有较好的可复用基础：



| 现有模块                    | 建议调整                           |

| ----------------------- | ------------------------------ |

| `MacroContextStrip.tsx` | 改成四个主入口，拆分页面职责，不再把所有内容集中在一个组件里 |

| `MacroOverview`         | 精简摘要，完整宏观数据移动到市场证据             |

| `TrackedFundWatch.tsx`  | 从今日重点移出，升级成“我的基金”汇总视图          |

| `StudyTracking.tsx`     | 保留业务能力，作为基金详情中的研究与复盘区域         |

| `ValueDirections`       | 首页只展示精选方向和重点结论，详细基金图表按需打开      |

| `DailyResearchReport`   | 抽取经济事件内容，避免在多个页面重复整篇日报         |

| `MacroEvidencePanel`    | 保留并改进曲线、来源、数据缺失与展开行为           |



《76.支持经济事件故事叙事.md》也需要修改实施范围。它目前主要围绕重做“今日信息总览”，而现在更合理的是新增独立“经济事件”页面，并让“今日重点”只引用重点事件摘要。



值得保留的核心约束包括：不额外运行一次 Codex、优先复用已核验的事件与传导分析、保留失败状态、不能把旧日报伪装成新研究，以及不改变现有投资风控校验。



\### 推荐实施顺序



第一阶段：重组导航与信息层级



把现有页面拆成四个入口；先把长错误、宏观总纲、持续跟踪表格移至合适位置，压缩今日重点首屏。尽量只调整前端，不改投资核心逻辑。



第二阶段：实现经济事件故事



依据第 76 份方案复用当前 `events`、`channels`、`scenarios`、`sources` 等数据；确有必要才增加少量叙事字段。明确今日新闻、历史新闻和待核实信息的边界。



第三阶段：重做我的基金



复用现有持仓和跟踪接口，按基金聚合展示，把真实走势图、冻结买卖点和动态观察状态放在主要位置；复盘作为二级详情。



第四阶段：兼容与验收



保持旧 URL 深链、历史冻结计划、个人数据隔离、研究权限、卖出风控优先级。专项测试今日研究失败、图表与行情日期不一致、多研究归属同一基金、手机布局与无数据状态。



整个改造应尽量沿用当前后端 API 和既有组件，避免为了页面更好看而重新设计数据库、重新计算买卖区间或增加额外 AI 调用。
