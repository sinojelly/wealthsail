# NAS 独立 PostgreSQL 实施计划与任务清单

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 接入已有 NAS PostgreSQL 18，保留 Web 登录与用户/租户体验，提供可重复的空库安装与管理员初始化。

**Architecture:** 保留现有 FastAPI 自有认证、PostgreSQL RLS 与 Worker。使用 NAS Compose overlay 接入 `global-postgres-network`，为独立 `wealthsail` 库创建两套受限运行登录，通过一次性安装容器管理建库和迁移。

**Tech Stack:** Python 3.12、asyncpg、PostgreSQL 16/18、Docker Compose、现有 React 前端。

**Spec:** `docs/30.NAS独立PostgreSQL部署与身份租户设计.md`

## Global Constraints

- 不修改 NAS 已有 PostgreSQL Compose 或 `prismscore_db` 内容与 ACL。
- 不提交 NAS 管理员密码，不将管理员 DSN 注入 API/Worker。
- 不改写旧 migration，不运行开发样例 seed，不绕过 RLS。
- 保持现有前端页面、认证接口、JWT 与 refresh cookie 协议。
- 生成配置拒绝覆盖；重复 bootstrap 不重置密码。
- 本机无 Docker，明确区分本地通过与 NAS 待验证。

## Review Focus

1. 管理员名是 `admin`、集群没有 `postgres` 角色时仍能完成部署。
2. 角色是集群级对象：目标库不可信或同名角色被其他部署占用时拒绝修改。
3. 密码包含 URI 特殊字符，配置仍正确解析；秘密不进入构建上下文或日志。
4. 首管理员重复/并发初始化不会产生重复租户、任务或密码重置。
5. SMTP/企微关闭时不能创建无法投递的令牌或消耗投递队列；开启后保持旧行为。
