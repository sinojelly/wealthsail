#### 2. `positions` 表结构细节对比（截图 2）

| 对比维度 | 截图中的 `positions` 表 | 最新脚本设计（`migrations/003` 等） |
| :--- | :--- | :--- |
| **所属 Schema** | `public.positions` | 已演进为 `ledger.position_lots` 与 `ledger.position_snapshots` |
| **租户隔离** | **无 `tenant_id`**，仅有可空的 `user_id` | **强制要求 `tenant_id NOT NULL`**，支持多租户与多账户体系 |
| **账户模型** | 缺乏 `account_id`（绑定用户而非具体券商/基金账户） | 关联 `identity.accounts(id)`，支持多账户管理 |
| **标的标识** | 字符串 `symbol`、`asset_name`、`asset_type`、`market` | 规范化外键关联统一标的主数据 `reference.instruments(id)` |
| **持仓计算模型** | **可变状态表**（包含 `avg_cost`, `quantity`, `accumulated_dividends`, `ai_stop_loss`, `ai_take_profit` 等） | **不可变事件驱动账本**（通过 `ledger_events` + `ledger_legs` 记账，持仓/快照为只读派生投影） |
| **风控与论点** | 硬编码止损止盈列（`ai_stop_loss`, `ai_take_profit`） | 解耦至 `risk.investment_policies`、`risk.alert_rules` 与 `research.theses` |
