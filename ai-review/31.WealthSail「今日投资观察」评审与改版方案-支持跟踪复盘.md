# WealthSail「今日投资观察」评审与改版方案

这版有一个明显进步：恢复了顶部可折叠区域，也把宏观事实、每日研究和数据质量集中到同一个入口。方向基本正确。

但它仍然没有实现最重要的目标：

> 用户打开投资机会中心，应该先知道今天最值得关注什么、哪些基金或持仓可能受到影响、下一步需要验证什么，而不是先看到三列宏观指标说明。

我建议保留顶部伸缩栏，但重新设计里面的信息层级；同时保留你提出的每天北京时间 08:30 运行一次 Codex CLI 研究方案，不再要求每小时调用大模型。

## 一、当前界面存在的主要问题

| 问题          | 截图中的表现                       | 改进方向                   |
| ----------- | ---------------------------- | ---------------------- |
| 顶部三列不够有价值   | PMI变化、CPI 0.9%、M2 7.2%       | 改为事件风险、研究机会、持仓影响       |
| 缺少真正的每日研究结果 | 显示「今日尚未研究」                   | 明确任务状态，使用上一份有效报告作为回退   |
| 缺少新闻和国际事件   | 新闻栏主要是国内官方经济公告               | 接入每日 AI 全球事件发现结果       |
| 信息层级仍然不合理   | 首页、新闻页和宏观页重复出现 PMI           | 一条事实只存一次，在不同位置展示不同视角   |
| 技术信息影响阅读    | `0.9000000000%`、大量「未采集」「待核查」 | 数字格式化，数据问题集中管理         |
| 当前方向没有研究结论  | 只有支持依据和缺失条件                  | 增加情景判断、利好与逆风、关联指数及验证条件 |
| 策略区域都是「待核查」 | 七项条件并列，却没有可用的部分结论            | 区分客观观察、策略资格和回测结果       |

其中有两个具体的 UI 问题应该直接修复：

第一，数字格式化。 CPI 显示 `0.9000000000%` 属于明显的呈现问题。宏观同比通常显示一到两位小数即可；底层仍保留完整精度。

第二，「今日尚未研究」不能掩盖上一份有效分析。 假设用户早上 07:00 打开页面，08:30 还没到，可以显示“今日研究计划 08:30 运行”，但同时应展示昨天或最近一次已经验证的研究结论，并清楚标注时间。不能让整个投资情报区变成空白。

### 为什么截图显示「今日尚未研究」？

截图的时间是 2026 年 10 月 17 日 00:28，而计划运行时间是 当天 08:30（北京时间）。

所以，这个状态在当时是合理的，不能据此判断调度失败。

但还有两个条件：

第一，08:30 时研究服务必须运行。 当前任务在 `macro_worker` 中执行。如果只启动 API 和前端，或者用了跳过宏观 Worker 的启动方式，就没有消费者执行每日研究。

第二，晚启动补跑有明确前提。 如果当天尚未创建执行记录，且启用了补跑，Worker 在 08:30 之后启动时会尝试补跑。如果当天已经执行过，即使失败，也不会再次发送 Codex 请求。

目前数据库中的状态大致分为：

| 状态          | 实际含义          | 建议向用户展示         |
| ----------- | ------------- | --------------- |
| `NOT_RUN`   | 当天尚未登记研究执行    | 今日 08:30 待研究    |
| `RUNNING`   | 已登记任务，尚无终态    | 研究执行中           |
| `READY`     | 当日报告已经验证并保存   | 今日研究已完成         |
| `FAILED`    | 执行失败          | 今日研究失败，展示最近有效报告 |
| `UNCERTAIN` | 结果不能确定，例如执行超时 | 结果待确认，不自动重试     |
| `STALE`     | 目前只有历史日报      | 展示最近有效日报及日期     |
| `DISABLED`  | 功能未启用         | 自动研究未启用         |

这里我建议再修正一个重要交互：

「概览生成时间」不是「每日 AI 研究完成时间」。

现在页面展示 `2026-10-17 00:28`，容易让人以为系统已经在 00:28 做过新闻分析。实际上这是页面研究摘要的生成时间，不代表 Codex 运行过。

建议顶部明确显示：

`最近有效研究：10月16日 08:34｜下次研究：10月17日 08:30`

如果没有历史日报，就显示：

`尚无有效日报｜计划 08:30 首次研究`

这里的完成时间必须使用数据库真实记录，而不是推测。

### 对补跑机制，我建议保持“同日最多一轮”，但增加运行保障

当前「失败后当天不重发」适合控制成本，不过也意味着 CLI 启动失败可能使当天无法得到报告。

推荐采用更细的状态区分：

模型调用前失败（例如采集任务失败、CLI 未登录）：可以由系统修复后重新进入待执行状态，但必须确认从未发送模型请求。

模型已启动或执行结果未知：不自动再次调用，防止双重消耗。

模型成功、校验失败：保留原始失败状态和校验错误，不修改为成功；是否允许人工重跑，应有显式审批和每日成本上限。

这是下一版可以增加的可靠性优化，不建议当前直接删除数据库唯一约束或在失败时盲目重试。

## 三、顶部应该展示什么？我建议从“三个指标”改成“四类投资关注”

你说“多列、多行都可以，但要有价值、有逻辑”，我完全赞同。

我不建议固定为三列，更不建议把三条宏观数据硬塞满。建议按照用户需要采取的研究行动分类，最多显示四类，每类最多两条，数量不足就不强行补满。

这只是布局示意。真正的首页应根据当天事项动态调整顺序。比如：

- 有已确认的持仓风险超限，持仓风险排第一；
- 发生重大国际能源冲击，即使用户当前研究的是A股宽基，也应该显示其全球影响；
- 出现已验证的指数趋势变化，机会研究应获得更高展示优先级；
- 如果没有任何机会候选，清楚说明，而不是用 CPI、M2 填充“机会”栏目。

### 首页还应有一句真正有用的总结

不是：

“制造业 PMI 50.1，CPI 0.9%，M2 7.2%。”

而是类似：

> 市场研究摘要： 增长端出现有限改善迹象；能源和利率条件需要结合最新事件继续评估；A股宽基的估值与技术条件尚未完整验证，当前不形成基金建仓结论。

这句话应是系统根据实际可用证据生成的结论。它可以不预测涨跌，但必须体现什么变了、为什么值得关注、当前能判断到什么程度。

## 四、你目前的分类还要再调整一次

现在展开后是：

`新闻与推理｜宏观指标｜当前方向｜数据质量`

这个结构已经比以前的多个弹窗好，但仍然有一个问题：前三项按数据来源或系统模块命名，最后一项却是运维概念。

我建议统一成四个直接服务投资研究的分类：

| 一级分类    | 重点展示什么                   | 用户想解决的问题         |
| ------- | ------------------------ | ---------------- |
| 重大事件与情景 | 国际新闻、政策、战争、能源、事件关联、反方情景  | 有什么事情正在改变市场环境？   |
| 宏观与市场证据 | CPI、PMI、信用、利率、油价、指数价格与风险 | 哪些变化已被真实数据支持？    |
| 投资方向与基金 | 支持因素、逆风、估值、趋势、ETF候选      | 哪些投资方向值得进一步研究？   |
| 跟踪与复盘   | 研究假设、验证条件、提醒、投资决策和历史结果   | 当初为什么关注？后来判断对不对？ |

而\*\*「数据质量」不建议继续占一个平级的大标签页\*\*。

它可以成为研究证据右上角的「数据状态」入口，集中查看来源、缺口、采集失败和更新时间。管理员再进入运维页面。

### 各分类内部也要继续清理

目前“新闻与推理”实际组合了每日 AI 报告、官方关键事件以及普通重要变化，容易重复。应该按事件 ID 聚合，一件事只生成一条主事件卡片，下面挂不同来源及更新。

“宏观与市场证据”不要继续让 10 张数据卡片默认全部展开。应先显示当前研究方向最重要的 4—6 个指标，其他指标按增长、通胀、利率信用、全球风险归类。

“投资方向与基金”最需要补强的是：指数的客观技术状态和估值、相关基金质量，以及哪些研究条件已经满足、哪些确实不满足、哪些无法核验。三种状态必须分开。

“跟踪与复盘”则是当前最值得新增的长期能力，下面会重点说明。

## 五、代码中还有两个导致“重要新闻被淹没”的具体问题

我检查了 `backend/macro/daily_research.py` 的 `build_research_overview()`。

### 1. 普通宏观变化和重大事件目前存在排序竞争

当前投影使用数字优先级选取最多三条重点。部分宏观变化和模型日报中的重要事件使用相同的优先级。

由于宏观事项先加入候选，后续使用稳定排序，当优先级相同时，已有宏观事项可能排在重大新闻前面。

这与截图里顶部被 PMI、CPI、M2 占满的现象一致。

建议改成先按业务类别确定展示名额，再在类别内排序。

例如：

`已确认个人风险 > 重大跨市场事件 > 经验证的研究机会 > 重要市场条件变化 > 普通指标观察`

但这不是绝对的机械顺序。是否影响当前持仓、潜在冲击大小、证据质量和时效性也应参与判断。

这样普通 CPI 数值更新就不会因为“有数据”而自动抢占重大事件的位置。

### 2. 全球重要新闻可能因“当前方向不匹配”被过滤

当前事件投影中存在这样的逻辑：

```
if direction_id and related and direction_id not in related:    continue
```

如果当前选择是「A股·宽基」，某件重大能源事件只被映射到「能源」和「海外市场」，它便可能无法进入首页。

这在方向专题内部是合理的，在全球重大事件首页却不合理。

建议采用两个独立结果集：

全局重要事件：按事件本身的重要程度展示，不依赖当前所选指数。

当前方向相关事件：只保留真正与当前市场、行业、指数有关的事件。

首页融合两者，去重后排序。事件详情再说明为什么和用户当前持仓或研究方向有关。

这样才能避免“系统其实已经发现了新闻，但首页因为分类过滤而没有展示”。

## 六、每日一次 Codex CLI，怎样兼顾研究质量和低成本？

我建议继续使用当前的 Codex CLI 实现，不引入第二套大模型任务系统。

不过，应将原来的“直接要求模型全面搜索”改成更节省成本的方式：

程序先准备高质量资料包 → Codex 一次性综合研究 → 程序校验并保存结构化结果 → 前端反复使用缓存。

### 如何进一步减少 Token？

现在的提示词已经包含国内增长、信用、美国利率、能源航运、地缘政治、全球权益和未来日历等主题，这个方向合理。

但可以进一步优化输入：

| 输入内容  | 推荐做法                         |
| ----- | ---------------------------- |
| 原始新闻  | 程序先去重、聚类，模型只看重要候选与来源摘要       |
| 上一次报告 | 不传整篇长报告，只传未结束的事件和待验证假设       |
| 宏观数据  | 传最新值、变化、参考线和数据时间，不传全部历史序列    |
| 市场数据  | 传预先计算好的涨跌、趋势、波动及风险指标         |
| 新闻检索  | 以预收集资料为主，只允许模型补充少量关键遗漏       |
| 输出内容  | 限制事件数量、每条字数，使用固定 JSON Schema |
| 缓存    | 按日期和输入哈希保存，页面只读数据库           |

尤其要避免让大模型重新计算 CPI 环比变化、MA200、收益率分位或基金交易费用。这些适合用程序计算。

大模型最应该花算力的部分是：哪些事件值得关注、事件之间有什么关系、可能通过什么渠道影响资产、哪些观点与证据存在矛盾。

### 当前每日研究接口还有一个值得注意的限制

现在 `_Report` 最多允许 12 个事件、16 个来源、12 项未来日程，来源核验也有数量上限。

这些上限有助于控制执行时间和费用，但当全球有多件重大事件时，16 个来源可能比较紧张。

我的建议不是无限放宽，而是分开两个概念：

内部候选池： 可以由廉价采集程序保存更多候选和来源。

模型研究输出： 仍然限制在经过筛选的重点事件，比如最多 6—10 条重大事件；其余新闻保存检索索引，不必让模型逐条写长篇分析。

对于重大或存在争议的事件，尽量保留原始官方依据及独立媒体交叉证据。不能仅为了减少 Token 而省掉关键核验步骤。

### 推荐的一次性提示词结构

你现在的 `build_prompt()` 可以逐步升级成这样的结构。这里展示的是核心任务说明，实际运行还应附带当前已有的 JSON Schema 和经过筛选的公共资料包。

```
任务：生成 WealthSail 每日全球市场与基金投资研究。

时点：北京时间今天 08:30。
仅使用在研究时点已公开、可核验的信息。

研究目标：
找到真正可能影响市场、指数、基金及风险的重大变化。
优先发现被普通宏观数据摘要遗漏的跨国事件。

必须覆盖：
1. 战争、地缘政治、国际贸易、制裁和重大政策。
2. 原油、柴油、天然气、航运与供应链。
3. 美国通胀、就业、美联储、国债实际利率。
4. 中国增长、信贷、流动性、企业盈利与政策。
5. 全球权益市场、科技估值和风险偏好。
6. 未来7天重要官方日程。

先利用输入资料，必要时进行有限的补充检索。
按事件聚类去重，不按文章逐条生成研究。

每个重要事件输出：
- 事件名称、时间、当前阶段
- 已确认事实与来源
- 为什么重要
- 从事件到经济变量再到资产价格的传导链
- 潜在受益方向、潜在承压方向
- 反方情景和无法确认的信息
- 哪些实际数据可以验证判断
- 相关市场、指数及基金类别
- 相对上次研究有什么实质变化
- 建议继续跟踪的条件

禁止：
- 将传闻当成事实
- 将政策宣布当成实际执行
- 将价格同步变化直接当成因果关系
- 生成未经验证的涨跌概率或买卖指令
- 填补缺失的价格、估值、成交及持仓数据

输出：
仅按约定JSON Schema输出。
先给重要事项，再给依据和解释。
找不到可靠事件时明确说明，不凑数量。
```

还有一个隐私边界建议保留：这次 Codex 公共研究只处理公开市场信息，不传入用户账户、个人持仓或交易记录。

公共报告保存后，由 WealthSail 在自己的服务端使用持仓数据确定性地计算相关性和风险敞口。这既省成本，也减少个人信息流向外部模型的风险。

## 七、最值得新增的能力：把新闻变成可持续验证的「投资研究链」

这是我认为你这次提出的最有价值的新要求。

目前的每日研究可以生成：

`事件 → 可能影响 → 待核查事项`

但它还不是完整的研究闭环。

真正有价值的系统应该能够记住：

当初为什么认为这个事件重要？当时预计会影响什么？依据是什么？后来发生了什么？哪些判断正确，哪些错误？

我建议建立一个长期保存的 Investment Thesis（投资研究假设）。

### 一个研究链条应该包含什么？

以能源供给扰动为情景示例：

研究主题：能源供应冲击

研究记录示意

事件事实

政策变化、航运中断、实际供应量变化及可靠来源。

经济传导假设

供应减少 → 柴油或原油价格上升 → 运输成本和通胀压力变化。

资产影响假设

上游能源利润可能受益；部分下游企业成本承压；实际利率和成长估值可能受到影响。

需要验证的条件

油价、库存、运费、通胀预期、利率、行业盈利及指数价格是否出现符合假设的变化？

后续跟踪与研究结论

哪些证据增强或削弱了假设？是否需要修改研究观点？

复盘

与最初判断相比，实际结果如何？错误来自事实、传导、时机、估值，还是执行？

这条链不能仅存成一段 AI 生成文字。

应该拆成有稳定 ID 和版本的结构化记录，并且旧判断不能被新判断覆盖。

### 需要保存的核心数据

| 记录对象                  | 核心字段                      |
| --------------------- | ------------------------- |
| `ResearchEvent`       | 事件ID、标题、状态、首次发现、最近更新、来源   |
| `ResearchEvidence`    | 事实、原始URL、发布时间、获取时间、核验状态   |
| `ResearchHypothesis`  | 假设ID、事件ID、经济传导、适用范围、支持与反方 |
| `ResearchScenario`    | 条件、可能影响、失效条件、待观测指标        |
| `ResearchExposure`    | 关联市场、行业、指数、基金及关联理由        |
| `ResearchObservation` | 某个时间点的实际指标、价格和风险数据        |
| `ResearchRevision`    | 前后研究结论、变更原因、模型与方法版本       |
| `InvestmentDecision`  | 用户当时选择关注、买入、卖出、持有或忽略的原因   |
| `ResearchReview`      | 事后结果、对照基准、错误分类、改进经验       |

尤其应当分别保存：

`事件确实发生`、`事件可能造成某种影响`、`该影响已得到数据支持`。

三者不能使用同一个“事实已核验”状态。

## 八、让系统真正具有跟踪和复盘能力

我建议增加一个轻量的「我的研究」功能，而不是又做一个复杂的弹窗中心。

用户看到某条有价值的事件或投资假设时，可以点击：

加入跟踪

这一个操作就够了。系统自动保存研究主题、相关指数、当时证据和下一步验证条件。

### 跟踪状态应该简单

| 状态   | 含义               |
| ---- | ---------------- |
| 观察中  | 假设已建立，等待条件变化     |
| 证据增强 | 新事实进一步支持原假设      |
| 证据减弱 | 反方因素出现或支持证据减弱    |
| 条件触发 | 明确的预设指标或策略条件发生变化 |
| 假设失效 | 预先定义的失效条件满足      |
| 已结束  | 用户停止研究或研究期限结束    |

这里要避免让 AI 每天重新改写一个全新的结论。

例如，10 月 17 日建立了能源供应紧张的假设，那么 10 月 18 日应当优先问：

“昨天关注的运输中断有无新证据？实际供应量改变了吗？油价和预期有没有变化？哪个结论需要更新？”

而不是把昨天的研究完全忘掉。

### 如何复盘投资经验？

这一点建议分成两种不同的复盘。

第一种：研究判断复盘。

即使用户没有实际买基金，也可以判断原研究是否有价值。

例如，之前认为能源价格上升可能增加运输业成本，事后检查实际燃料价格、行业利润率和相关指数表现。

但应把当时的研究预期、观察期限和失效条件冻结保存，避免事后选择有利的数据解释。

第二种：实际投资决策复盘。

如果用户后来购买了一只基金，则要将真实交易记录关联到当时的研究版本。

应记录：买卖时间、价格、费用、基金、数量、交易原因、风险预算以及计划与实际执行的差异。

事后不仅要看收益率，还应比较同期基准指数、持有期间最大回撤、机会成本和是否遵守最初规则。

### 最有价值的复盘结果是什么？

不是简单告诉用户“这次赚了”或“这次亏了”。

而是把错误分成具体类别：

| 错误类型     | 示例                    |
| -------- | --------------------- |
| 事实判断错误   | 原始事件信息不准确             |
| 经济传导错误   | 供给变化没有产生预想中的价格影响      |
| 市场预期判断错误 | 事实发生了，但市场早已提前定价       |
| 标的选择错误   | 看对行业，却选择了跟踪或成本较差的基金   |
| 择时错误     | 看对长期方向，但买入时估值或趋势条件不合理 |
| 风险管理错误   | 仓位过高、相关性过强、缺少风险预算     |
| 执行纪律错误   | 临时改变规则、情绪化追涨杀跌        |

这套复盘数据长期积累，价值可能超过再增加几十个技术指标。

因为 WealthSail 可以逐步回答：哪类事件研究对你的投资方式最有帮助？什么条件下容易误判？哪些择时规则经过真实样本验证确有价值？

### 一个特别需要改的地方：把“研究机会”分级

现在系统对“建仓资格”要求很严格。这是正确的，但不应因此抹去所有较早阶段的研究价值。

我建议在系统中区分：

| 研究阶段       | 是否可以展示             |
| ---------- | ------------------ |
| 全球重要事件     | 已经有可靠来源即可展示        |
| 投资方向线索     | 有明确传导假设和证据即可展示     |
| 指数研究候选     | 需要估值、盈利、趋势和风险等适用证据 |
| 基金工具候选     | 需要费用、跟踪和交易条件       |
| 可考虑执行的策略条件 | 需要预设规则、有效验证和个人风险检查 |

这能解决现在的主要矛盾：

尚未形成买点，不代表没有值得研究的机会；但有研究机会，也绝不代表已经出现可靠买点。

## 十、建议的最终用户使用流程

我希望 WealthSail 最终变成这样的体验：

早上打开页面： 用户只需要看顶部“今日投资观察”，30 秒了解重要事件、研究线索和已有持仓风险。

看到关心的事件： 展开“重大事件与情景”，直接看到已确认事实、经济传导、受益与承压方向、反方情景，以及下一步要验证的指标。

想研究基金： 点击相关方向，直接联动下面已有的指数与基金筛选工作台，查看估值、趋势、产品质量和风险。

认为值得持续观察： 点击“加入跟踪”，系统保存当时完整研究假设，之后通过确定性条件判断记录实际变化。

之后复盘： 回看最初的事实与假设、什么时候验证、为什么采取投资行动、实际结果以及哪些判断失误。

不需要每天逐一打开四个标签，也不需要每次看页面都调用 AI。

### 最后建议的验收标准

我会要求开发工具至少通过以下场景：

| 场景                         | 正确结果               |
| -------------------------- | ------------------ |
| 00:28 打开页面，08:30 尚未到       | 显示下一次研究时间，保留最近有效日报 |
| 08:30 Worker 正常运行          | 当天只登记一次 Codex 研究   |
| 08:30 Worker 未启动，10:00 才启动 | 未消费时补跑当天一次         |
| 当天 Codex 已经启动但超时           | 不盲目再次发送请求          |
| 重要地缘政治新闻与A股宽基标签不直接匹配       | 仍能在全球重要事件中出现       |
| 有重要事件和普通 CPI 更新            | 重要事件优先，CPI 留在证据区   |
| 新闻仅为政策宣布                   | 不写成已经执行或实际交付       |
| 事件有潜在受益行业                  | 只形成研究线索，不自动生成买入信号  |
| 用户加入一个研究主题                 | 保存完整原始假设、来源和研究时间   |
| 后续指标与原假设相反                 | 标记证据减弱或假设失效，不覆盖旧记录 |
| 用户实际交易                     | 关联当时研究版本，用真实交易结果复盘 |
| 浏览器反复刷新、切换分类               | 不增加任何模型调用          |

## 我的最终建议

我认为你现在提出的方向已经可以作为 WealthSail 投资研究能力的长期主线，不需要再反复改变整个产品布局。

这一次最值得做的不是再增加界面，而是完成三个关键升级：

第一，今日投资观察从“宏观指标摘要”改为“风险、机会、持仓、重大事件”的高价值摘要。 让国际事件有机会出现在首页，普通数据更新不再自动占满版面。

第二，把每日 Codex 研究从“生成新闻总结”升级为“持续跟踪事件、假设、传导和验证条件”。 仍然每天 08:30 一轮，低频调用，通过优质输入和结构化输出提高研究质量。

第三，建立可追溯的投资研究记录和复盘机制。 让系统不只是每天告诉你它今天怎么看市场，还能长期检验自己过去怎么看、哪些判断有依据、哪些失败、原因是什么。

这三件事一旦做好，WealthSail 才真正从基金筛选页面，升级为一个能够积累研究经验、持续改进投资决策的智能投资工作台。
