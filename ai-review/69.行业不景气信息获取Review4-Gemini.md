\#### 1. 【必改 P1】防止“张冠李戴”：核验风险引文是否真的属于当前被审查的赛道 (`industry\_cycle.py` \& `daily\_research.py`)

\* 当 `expected\_industries` 传入时，检查引文或标题是否命中当前行业的关键词（或未出现其他互斥行业的专属词）：

\#### 2. 【必改 P2】わずか 1 行代码的逻辑修正：禁止用“融资降温/砍单”把成熟行业强行打成“商业化早期” (`industry\_cycle.py:553`)



\* \*\*问题所在（68号文档 P2）\*\*：

看 `industry\_cycle.py` 第 553–556 行：





```python

if stage == "EARLY\_COMMERCIALIZATION" and not (

&#x20;   stage\_kinds or confirmed\_flags or suspected\_flags

):

&#x20;   stage = "UNKNOWN"



```





这意味着：如果一个\*\*已经大规模量产的成熟行业\*\*（如白酒、煤炭、成熟消费电子）出现了 `ORDER\_CUTS`（下游砍单，属于 `confirmed\_flags`），而模型把 `stage` 填成了 `EARLY\_COMMERCIALIZATION`，代码会因为 `confirmed\_flags` 非空而放行，把这个成熟行业在前端标成 \*\*`🟠 商业化早期·去伪存真期`\*\*！





\* \*\*最简修复方案\*\*：

直接把第 553–556 行改为：

```python

if stage == "EARLY\_COMMERCIALIZATION" and not stage\_kinds:

&#x20;   stage = "UNKNOWN"



```





这样：只有真正具备 `COMMERCIALIZATION\_EARLY` / `EARNINGS\_NOT\_DELIVERED` 原文实证的行业才能标为 `商业化早期`；而成熟行业遇到砍单/融资降温时，阶段保持 `UNKNOWN`（或原有的政策/其他阶段），同时 `riskLevel` 依然照常触发 `CONFIRMED` / `SUSPECTED` 风控折价，真正做到“产业成熟度”与“行业风险度”完全解耦。







\#### 3. 【顺手改进】消除 `researchStatus: "COMPLETE"` 的状态歧义 (`industry\_cycle.py:570`)



\* \*\*问题所在\*\*：68 号文档提到，当 `searchExecutionVerified=False` 且 5 项核查存在 `evidenceGaps` 时，返回 `"researchStatus": "COMPLETE"` 容易让人误以为外部搜索证据已经 100% 完备。





\* \*\*修复方案\*\*：保持向后兼容的同时，增加明確的 `"auditStructureStatus": "COMPLETE"`，或将说明细化，并在前端 `IndustryCycle.tsx` 中确保不把 `researchStatus` 渲染成“外部搜索已完备”。
