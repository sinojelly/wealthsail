# WealthSail 基金筛选实施计划评审与 UI 优化方案

结论：计划可以继续使用，但建议调整后再实施

我已阅读你指定的文件：

`ai-review/18.WealthSail-基金筛选页面功能扩展实施计划.md`

同时对照了 `docs/23`、`docs/24`、现有基金筛选 React 页面、相关后端 API、数据表以及宏观报告代码。

我的判断：这是一份工程实施质量较好的计划，但目前更像“基金数据筛选 + 技术指标分析”的开发计划，而不是完整的“宏观经济 → 投资方向 → 基金选择 → 买卖决策”产品设计。

两者的差异很重要。

如果直接按照现有计划开发，能够得到一个比较专业的基金筛选器；但用户仍然需要自己分析宏观经济，再手动判断应该筛选什么方向。

而你的真正目标应当是：

> 打开 WealthSail，自动了解当前经济环境，看到哪些投资方向值得研究，再选择方向、指数和具体基金，最后判断价格趋势、风险与买卖时机。

我建议保留现有计划中大部分技术架构与验收设计，重点调整产品结构、页面交互、宏观数据衔接以及实施顺序。

## 一、现有实施计划评价

| 评价维度        | 判断   | 原因                                   |
| ----------- | ---- | ------------------------------------ |
| 整体技术架构      | 很合适  | 继续复用 FastAPI、React、PostgreSQL、Worker |
| 数据质量与金融严谨性  | 很合适  | 注意复权、来源版本、历史可得性、缺失状态                 |
| 技术指标设计      | 基本合适 | MACD、KDJ、MA、RSI 的计算规则明确              |
| 自动化采集与更新    | 基础较好 | 有异步任务、批次、重试与监控设计                     |
| 基金筛选交互      | 需要优化 | 主要依靠用户主动输入筛选条件                       |
| 宏观经济与投资方向联动 | 明显不足 | 宏观周期模型被推迟到后续阶段                       |
| 基金质量与估值比较   | 不足   | 首版主要考察价格和技术状态                        |
| 投资决策体验      | 不完整  | 尚未形成方向、基金、择时的连续分析链路                  |

现有计划中我尤其赞成三项设计：

一是明确区分“净值区间位置”和“真正的估值分位”，避免将低净值误判为低估。

二是将指标计算独立于数据库、HTTP 和 AI，保证 MACD、KDJ 等计算可测试、可复现。

三是所有评分、研究数据都有来源和版本，缺失数据不假装成有效信号。这些应该保留。

最重要的调整是：不再以“基金列表”为页面的唯一中心，而是以“发现投资机会的完整过程”为中心。

## 二、当前设计和我建议的设计有何区别？

### 现有计划中的页面

按照第 4.1 节，它大致是：

基金筛选

研究覆盖数量 · 数据更新时间 · 评分覆盖率

筛选条件

搜索基金名称或代码

基金类型

交易形态

投资方向

跟踪指数

技术状态

历史位置

基金结果表

名称 · 净值 · 趋势分 · 数据质量 · 排序

点击任意基金 → 展开右侧技术诊断

这个结构适合已经知道自己要研究哪一类基金的人。

但对尚未确定投资方向的用户，并不够友好。比如：

- 目前应该优先关注权益、债券还是黄金？
- 如果考虑权益，A股、港股、美股哪个方向更值得研究？
- 看好中国权益以后，是宽基、红利、成长还是某个行业？
- 确定一个指数后，哪只 ETF 的费用、跟踪和交易成本更有优势？
- 这只 ETF 长期值得持有，但现在是不是一个合适的建仓位置？

现有计划能处理其中一部分，但缺乏贯穿全程的 UI 引导。

### 我建议的结构

① 宏观经济环境

经济增长 · 通胀 · 流动性 · 风险环境

② 资产与投资方向

权益 / 债券 / 黄金 → 国家 → 宽基 / 风格 / 行业

③ 指数和具体基金

指数比较 → ETF / 场外基金 → 成本与质量

④ 买卖时机和风险

趋势 · 技术信号 · 历史验证 · 仓位约束

核心是：上层选择可以自动带出下层内容；下层保留独立搜索和自由筛选能力。

不应强迫用户必须依次点击四步才能找到自己关心的基金。

## 三、我建议的基金筛选 UI：宏观、方向、指数、基金都在一个工作台里

这应该是一个有层次、能联动、但不复杂的页面。不建议把宏观分析、投资方向和基金列表拆成三个完全独立的系统，让用户来回跳转。

下面是我推荐的交互原型。它是界面设计示意，不是 WealthSail 当前运行页面。

这个原型体现了一个关键特性：你点击某个投资方向后，下方相关指数和基金候选随之改变。正式版还要在选择某个指数时，只比较跟踪该指数的基金，避免把完全不同的产品混在一起排名。

### 1. 页面顶部：宏观经济只展示决策需要的信息

不要在基金页面顶部放几十个经济数据图表。

首屏可以浓缩为四个维度：增长、通胀、流动性、风险。每个维度展示最新值、相对于前期的变化、数据日期和简短解释。点击后再查看历史曲线和数据依据。

例如，未来若有可靠数据发现增长边际改善、流动性宽松，可以显示与权益资产有关的研究情景。但必须同时解释估值、市场风险和反方情景，不能机械地产生“宏观向好，立即买股票”的结论。

现在 WealthSail 已经有一个很好的起点：`backend/integrations/market_data.py` 中的 `fetch_economic_calendar()` 会通过 AKShare 获取最新一期中国 CPI 和制造业 PMI，`backend/reports/pre_market_macro.py` 将其用于盘前宏观简报。

但当前主要是单期快照与文本摘要，尚不能直接作为完整经济周期模型。 需要进一步保存历史序列和原始发布时间，并扩展利率、信用、盈利等数据。

### 2. 页面中部：投资方向应该是核心导航

我认为这是实施计划最需要补强的地方。

不要只是一个“投资方向”下拉筛选框。应让每个方向都有自己的研究概览，至少呈现：

| 内容      | 用户需要看见什么                  |
| ------- | ------------------------- |
| 方向名称    | 中国宽基、成长、红利、港股、美国权益、债券、黄金等 |
| 主要驱动    | 该方向受哪些宏观与基本面因素影响          |
| 中期趋势    | 相关代表指数的趋势变化               |
| 估值或资产定价 | 与该资产适用的估值、收益率或风险指标        |
| 主要风险    | 哪些情景可能推翻当前逻辑              |
| 相关指数    | 可进入哪几个指数的研究页面             |
| 数据状态    | 结论是否有足够数据支持               |

方向不应该只被贴上“利好”“利空”的标签；有时宏观数据彼此矛盾，最合适的结论就是“暂不明确”。

而且，应允许用户手动选择任何方向，不受系统宏观判断限制。

### 3. 第三层：先选指数，再选基金

这一步我认为比 ETF 技术评分排行榜还重要。

例如，用户选中“中国宽基”，看到沪深300、中证A500、中证500等不同指数，先比较指数本身的风险、风格、估值及趋势。

选择沪深300之后，再比较跟踪该指数的具体 ETF 和场外指数基金。

这是两个不同的问题：

指数选择决定主要承担什么市场风险；基金选择决定以怎样的费用、跟踪效果、流动性和交易方式获得该风险敞口。

如果仅按 ETF 的 MACD 排名，同一个指数下的 ETF 往往得到极其相似的技术结果，却无法解释哪只 ETF 更值得购买。

因此，技术指标建议以指数作为主要趋势分析对象，同时检查 ETF 自身的价格走势、折溢价和交易流动性。真正评价同指数基金时，重点比较费用、跟踪质量、规模和执行成本。

### 4. 第四层：基金详情不是数据罗列，而是决策解释

建议诊断抽屉分成四个页签：

| 页签   | 主要内容                     |
| ---- | ------------------------ |
| 综合判断 | 长期配置研究状态、近期技术状态、风险和数据质量  |
| 趋势分析 | K线或净值、MA、MACD、KDJ、RSI、动量 |
| 基金质量 | 跟踪指数、费用、跟踪误差、规模、流动性、折溢价  |
| 策略验证 | 后续接入回测、基准比较和历史信号分析       |

首屏不要一次性展开所有技术指标，否则对非专业用户非常不友好。

尤其要保留三个独立结论：长期配置价值、近期技术状态、当前组合可承担的风险。其中没有被可靠计算的部分，直接展示“尚未评估”。

## 四、实施计划建议做哪些具体调整？

我建议直接以现有第 18 号计划为基础修改，不另起一份完全不同的实施计划。

### 调整 1：修改第 1 节，明确完整产品目标

原目标是：

> 将现有基金筛选页面升级为具备组合筛选、可靠技术状态排名和单基金诊断的研究入口。

建议改成：

> 将 WealthSail 基金筛选入口升级为覆盖“宏观经济观察—投资方向发现—指数比较—基金筛选—技术择时—风险复核”的一体化投资研究工作台。系统自动更新可验证的市场事实和指标，以分层联动、可解释结论及可追溯证据帮助用户决策，同时保留基金直接搜索和高级条件筛选。

这会影响后面的页面结构、数据模型和 API，而不只是修改标题。

### 调整 2：修改第 4 节，采用三层页面、四级研究路径

我建议保留 `/fund-screener` 原路由和兼容入口，但菜单名称可以升级为“投资机会”或“投资研究”。

桌面端页面分为三个主要区域：

| 页面区域      | 主要内容                  | 交互方式       |
| --------- | --------------------- | ---------- |
| 上：宏观环境摘要  | 当前经济观察、增长/通胀/流动性、风险提示 | 点击查看依据和历史  |
| 中：投资方向探索  | 大类资产、市场、风格、行业、相关指数    | 选择后联动下方    |
| 下：基金筛选与比较 | 基金搜索、列表、评分、比较、诊断      | 排序、过滤、进入详情 |

底层研究路径再按资产 → 方向 → 指数 → 基金逐步下钻。

在手机上，顶部宏观区域应压缩成简要摘要，投资方向使用横向可滚动选项，基金列表改成更简洁的行或卡片，诊断使用全屏面板。

此外，直接搜索基金必须始终可用，不能因为引入宏观和方向步骤，让熟悉基金代码的用户操作变慢。

### 调整 3：修改第 5.1 节，建立真正的“投资方向”数据模型

目前计划中的 `reference.fund_research_profiles` 有一个 `direction` 字段。这个设计不够灵活。

例如，一只指数基金可能同时属于：

中国权益 → 宽基 → 大盘 → 价值风格。

又例如，科技成长基金既属于成长风格，也属于科技行业，还可能覆盖多个市场。

因此方向与指数、基金不能只使用简单的一对一关系。

建议增加如下逻辑实体：

| 逻辑实体                           | 作用                       |
| ------------------------------ | ------------------------ |
| `research_directions`          | 管理权益、债券、黄金、市场、风格、行业等方向分类 |
| `direction_index_links`        | 维护方向与指数的多对多关系            |
| `fund_index_links`             | 沿用原计划，关联基金、跟踪指数和联接目标     |
| `direction_analysis_snapshots` | 保存方向分析的时间、理由、质量与版本       |
| `macro_indicator_catalog`      | 管理宏观指标口径、公布周期和更新规则       |

宏观原始数据优先复用现有 `market.market_observations` 等来源治理机制，不必重新建立一套重复的市场数据系统。

非常重要的一点是：投资方向的分类关系是相对稳定的参考事实，而“这个方向现在是否值得研究”是随时间变化的分析结论。两者必须分开保存。

### 调整 4：新增一项宏观与投资方向联动任务

这是我最建议补充的任务。

可以在原任务 2 后增加一个 任务 2A：宏观与投资方向研究上下文，先实现一个较轻的版本。

| 阶段  | 可以自动化的内容                        | 不应提前承诺的内容   |
| --- | ------------------------------- | ----------- |
| 第一版 | CPI/PMI 等已核验宏观数据、公布时间、方向映射、指数列表 | 精准经济拐点预测    |
| 第二版 | 历史增长、通胀、利率、信用趋势，方向风险与相对强弱       | 宏观模型必然提升收益  |
| 第三版 | 情景变化、方向研究优先级、历史表现验证             | 凭宏观分数自动决定买卖 |

这样即使尚未完成完整宏观周期模型，第一版页面也可以体现“宏观信息—方向—基金”的关系，而不是等到很久以后才接入。

同时，需要验证宏观数据首次公开时间与历史修订版本，否则容易在回测中出现未来信息泄漏。

### 调整 5：第 5.3 节的技术评分增加“指数级分析”

当前计划主要面向 ETF 计算技术指标。

我建议调整成两层：

指数级分析用于判断一个投资方向或指数的价格趋势、动量和波动风险。

基金级分析用于检查具体产品的跟踪质量、成本、折溢价、流动性以及与指数走势的差异。

例如，两只同样跟踪沪深300的 ETF，可能具有几乎一样的中期市场趋势，却有不同的费用和成交成本。不能因为某只 ETF 的 MACD 分数高一点，就认定它长期更适合投资。

也应保留不同资产的分析模型。黄金、债券和股票可以共用部分趋势指标，但长期配置评价不应采用完全相同的估值或评分规则。

此外，计划要求首次获取至少 260 个交易日，这适合作为 MA200 等指标的研究起点；但并不足以验证跨经济周期的策略表现。需要提前预留多年历史数据回填能力。

### 调整 6：第 5.4 节新增三个研究接口

我建议在原基金筛选 API 基础上补充：

| API                                              | 用途                    |
| ------------------------------------------------ | --------------------- |
| `GET /api/v1/investment/market-context`          | 宏观经济观察、数据状态、变化方向和分析依据 |
| `GET /api/v1/investment/directions`              | 方向列表、研究状态、相关指数和可用数据覆盖 |
| `GET /api/v1/investment/directions/{id}/indices` | 某一方向下的指数及其指标比较        |

现有 `GET /api/v1/funds/screener` 可以继续负责最终的基金列表，但应增加能够表达方向、指数和数据批次的筛选条件。

方向选择后，前端自动把对应条件传入基金筛选接口。用户手动修改筛选条件时，系统不应擅自重置用户选择。

宏观数据、方向快照、指数行情可能具有不同的实际数据截止时间，所以不能只在整页显示一个笼统的“截至今日”。

### 调整 7：第 6 节新增前端组件和联动测试

建议新增以下前端模块：

```
frontend/src/features/fund-screener/
├── FundScreenerPage.tsx
├── components/
│   ├── MacroContextStrip.tsx
│   ├── DirectionExplorer.tsx
│   ├── IndexComparison.tsx
│   ├── ScreenerFilters.tsx
│   ├── FundResultsTable.tsx
│   ├── FundAnalysisDrawer.tsx
│   └── FundTrendChart.tsx
```

其中三个新组件的职责要明确：

`MacroContextStrip` 只负责宏观概览，不在前端临时计算投资结论。

`DirectionExplorer` 负责方向分类、研究理由、风险提示、方向与指数的联动。

`IndexComparison` 负责在进入具体基金前，先判断和比较指数本身。

此外，任务 7 需要加入端到端测试：点击某个方向后，相关指数是否变化；选定指数后，基金结果是否正确；当宏观数据过期时，是否还能诚实显示已知事实、同时停止发布不可靠的方向结论。

## 五、信息自动化应该达到什么程度？

你的目标是“尽可能自动获取信息，人容易决策买卖”。我非常认同把自动化放在信息与分析层，而非直接从第一版开始自动交易。

| 数据和工作         | 建议自动更新频率      | 展示位置        |
| ------------- | ------------- | ----------- |
| ETF、指数行情      | 交易日盘后，必要时盘中补充 | 基金与指数诊断     |
| 技术指标和趋势评分     | 有效行情更新后       | 基金排行、详情     |
| CPI、PMI 等宏观数据 | 按实际发布周期       | 宏观观察        |
| 利率、信用及流动性     | 按来源更新频率       | 宏观与方向研究     |
| 行业、风格相对强弱     | 每个有效交易日或每周    | 投资方向        |
| 估值、费率、规模、跟踪质量 | 按来源披露频率       | 指数及基金比较     |
| 组合仓位和风险状态     | 数据刷新及持仓变化后    | 资产看板、基金诊断   |
| 研究状态发生重大变化    | 有新数据且满足提醒条件时  | 企业微信、Web 通知 |

现有计划在上海时间 22:30 增加日终研究任务，适合作为部分 A 股和基金数据的刷新入口，但不能假设所有宏观指标、美股行情和场外基金净值都在此时可用。

应采用按数据源和市场分别调度、按实际有效数据触发重算的方式，最终合成带时间戳的研究快照。

自动提醒也建议分两类：一个是“有新的值得研究的机会”，另一个是“现有持仓的风险条件发生变化”。两者需要不同的频率和触发规则，避免每天推送大量没有实际决策价值的信号。

## 六、我建议重新安排实施里程碑

现有计划是 M1 基础筛选、M2 技术研究、M3 发布验收。

如果按你的完整产品目标，我更推荐这样调整：

| 里程碑          | 核心交付                          | 是否进入第一阶段 |
| ------------ | ----------------------------- | -------- |
| M0：产品信息架构    | 宏观 → 方向 → 指数 → 基金的完整 UI 与数据契约 | 是        |
| M1：数据与基础筛选   | 数据口径修正、基金主数据、方向关系、组合筛选        | 是        |
| M2：趋势与指数研究   | 历史序列、技术指标、指数诊断和基金比较           | 是        |
| M3：宏观自动观察    | 自动采集已验证宏观指标、展示方向情景及联动证据       | 优先推进     |
| M4：策略验证与基金质量 | 回测、同指数费用/跟踪比较、估值研究            | 后续       |
| M5：投资决策辅助    | 组合风险、可执行规则、自动提醒、决策复盘          | 后续       |

其中 M0 是界面和契约设计，不要求立即完成宏观分析模型。

第一阶段即可交付完整的页面导航与方向联动，但没有可靠数据的功能只能显示待评估，不能填入虚构结论。

这样既能逐步上线，又能避免先做成普通基金筛选器，后面再为宏观与投资方向重新设计整个页面。

## 七、最终建议

这份第 18 号实施计划不需要推翻。技术部分考虑得很周到，尤其数据质量、评分可追溯性、异步采集和测试设计应当保留。

但我建议在执行前，优先完成三个产品级调整：

调整页面定位

从“基金筛选器”升级为“投资机会研究工作台”，支持直接搜索，也支持宏观到基金的逐层探索。

提前建设投资方向层

宏观经济可以逐步完善，但方向、指数、基金之间的联动和数据关系必须在第一阶段设计好。

分开评价“投什么”和“何时买”

长期配置价值、指数趋势、基金质量和个人组合风险分开分析，不使用一个技术分数解决全部问题。

我最推荐的最终产品形态是：用户进入投资机会中心，先看到可信的宏观环境摘要，然后发现值得研究的方向，点击方向看指数比较，再进入基金排行榜和买卖时机诊断。

这比单独建设基金筛选、宏观报告、技术指标三个互不关联的功能，更符合你的目标，也更有可能成为真正每天愿意使用的投资助手。
