# WealthSail 最新版评审：页面更整洁了，但还没有成为真正的投资助手

这版在视觉上比之前清爽，但我认为它目前仍不适合定稿。

问题已经不只是布局，而是用户想研究投资机会，系统却主要在展示自己还有哪些数据没准备好。

我看了你提供的截图，并核对了当前 `codex/investment-opportunities` 分支的 `ResearchBoard.tsx` 实现。你的六点反馈基本都成立，而且其中两点可以明确定位为交互设计问题。

## 一、目前最明显的问题

| 问题               | 实际情况                   | 判断       |
| ---------------- | ---------------------- | -------- |
| 「查看方向关联事项」打开数据状态 | 源码里确实存在这一联动            | 应修复      |
| 「查看运行状态」跳去运维页面   | 当前操作映射到 `/operations`  | 不适合普通投资者 |
| 三张摘要卡片都没有实质结论    | 持仓未评估、机会证据不足，只有一项普通变化  | 数据能力尚未完成 |
| 展开后有大量未采集、未核验内容  | 数据源确实分为未接入、需授权、采集失败等状态 | 应由系统分类处理 |
| 不知道该看摘要还是逐层展开    | 页面缺乏清晰的研究主路径           | 需要重新定义   |
| 宏观模块展开后占据很大页面    | 运维、研究证据、原始图表混在同一容器     | 建议拆分展示层级 |

### 「查看方向关联事项」为什么会打开数据状态？

我在 `ResearchBoard.tsx` 中确认：

`showReferences()` 收到关联事项后，只要其中包含 `DATA_GAP` 或 `SYSTEM`，就会自动执行 `setDataOpen(true)`。

所以这不是你点错了，而是当前代码把方向相关问题与底层数据问题绑定在了一起。

正确的行为应该是：

点击「查看方向关联事项」→ 打开当前方向的相关研究事项 → 显示支持证据、逆风、尚未满足的条件及下一步操作。

如果其中某一项缺数据，再由用户点击「查看数据缺口」，进入对应的数据详情。

不能直接把用户带到整页运维与数据故障列表。

### 「查看运行状态」为什么不合适？

当前 `VIEW_OPERATIONS` 被映射到 `/operations`。这个路由可以保留给管理员，但它不是普通投资者想看的页面。

投资者只需要知道：

- 哪项数据受影响；
- 对研究判断有什么影响；
- 系统是否正在处理；
- 需要自己做什么。

只有管理员才需要进一步查看任务日志、来源错误、重试情况和服务状态。

建议将操作分为用户查看研究限制和管理员排查采集故障两种，不再共用同一个按钮。

## 二、为什么还是看不到真正有价值的投资信息？

根本原因是：页面设计所需的决策数据尚未准备完整，而首页没有把“已知事实”和“尚不能判断的事情”组织好。

目前系统可以确认部分宏观事实，例如截图中提到的制造业 PMI 略高于 50。但要判断沪深300是否存在建仓研究机会，还需要指数价格趋势、估值、企业盈利、风险和基金质量等证据。

当前源码里的机会生成逻辑也体现了这一点：

`backend/macro/research_board.py` 只有在指数趋势有效，而且价格相对于 MA200 和 63 期动量满足条件时，才会产生趋势研究机会。

因此，在指数历史数据尚未到位时，“研究机会”卡片不会出现真正的候选。这是符合数据严谨性要求的。

问题不在于系统不肯给出结论，而在于它反复解释为什么给不出结论，却没有优先推进最能产生结论的数据建设。

建议将“市场事实”“研究线索”“具备完整资格的候选”严格区分。不能把缺数据说成没有机会，也不能为了页面好看而凭宏观数据制造买卖点。

## 三、数据到底为什么没有获取到？

我查了 `backend/integrations/opportunity_sources.py`，目前至少存在四种不同情况。

| 截图中的数据             | 当前状态    | 我核查到的原因                             | 应该怎样处理                 |
| ------------------ | ------- | ----------------------------------- | ---------------------- |
| 美国10年期名义与实际收益率     | 已采集     | 美国财政部数据采集适配器已实现                     | 保留使用，继续完善发布时间核验        |
| 中国10年期国债收益率、DR007  | 需要来源授权  | 当前公开实现未启用相应授权客户端                    | 核查数据许可，评估合法可用的替代来源     |
| M1、社融、企业中长期贷款      | 采集失败    | 截图显示 `HTTPStatusError`；已有人民银行网页采集逻辑 | 排查具体 HTTP 状态、网页结构及访问限制 |
| A50、标普500、纳斯达克隔夜变化 | 尚未采集    | 当前机会研究尚无可用的对应观测                     | 接入现有行情能力或补建数据服务        |
| 沪深300估值、趋势、盈利      | 尚未评估或采集 | 没有满足研究条件的完整可验证数据                    | 优先补齐指数日线、估值、盈利快照       |
| 个人持仓风险             | 未确认     | 当前账户/持仓/估值/风险政策未满足完整核验要求            | 检查现有账户与持仓快照，而非重新做账户系统  |

这里有一个重要区别：

“需要来源授权”不是采集失败；“尚未采集”不是市场没有数据；“尚未评估”也不是数据一定不存在。

尤其是中国国债收益率和 DR007，当前代码明确要求相应许可与客户端，简单点击“重试”不会解决问题。

人民银行数据则不同：采集器已经尝试请求，但失败了。应检查详细请求记录、响应状态及来源变更，不能仅凭 `HTTPStatusError` 判断究竟是访问被拒、资源迁移还是其他原因。

另外，截图中的“下次处理时间”只是已记录的计划，并不证明 Worker 此刻一定在线运行。只有采集任务的实际执行记录才能证明处理结果。

### 真正应该优先接通什么？

从你当前研究的「A股宽基」来看，我建议优先级是：

第一：沪深300、中证A500、中证500的长期价格数据。

这是计算 MA200、63日动量、波动、回撤，以及判断技术条件变化的基础。

第二：对应指数的估值和盈利数据。

这是区分“趋势上涨”和“价格是否具有合理投资吸引力”的基础。

第三：基金产品数据。

要能在确定研究指数后，比较 ETF 和场外基金的费用、跟踪质量和交易条件。

第四：国内利率与信用。

中国国债收益率、M1、社融等能增强宏观判断，但不必等所有宏观指标全部接齐，才允许计算已具备数据的指数趋势。

第五：个人持仓与风险预算。

如果 WealthSail 已经有账户和持仓，优先检查为什么研究模块无法得到有效快照，而不是额外做一套手工录入。

这比继续增加大量空白数据卡片更重要。

## 四、页面应该让用户怎么看？

我不建议用户每天把所有折叠栏逐一打开。

正确的产品体验应该是：日常主要看首页摘要；出现值得关注的变化时，点击对应事项；需要深入研究时，再进入专题证据。

建议分为三个使用深度。

5 秒：查看首页

只看持仓风险、研究机会、重要变化三项。用户应立即知道有没有需要处理的事。

30 秒：查看当前方向

点击相关指数或基金，查看支持因素、逆风、策略条件和下一步观察点。

5 分钟：深入分析证据

根据需要查看宏观历史、国债利率、指数估值、技术指标、策略回测和数据来源。

这个首页比现有三张卡片更实用的地方是：它不只是告诉用户结论不足，还明确说明目前已经知道什么，以及下一步最值得研究什么。

真正出现已核验机会或持仓风险后，才使用绿色、橙色或红色强调。

## 五、折叠栏究竟应该怎样组织？

我建议首页保持非常少的入口，不再层层嵌套。

### 默认呈现

市场环境与投资关注：三张摘要卡片，加上当前研究方向的简短结论。

当前方向的指数与基金：直接复用你已经设计好的左右两栏选择与诊断工作台。

### 点击后呈现

| 用户点击     | 应显示什么                | 不应发生什么         |
| -------- | -------------------- | -------------- |
| 查看重要变化   | 当前重要变化清单、相关资产及来源     | 无关宏观原始数据自动全部展开 |
| 查看方向关联事项 | 当前方向的支持因素、逆风、条件及相关指数 | 自动进入全部数据与运行状态  |
| 查看指数与基金  | 定位指数、基金列表和选中标的诊断     | 跳到与当前选择无关的内容   |
| 查看研究依据   | 宏观、利率、指数及事件专题        | 默认展示所有专题全部数据   |
| 查看研究限制   | 分组显示缺少的必要数据及影响       | 一项缺口重复生成多个长卡片  |
| 查看运行详情   | 仅管理员查看相应任务及错误        | 普通用户被带进运维后台    |

你之前的宏观折叠栏确实更符合这个思路。

我建议恢复它的简洁视觉结构，将“研究依据”作为独立的二级详情区域，而不把完整宏观详情直接挂在首页最庞大的折叠内容里面。

## 六、数据与运行状态应该重做为紧凑的「研究受限事项」

目前最大的浪费在这里。

截图里展示了非常多的缺口，每条都占据大块空间，但大多数内容只有一句话：

“研究受限，尚未评估，负责模块处理。”

这属于同一种状态，不需要十几张大卡片。

建议合并展示：

| 受限类型     | 具体项目            | 影响        | 谁来处理    |
| -------- | --------------- | --------- | ------- |
| 市场数据缺失   | 沪深300趋势、估值、盈利   | 无法完成该指数研究 | 研究数据服务  |
| 宏观数据获取失败 | M1、社融、贷款        | 国内信用分析不完整 | 宏观采集服务  |
| 需要来源许可   | 中国10年期收益率、DR007 | 利率分析受限    | 管理员     |
| 持仓证据不完整  | 账户快照、风险预算       | 个人风险无法评估  | 账户服务与用户 |
| 策略验证缺失   | 样本外回测           | 无法验证择时规则  | 策略研究服务  |

表格中的项目可以展开查看错误、责任、最近处理和来源，但默认只显示五行概览。

尤其是 `PBOC` 相关三个采集失败，不应在前端变成三份完全重复的系统故障说明。如果确实来自同一个失败根因，可以按来源聚合；但也要保留每个指标自己的采集状态，避免把不同故障误合并。

对于没有实际处理记录的任务，建议显示：

「尚未建立处理任务」 或 「未检测到执行记录」。

不能模糊地写成“等待系统处理”，让用户误以为系统正在后台自动修复。

## 七、建议让开发工具修改的具体内容

下面是我认为最值得立即修改的地方，尽量避免再次推倒 UI。

P0：修正方向关联跳转

`ResearchBoard.tsx` 中不要在 `showReferences()` 遇到数据缺口时直接 `setDataOpen(true)`。

同时，`research_board.py` 的 `direction.itemIds` 目前直接使用 `blockers`，应改为实际与方向关联的研究事项，另设 `blockerIds` 管理数据缺口。

P0：调整首页布局

`ResearchBoard.tsx` 默认只呈现三张摘要卡片和当前方向的关键结论，详细证据、运维与条件跟踪不占据首页主要空间。

P0：修正运行状态入口

`VIEW_OPERATIONS` 只供管理员在系统管理场景中使用。普通用户点击受限事项，应看到业务含义和可执行动作，而不是运维路由。

P1：优先补齐真正产生机会结论的数据

复核 `backend/investment/service.py` 中的指数分析快照链路，先让真实指数行情、MA200、动量、估值及风险能够进入投资研究。之后再完善基金产品质量。

P1：合并数据缺口

`backend/macro/research_board.py` 根据受影响的研究判断、数据源与处理责任分组；前端只显示分组摘要，支持展开子项。

P2：明确自动提醒的触发条件

只对新出现的、已经验证的重要变化和个人风险触发提醒。持续存在的数据缺口不应每小时产生新的用户提醒，系统管理员可另行收到运维告警。

需要同步添加交互测试：方向关联事项不能再打开数据与运行状态；普通用户不进入 `/operations`；同一个数据源错误不在首页重复刷屏；索引数据缺失时不生成虚假机会；个人持仓未知时不将其误判为安全。

## 八、我的最终判断

这次改版解决了以前满屏红字和部分内容混杂的问题，但牺牲了投资决策界面的效率。

你的原始目标始终应该是：

帮助用户找到值得研究的方向和基金，识别持仓风险，判断预设买卖条件是否发生变化。

而不是让用户不停研究 WealthSail 为什么缺数据。

我建议目前采取两条并行路线：

产品界面方面： 恢复简洁的宏观折叠概览，首页只保留持仓风险、机会候选、重要变化。下方直接连接指数和基金选择；数据缺口、历史图表、原始证据进入二级研究或管理页面。

数据研发方面： 优先修复指数日线、技术趋势、估值、基金质量与个人账户风险链路。宏观新闻和全球数据可以逐步扩充，但不必让这些数据全部齐备才允许用户进行部分有效的基金研究。

你现在最应该要求开发工具完成的，不是再增加一轮 UI 卡片，而是：修正错误跳转，简化数据状态显示，并让第一批真实指数研究结果进入首页。

当系统能够首次可靠地显示“某指数出现值得研究的趋势变化”或“某已有持仓触发了风险条件”，这套界面才真正开始发挥价值。
