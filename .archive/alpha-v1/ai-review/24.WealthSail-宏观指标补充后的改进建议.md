# WealthSail「市场环境与投资机会」全面评审

你指出的问题非常准确。现在系统的数据能力进步很大，但决策信息的组织方式还没有跟上。

从截图看，系统已经把宏观指标、国债收益率、官方事件、市场指数、方向研究、持仓风险、策略条件和通知都放进来了。功能比以前完整得多，却产生了一个新问题：

> 重要风险、潜在机会、证据不足、普通数据更新被混在一起。用户看到大量红字和“待核查”，但不知道什么事情真正值得关注，以及下一步该做什么。

我核对了当前 WealthSail `codex/investment-opportunities` 分支（提交 `94b80a0`）的实现。发现一个直接原因：

在 `backend/macro/opportunity.py` 中，只要方向研究缺少必要证据，就会产生一条 `CRITICAL` 优先级的 `GAP`（证据缺口）事件。

前端随后把这类信息以醒目的红字反复呈现。

这实际上混淆了两种完全不同的情况：

- 市场或持仓风险已经发生：用户可能需要及时复核。
- 系统还没有采集或核验足够的数据：这是研究覆盖和数据建设问题，并不意味着市场要下跌。

这也是为什么你现在看到最醒目的信息是「A股尚待核查」，而不是「当前有哪些值得研究的方向」或「哪些已有持仓的风险正在增加」。

## 一、总体评价

| 维度       | 当前表现                    | 我的评价       |
| -------- | ----------------------- | ---------- |
| 数据真实性和溯源 | 官方数据、发布时间、来源及可得性管理      | 已有较好的基础    |
| 宏观数据覆盖   | CPI、PPI、PMI、M2，部分美国利率数据 | 仍存在关键缺口    |
| 信息重要性排序  | 普通更新与缺口、风险混合            | 需要重做       |
| 投资方向识别   | 有宏观关联模型，但缺乏完整判断证据       | 尚未形成可用机会筛选 |
| 个人持仓风险   | 已预留入口和判断条件              | 联动不完整      |
| 下一步操作引导  | 大量重复提示“待核查”             | 不够具体       |
| UI 可读性   | 信息充分，但层级和重复控制不足         | 需要重新编排     |

我的建议不是删掉这些信息，而是将它们分成三个层次：决策摘要、研究证据、数据与系统状态。

用户默认看到决策摘要，主动深入时再看证据；只有遇到数据问题时，才需要进入系统状态排查。

## 二、最先应该修复的三个逻辑问题

### 问题 1：证据缺失不能自动成为最高级别风险

当前代码存在如下规则：

`方向有 missingEvidence → 产生 CRITICAL / GAP`

因此，只要中国国债收益率、M1、社融、企业盈利或指数估值没有接齐，就很容易在首页反复看到醒目的红色信息。

建议改成：

| 情况             | 正确分类 | 用户看到什么     |
| -------------- | ---- | ---------- |
| 已确认的持仓风险预算超限   | 风险预警 | 优先处理       |
| 已确认的市场风险指标明显变化 | 风险观察 | 检查相关持仓     |
| 已验证的投资条件改善     | 研究机会 | 查看候选指数和基金  |
| 缺少关键数据         | 数据不足 | 暂不能确认，查看缺口 |
| 普通经济指标更新       | 信息更新 | 查看变化       |
| 数据源故障、冲突或过期    | 系统状态 | 查看修复进度     |

例如，“缺少M1数据”不应显示为红色最高优先级，而应显示为中性的“研究受限”。

只有明确存在风险事实，或者个人风险政策确实被触发，才应使用高紧急度提示。

### 问题 2：当前最显眼的信息被重复展示

截图中的「A股尚待核查：人民币融资条件、企业盈利/订单、指数估值与趋势……」至少出现在：

页面顶部、四问卡片、研究变化列表、利率与信用区域、方向支持与逆风、策略条件以及下一步核查中。

重复文字没有增加决策价值，反而稀释了重要信息。

建议同一个问题只生成一个结构化事项，例如：

`EVIDENCE_GAP / A股宽基 / 企业盈利数据`

首页展示一句摘要，点击后进入缺口详情。其他模块通过同一个事项 ID 引用状态，而不是重新生成整段红字。

### 问题 3：缺少按当前研究对象和个人持仓定义的优先级

现在是按 `CRITICAL / ATTENTION / INFO` 排序，但真实投资中，一条信息是否重要，还取决于：

是否影响我的持仓、影响多大、是否刚刚发生、是否已经有可靠证据、是否存在明确的后续操作。

一个已持仓且高度集中的基金发生已确认的风险条件变化，通常比某个无持仓方向的宏观数据更新更值得优先查看。

但如果系统还没获取持仓，不能假设用户没有持有，更不能声称“该基金可能下跌”。

所以首页的优先级应该结合事件、标的和个人持仓，做分层排序，而不能只看宏观事件本身。

## 三、建议重新组织成「三个重点入口 + 四层研究信息」

现在页面是按数据模块组织的：

宏观周期 → 利率与信用 → 指数与市场 → 全球事件 → 策略与持仓 → 原始指标。

这是开发者比较容易理解的组织方式，却不是投资者最自然的阅读顺序。

投资者的阅读顺序应该是：先看有没有事情需要处理，再看有没有值得研究的机会，最后才查依据。

### 推荐的首页信息架构

## 投资机会中心

页面结构示意

第一层：今天最值得关注什么？

我的持仓风险

已确认风险、需要复核的仓位

机会候选

满足研究条件的指数或基金

重要新变化

宏观、市场与全球事件

第二层：当前研究方向

A股 / 宽基 · 支持证据 · 主要逆风 · 仍需核查的条件

关联沪深300、中证A500、中证500 → 点击进入基金比较

第三层：研究依据

经济周期

利率与信用

指数估值与趋势

全球事件

打开专题后，才呈现详细图表、历史分位和原始证据。

第四层：数据与研究系统状态

缺失数据 · 数据源授权 · 最近同步 · 失败任务 · 计算版本 · 可得性核验

这四层职责应严格区分。

特别是数据与系统状态不应该占据投资决策首页的最醒目位置，除非数据错误可能直接使正在展示的判断失效。

## 四、颜色应该怎样用，才能真正突出机会和风险？

我建议将“信息类别”和“紧急程度”分开设计。

你目前实际上只有一种非常显眼的状态：红色异常。这会让用户逐渐对红字失去敏感性。

应该采用以下规则：

| 颜色       | 表达含义           | 示例              |
| -------- | -------------- | --------------- |
| &#x20;红色 | 已确认且需要优先复核的风险  | 已持仓组合超过确认的风险限额  |
| &#x20;橙色 | 重要变化或尚需确认的潜在风险 | 利率显著变化、市场波动上升   |
| &#x20;绿色 | 有可靠证据支持的积极研究线索 | 某指数经过验证满足预设趋势条件 |
| &#x20;蓝色 | 重要客观事实或普通更新    | PMI公布、官方政策事件    |
| &#x20;灰色 | 信息缺失、未计算、条件未确认 | 社融未采集、指数估值不足    |

特别需要强调：绿色不等于买入，红色也不等于预测下跌。

举例来说，某个持有的指数触发波动风险阈值，可以显示红色“风险复核”，但不能直接写“预计明天会跌”。

对应地，一个指数趋势开始改善，可以显示绿色“机会线索”，但只有基金质量、策略验证、成本和持仓预算符合条件，才可升级为真正的建仓研究候选。

### 同一条信息的正确展示方式

已确认风险

某持仓已超过用户设定的单一资产风险限额。

下一步：查看风险暴露、限额差距和可选再平衡方案。

积极研究线索

某指数长期趋势条件由不满足转为满足。

下一步：检查估值、成本、风险及历史策略有效性。

研究证据不足

当前指数缺少经核验的盈利和估值数据。

下一步：系统尝试补齐；在数据到位前不形成价值判断。

这三类应该有完全不同的视觉表现，不能全部用红色。

## 五、最重要的改进：提示不仅要说明问题，还要告诉用户能做什么

你问得很关键：异常信息出现之后，用户能做什么？

当前许多提示只告诉用户“待核查”，却没有区分是系统该处理，还是用户真的需要处理。

建议为每个状态指定明确责任和操作。

| 情况          | 处理主体      | 页面提供的操作            |
| ----------- | --------- | ------------------ |
| 宏观指标未采集     | 系统 Worker | 查看采集进度；有权限时重试      |
| 官方发布时间未核验   | 数据治理任务    | 查看来源和核验状态          |
| 数据源需要授权     | 管理员       | 查看所需授权，进入数据源配置     |
| 历史数据过期      | 系统 Worker | 查看最新同步结果、触发有权限的刷新  |
| 指数没有估值或盈利证据 | 研究数据服务    | 查看缺口和后续计划，不生成分数    |
| 未选择个人账户     | 用户        | 选择 WealthSail 现有账户 |
| 持仓估值不完整     | 系统或用户     | 查看哪些账户、持仓缺少数据      |
| 已确认组合风险超限   | 用户        | 查看持仓和风险政策，复核再平衡    |
| 新的趋势条件满足    | 用户        | 查看基金候选、历史验证及风险     |

这其实需要一个比较重要的后台概念：

研究阻塞事项（Research Blocker）。

每个阻塞事项应记录原因、关联标的、负责模块、是否可由用户修复、最近处理时间和下一步任务。

例如：

`当前指数估值未核验`

系统要能进一步说明：

“缺少沪深300的可验证历史 PE 数据；正在等待估值服务更新；目前不影响用户查看技术趋势，但暂不能评价长期估值吸引力。”

这比反复显示“证据不足、不能认证建仓条件”更有价值。

## 六、现有五大专题应该怎样重新分组？

你现在有“宏观周期、利率与信用、指数与市场、全球事件”，另外还有策略与持仓、站内条件跟踪和底层宏观详细指标。

我建议重新划分为以下几个明确的业务区域。

| 区域       | 主要内容                          | 默认展示级别 |
| -------- | ----------------------------- | ------ |
| 我的持仓风险   | 当前敞口、集中度、风险预算、最近触发条件          | 首页优先   |
| 投资机会候选   | 指数方向、估值、趋势、产品质量及研究状态          | 首页优先   |
| 重要市场变化   | 最近变化、重大事件、与当前方向的关联            | 首页摘要   |
| 宏观经济与流动性 | PMI、CPI、PPI、M1/M2、社融、利率、收益率曲线 | 展开研究   |
| 指数与基金分析  | 估值、盈利、趋势、动量、波动、回撤、费用          | 点击标的   |
| 全球市场与事件  | 美债、美元、原油、A50、海外股指、重大公告        | 按需展开   |
| 策略与历史验证  | 规则条件、样本外测试、成本、历史信号            | 独立详情   |
| 数据与运行状态  | 采集、授权、缺口、时间戳、方法和版本            | 管理与诊断  |

其中你现在的“利率与信用”确实很重要，但不宜让所有人始终看到十几张细节卡片。

在 A股宽基研究中，应优先展示中国利率、信用、指数估值及盈利；美债、美元和全球事件作为外部风险因素。

如果切换到美股、黄金，才提高美债实际收益率、美元和全球风险的展示优先级。

信息分组不仅要固定，还要随着研究市场和用户持仓动态变化。

## 七、现在还缺哪些信息？应该先补什么？

这一点需要从“对基金投资决策有没有实际帮助”排序，而不只是看哪些数据容易接入。

## 建议优先级

| 第一优先级 | 当前指数估值、盈利、趋势、波动与回撤<br>它们直接关系到指数是否值得研究、价格是否正在反映基本面变化，以及风险是否上升。 |
| ----- | ------------------------------------------------------------- |
| 第二优先级 | 中国国债收益率、社融、M1、信用与融资条件<br>补齐 A股、债券和部分成长资产的关键宏观传导链路。            |
| 第三优先级 | 个人持仓、风险预算与同指数敞口<br>确保能够识别“需要关注的市场变化”与“真正影响我账户的风险”。            |
| 第四优先级 | ETF 费用、跟踪质量、规模、流动性及折溢价<br>将看好的指数转化为实际可比较的基金工具。                |
| 第五优先级 | 全球利率、汇率、原油、A50及事件关联<br>增加突发风险和外部市场反应的覆盖。                      |
| 第六优先级 | 真实历史时点策略验证<br>判断择时规则扣除成本后是否有稳定、可重复的价值。                        |

我特别注意到了第三张截图的一处问题：

美国10年期名义收益率和实际收益率已经显示数值，但中国10年期收益率、DR007、M1、社融和A50仍有未采集或需要授权的情况。

而当前所选方向是 A股宽基。

这意味着：系统优先获取了某些海外变量，但最直接影响当前研究方向的国内信用、利率及指数数据还不完整。

下一阶段应该按用户正在研究的方向决定采集优先级，而不是按数据源哪个最容易接通决定显示权重。

还有一点：美国国债收益率的历史序列虽然有大量样本，但截图显示其实际公布时刻尚未确认。可以用于当前事实观察，不能直接宣称这些历史值已经满足无前视偏差的策略回测要求。

## 八、现在的投资机会引擎还缺一种核心输出：明确的“研究机会状态”

当前系统已经有 `ENTRY_CANDIDATE`、`HOLD_REVIEW`、`POSITION_REVIEW`、`WAIT` 等状态。这是好的基础。

但前端还需要把它们转化成用户容易理解的操作语言。

我建议分别输出市场研究状态和个人持仓状态，不要混成一个“是否买入”。

| 市场研究状态 | 表示什么                 | 用户下一步        |
| ------ | -------------------- | ------------ |
| 值得优先研究 | 有可靠证据支持，且相关条件出现有意义变化 | 查看指数、基金、风险   |
| 等待条件   | 方向有研究价值，但某些规则尚未满足    | 跟踪条件变化       |
| 风险增加   | 已核验的趋势、波动或基本面风险出现变化  | 复核是否适合当前风险预算 |
| 证据不足   | 没有足够数据评价             | 查看缺口，不形成结论   |

个人持仓状态则独立显示：

| 持仓状态          | 系统应提示            |
| ------------- | ---------------- |
| 未持有           | 是否将符合条件的基金加入研究清单 |
| 已持有，风险可评估     | 当前仓位和预设风险条件是否仍合适 |
| 已持有，触发已确认风险政策 | 优先复核仓位或再平衡       |
| 持仓未知          | 选择账户或补齐资产快照      |

例如，系统发现某指数趋势明显转弱。

对未持有用户：它可能意味着该指数暂不符合新增建仓的趋势条件。

对已有持仓用户：系统应结合持仓比例、成本、风险预算、税费和策略规则，提示是否需要复核，而不是直接给出“卖出”指令。

至于“会不会跌”，系统不能准确保证未来价格方向，但可以识别经过验证的风险信号，并估算特定下跌情景对组合的影响。

这应是财富管理辅助系统更可靠的做法。

## 九、给开发工具的具体修改建议

现有 WealthSail 其实不需要大规模重构，最关键的变更集中在几个模块。

| 修改位置                                | 要做什么                                |
| ----------------------------------- | ----------------------------------- |
| `backend/macro/opportunity.py`      | 将证据缺口与真实风险分开排序，不再自动把缺口标为 `CRITICAL` |
| `backend/macro/direction_models.py` | 区分必要证据、建议核查项与实际缺失项，防止长期保留固定的“缺口”    |
| `backend/investment/decision.py`    | 让市场条件、个人持仓条件、策略验证状态独立输出，并附可操作的下一步   |
| `OpportunityRadar.tsx`              | 首页改为持仓风险、机会候选、重要变化的摘要布局             |
| `MacroContextStrip.tsx`             | 保留完整宏观详情，但降低原始数据和重复说明的默认展示优先级       |
| 前端数据模型与样式                           | 增加事件类型、严重程度、证据质量、用户操作及责任主体等字段       |

### 需要特别修正的后台规则

在 `direction_models.py` 中，目前 `missingEvidence` 会先加入一组通用的待研究事项，然后再追加实际缺失的数据。

这可能导致即使部分证据已经具备，模型仍反复显示同样的宏观缺口。

建议明确拆分为：

`requiredEvidence`：形成判断必须有的数据。

`missingRequiredEvidence`：目前确实缺少的必要数据。

`recommendedChecks`：可以进一步研究，但不必然阻止所有分析的项目。

`failedConditions`：数据已经充分，但某个预设条件确实没有满足。

这是决定系统能否正确区分“机会不成立”和“没有足够信息判断”的关键。

### 排序逻辑建议

每条研究事项至少包含：

| 字段                              | 作用                                     |
| ------------------------------- | -------------------------------------- |
| `category`                      | RISK / OPPORTUNITY / CHANGE / DATA_GAP |
| `severity`                      | HIGH / MEDIUM / LOW                    |
| `confidence`                    | VERIFIED / PARTIAL / UNKNOWN           |
| `relevance`                     | 是否影响当前选择方向或个人持仓                        |
| `actionability`                 | 用户能否采取明确操作                             |
| `affectedAssets`                | 受影响的指数、基金和账户                           |
| `nextAction`                    | 查看、复核、跟踪、补数据等                          |
| `evidenceIds`                   | 可追溯数据和事件                               |
| `firstSeenAt` / `lastChangedAt` | 变化时间与去重                                |
| `status`                        | 新出现、处理中、已确认、已关闭                        |

其中 `severity` 不能只凭信息缺失决定；`confidence` 也不能因为优先级高就自动提高。

同一事件对不同用户的相关度可以不同，但不能让相关度替代证据真实性。

## 十、如何分阶段改善，而不继续陷入 UI 反复修改？

我建议三轮推进即可。

第一轮：马上修复信息优先级和重复问题。

不动底层采集，只改风险与缺口分类、首页信息排序、文案和操作入口。让“没有数据”不再抢占投资风险预警的位置。

第二轮：让机会与持仓风险真正有数据可判断。

重点接通当前指数趋势、估值、盈利，中国10年期国债收益率、社融，以及个人账户风险。没有完整证据时保持诚实，但已经具备的部分应能独立得出有限结论。

第三轮：形成完整的研究和跟踪闭环。

把符合条件的基金加入研究清单，将历史信号变化与账户风险监控接入已有 Worker 和站内提醒。根据已验证的重要变化通知用户，不要因为每次宏观采集成功就重复提醒。

### 推荐验收标准

| 测试场景          | 应有结果                   |
| ------------- | ---------------------- |
| 缺失M1但没有市场风险事件 | 灰色数据不足，不出现红色最高风险       |
| 某指数真实趋势由弱转强   | 显示有依据的机会线索，不自动建议买入     |
| 已持仓超出确认的风险限额  | 显著提示个人风险，并能进入对应持仓      |
| 数据刷新但数值没有实质变化 | 不重复生成重要提醒              |
| 官方事件发生但市场影响未知 | 展示事实和待验证的影响渠道，不制造方向性判断 |
| 所有数据尚未接齐      | 仍能查看有效的部分分析，不反复输出相同缺口  |
| 切换A股到美股或黄金    | 自动调整核心证据和方向研究重点        |
| 研究事项被标记已读     | 已读状态变化，但未解除的真实风险继续保留   |

## 最终结论

我认为现在 WealthSail 的问题已经不主要是 UI 布局，而是研究判断、风险优先级和信息呈现三者没有形成一致的产品逻辑。

当前系统将“严格的数据治理”做得比较认真，这是好事；但不应让用户替系统承担所有数据检查工作。

我希望下一版首页最先回答三件事：

我已经持有的基金，有没有值得立即复核的风险？

现在有哪些新的、具有可靠证据的研究机会？

哪些重要条件发生了变化，下一次应该关注什么？

用户想深入研究时，再进入宏观经济、利率信用、全球事件、指数估值、基金质量和策略验证。

建议优先修复 `GAP → CRITICAL` 的错误优先级，再建设“持仓风险 / 机会候选 / 重要变化”三入口。这两项会比继续给现有页面添加数据、图表或更多颜色，更显著地提升实际使用价值。
